### 16.1 数据基建启发（数据库/容量规划视角）

本周数据面信号明确指向**AI 数据基础设施的容量扩张周期**：Hugging Face 并入 Nvidia、OpenAI Astra 上线、数据中心电力需求全线走强（VST/CEG/OKLO/IREN 大涨），意味着训练/推理/Agent 会话/多模态数据的**日志、轨迹（trajectory）、向量化内容与缓存层**规模将持续指数式增长——对数据库与后端工程的直接启示是：**Agent 会话存储与检索规模会成为新的容量规划变量**，不再是"日志按周归档"的传统思维，而是要把"每个 Agent 动作的轨迹 + 中间结果 + 工具调用记录"当作一等公民数据。选型思考上：高吞吐日志/轨迹适合列存+对象存储分层（如 ClickHouse/Parquet 湖仓 + S3 生命周期策略），在线 Agent 记忆/检索需要**向量索引（HNSW/IVF）与混合检索（向量+关键字+元数据过滤）**下沉到主库（pgvector/Milvus/Qdrant 均可），OLTP 侧强调会话表的高写入 QPS 与冷热分层（热数据 Redis/内存、温数据 SSD、冷数据 OSS/对象存储）；OLAP 侧则要承接"按模型/按任务/按用户聚合分析成本与质量"的新报表需求，流式处理（Kafka/Flink）用于实时监控推理调用与容量水位。工程启示再具体一点：**缓存分层从"可选优化"变成"成本必需品"**——推理成本虽在下降（模型蒸馏与 MoE 路线），但 Agent 全链路调用放大效应使 token 成本非线性上升，语义缓存（embedding 近邻命中）+ KV 缓存 + 结果缓存多层并用，才能把单位任务成本压下来；向量检索规模增长后，**归一化+量化（PQ/SQ）与分段存储**是控制内存成本的常规手段。本周暂无超出上述框架的颠覆性基建信号（如新型存储介质或数据库架构发布），故判定为"延续性扩容信号"而非范式转折。
