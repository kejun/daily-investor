## 16. 行业 / 技术趋势独立分析

本周最值得记录的结构性变化有三条，且它们指向同一个方向：**AI 产业的价值分配正在从"应用层"向"基础设施层"和"合规层"迁移**。

第一，**SK 海力士 Q3 利润大幅超预期（AI 内存驱动）**，与"AI 资本开支见顶"的市场叙事形成正面冲突。这说明算力投资仍在实物层面扩张，但资本市场已经提前对 2027 年的回报率打折——**基本面与股价的背离，本质是估值对"回报周期"的重新定价**，而不是对"需求"的否定。

第二，**亚马逊内部"反 tokenmaxxing"备忘录**（要求工程师更挑剔地使用 AI）是一个标志性事件：企业客户开始从"能用就用"转向"算单位经济性"。这与 CNBC 报道的"AI 债务担忧"是同一枚硬币的两面——**当 AI 从"实验预算"进入"生产成本"，按 token 计费的中间层会被挤压，而提供确定性（安全、观测、成本治理）的层会被强化**。这也解释了为什么同一天 ADBE -3.97%、CRM -2.71%，而 PANW +2.88%、CRWD +2.36%、HACK 创新高。

第三，**Anthropic 的 IPO 讨论与其现金储备规模**（CNBC：其现金规模超过几乎所有美国公司）说明头部模型公司正在从"烧钱竞赛"转向"资本结构竞赛"。这对二级市场的含义是：**模型层的赢家会越来越少，而围绕模型的基础设施（光通信、电力、内存）会获得更长的订单可见度，但更低的估值倍数**。

**独立判断**：市场当前把"AI 硬件下跌"定价为"AI 周期结束"（情绪），但把"AI 电力小票的 +9%"定价为"AI 复苏"（也是情绪）。真实趋势在中间：**需求在扩张（海力士）、估值在收缩（200 日线）、价值在向合规与成本治理迁移（安全新高）**。最大的定价偏差在于——**光通信与网络（LITE/COHR/ANET）的跌幅（-24% 至 -65%）远大于其订单能见度的恶化程度**，这是最可能被修正的错杀区；而**AI 电力小票的反弹幅度（+9%）远大于其现金流改善程度**，这是最可能被证伪的乐观区。

### 16.1 数据基建启发（数据库 / 容量规划视角）

本周出现了三个对数据基建有直接含义的信号。

**其一，推理成本纪律化 = 轨迹数据从"无限留存"转向"分级留存"。** 亚马逊要求工程师"更挑剔地使用 AI"，意味着企业开始对 agent 调用计费。工程上，这直接推动三件事：① 会话/轨迹表从"全量写入"改为冷热分层（热库保留 7-30 天可查询，冷库存 Parquet on S3/OSS）；② 引入 token 归因字段（按团队/功能/模型维度），这要求 OLTP 表设计时预留高基数标签列并配列存副本；③ 可观测性从"采样日志"升级为"结构化事件表"，写入放大成为新的容量瓶颈。

**其二，向量检索正在下沉到主库，混合检索成为默认架构。** 随着 agent 应用普及，pgvector / OceanBase 向量索引 / MySQL 9 向量类型的采用率上升，"一个 Postgres 同时做 OLTP + 向量 + 全文"成为中小团队的首选，代价是 HNSW 索引的内存占用（通常为向量数据本身的 1.5-2 倍）与 VACUUM 压力。容量规划上需要把"向量索引常驻内存"作为独立预算项，并接受"向量召回走内存、元数据过滤走 B-tree、最终排序走列存"的三层架构。

**其三，Agent 会话存储的写放大被严重低估。** 一次 agent 任务会产生 20-100 倍于人类会话的消息、工具调用、思考链与文件快照，单会话数据量从 KB 级跃升到 MB 级。若按 10 万日活 × 5 次任务 × 2MB 估算，日增原始数据约 1TB——这已经超出单机 OLTP 的经济区间，需要"写入走 Kafka → 落对象存储 → 热表只存指针 + 摘要"的流水线。对应的架构选择是：**元数据用 OLTP（强一致、低延迟），正文用对象存储（低成本、高吞吐），分析用湖仓（列存 + 分区裁剪）**，三者用统一 ID 打通。

**工程启示**：不要把"AI 功能上线"当成一次前端迭代——它同时是一次数据量级跃迁。上线前必须回答三个问题：单次任务的平均写入量是多少？这些数据需要在线可查多久？向量索引的内存预算从哪来？回答不了这三个问题，AI 功能上线三个月后一定会遇到"库写满、查询变慢、账单翻倍"的三重夹击。
