## 0. 今日一句话总结

昨夜是一次典型的"指数分化 + 内部剧烈换血"：道指首次收于 50,000 点上方（+0.85%，+423 点），而纳指跌 1.48%、纳指100 跌 1.99%，费城半导体指数单日崩塌 **-7.88%**。驱动因素是 AI/半导体交易在周一暴涨后的集中反手——AMD 因 3.37 亿股转售备案暴跌 8.86%，美光 -11.01%、MRVL -9.10%、LITE -10.52%，英伟达 -5.86%；同时资金大规模流向医疗（XLV +2.95%）、必选消费（XLP +1.66%）、房地产（XLRE +1.31%）与生物科技（IBB +5.17%）。risk-off 只发生在 AI 产业链内部，全市场并非普跌：等权标普 RSP +0.54%、罗素2000 +0.57%，VIX 盘中冲高至 32.38 后回落收 26.36（-0.98%）。最值得关注的线是 **10 年期美债 4.92% + 30 年期 5.31% 的长端高利率** 与 **半导体相对大盘的破位**——这是估值端的双重压制，不是一次普通回调。

**一句话判断**：这不是"美股跌了"，而是"AI 权重股被卖、其余板块被买"的良性轮动叠加半导体自身熊市反弹结束；道指新高与 SOX 暴跌同框，说明市场在为"AI 资本开支见顶"重新定价，而非为衰退定价。

## 16. 行业/技术趋势独立分析

**本周结构性变化**：最值得记录的不是股价，而是"AI 产业链的分层"终于被市场明确定价。同一天里，光模块（LITE -10.5%、COHR -9.1%、TSEM -9.8%）跌幅大于 GPU（NVDA -5.9%），GPU 跌幅大于定制 ASIC（AVGO -4.0%），ASIC 跌幅大于非 AI 芯片（QCOM -0.25%）。这条递减序列的含义是：**市场认为"AI 集群扩容速度"下修幅度大于"单卡价值量"下修幅度**。换句话说，供给端的单价故事还在，需求端的数量故事开始动摇。AMD 的 3.37 亿股转售备案是纯供给冲击（股本稀释），却被放大成整个板块的下跌，说明当前半导体的持仓拥挤度极高，任何单点利空都会被当成趋势信号。

**对数据库/前端的工程启示**：若"算力扩容速度下修"成真，最先传导的不是 GPU 价格，而是推理成本曲线的斜率。推理成本若因集群扩张放缓而下降速度减慢，agent 类应用的"平民化"节奏会被推迟——这直接影响会话存储设计：原本预期"单用户 agent 会话数 ×10、单会话轨迹体积 ×5"的容量规划，可能需要从"高增长档"下调到"中增长档"，但**下降的是增速而非绝对量**，因为单位成本仍在下降、模型能力仍在提升。前端侧则应观察软件板块（CRM/ADBE 大涨）的隐含信号：企业预算从"买算力"回流"买应用"，意味着 agent 交互范式的落地场景会更集中在**业务系统内嵌**（CRM/工作流/文档）而非独立的通用 agent 入口。

**独立判断**：情绪 vs 趋势需要分开。**情绪**是 AMD 转售备案引发的无差别抛售、Anthropic 破发带来的 AI 一级市场恐慌、以及"国会审查"传闻——这三者都是可逆的。**趋势**是三点：① 半导体相对大盘的估值溢价在收敛（SMH 回撤 36%，XLK 回撤 22%）；② 长端利率在高位锁死成长股估值上限（30Y 5.31%）；③ 企业 IT 预算正从基础设施层回流应用层（CRM/ADBE 单日 +4.21%/+3.62% 是真实定价）。市场可能定价偏差的地方在于：**把"AI 资本开支增速放缓"直接等价于"AI 需求见顶"**。前者是周期，后者是叙事反转，二者相差一个数量级的估值差。若后续某个季度的云厂商 capex 指引只是"增速从 60% 降到 35%"而非"下滑"，当前半导体的定价将明显过低；反之若出现绝对值下滑，SMH 的 36% 回撤只是开始。

### 16.1 数据基建启发（数据库/容量规划视角）

**本周数据基建信号**：本周无显著的一级数据基建事件（无重大数据库/存储厂商融资或发布），但二级市场提供了三条间接信号。

**一、容量规划的量级判断需要下修增速而非下修绝对量**。半导体暴跌的直接原因是"数据中心支出担忧回归"。对后端工程师的含义是：如果 2026 年上半年规划的存储扩容是按"AI 集群翻倍"做的，下半年应按"集群增速减半、单节点数据密度上升"重新校准。具体到数字，agent 会话数据的增长主要来自三块：会话轨迹（trajectory，单条 50-500KB）、工具调用日志（结构化，可列存）、向量与上下文缓存（高维、写放大）。集群增速放缓影响的是**会话并发数**（第一块），而不影响**单会话数据密度**（后两块还在涨）。

**二、存储选型上，"向量引擎下沉主库"的判断被强化**。当推理成本下降速度放缓，agent 应用的经济性从"多调模型"转向"多查数据"——即用检索替代推理。这会推动向量检索从独立向量库（Milvus/Qdrant 独立部署）下沉到主库扩展（pgvector / Postgres 扩展、MySQL  HeatWave 类方案）。理由是运维成本：独立向量库在扩容放缓的环境下，"多一套系统"的固定成本占比上升。同理，混合检索（BM25 + 向量 + 结构化过滤）会成为默认架构，因为纯向量检索的召回成本高于"先过滤再检索"。

**三、OLAP/OLTP 边界与缓存分层**。可观测性数据（工具调用日志、agent 轨迹）本质是"高写入、低延迟读取、按会话聚合"的混合负载。把这类数据放进 OLTP 主库会拖垮事务性能，放进纯 OLAP（ClickHouse/Doris）又缺乏点查能力。合理架构是三层：热层（Redis/内存，会话活跃窗口 1-2 小时）、温层（列存，按天分区，用于会话回放与聚合）、冷层（对象存储 + 开放格式 Parquet/Iceberg，用于训练数据回流）。**关键工程取舍是"轨迹数据是否要可查询"**：若要支持 agent 调试与合规审计，温层必须保留可 SQL 查询的结构，不能直接压成压缩包；若只做训练回流，冷层即可，成本可降一个量级。

**结论**：本周没有"数据库行业大事件"，但市场给出的信号很明确——**AI 数据面的增长故事从"集群规模驱动"切换到"单会话密度驱动"**。对容量规划的直接影响是：写入吞吐的增长率下调，但数据保留期与可查询性要求上升，这意味着**分层存储的冷热边界要往前移**（更多数据下沉到列存/对象存储），而不是简单地砍掉扩容预算。
