### 16.1 数据基建启发（数据库/容量规划视角）

**本周数据基建信号充足：** ① **Agent 会话与推理日志数据爆炸**——推理成本下行直接刺激 agent 调用量，每次 agent 会话产生的轨迹/token 级日志、工具调用记录、评估数据，正在以远超传统应用的速度增长；可观测性巨头（DDOG +4.0%、NET +7.8%）与安全（CRWD/PANW）大涨正是资本市场对这一数据面扩张的定价。② **向量检索规模上升**——RAG/语义检索成为 agent 标配，向量表从百万级走向十亿级，混合检索（向量+全文+元数据过滤）成为标配能力，单一向量索引难以满足召回质量，需倒排索引与 HNSW 并行。③ **存储选型思考**：推理日志/轨迹适合列存+压缩的 OLAP 湖仓（如 Iceberg/Parquet + 物化视图），会话状态与短期缓存适合 KV/内存层（Redis/嵌入式），而向量+图谱混合检索正从专用向量库（Milvus/pgvector 并存）向"主库原生向量"演进——PostgreSQL/MySQL 8.4+/SQLite 向量扩展使小团队不必引入独立向量服务。④ **容量规划建议**：agent 日志留存设置分层策略（热存 7 天 + 冷存压缩归档），向量索引按数据新鲜度分区（热向量内存、冷向量磁盘+量化），并预留 3-5 倍检索 QPS 余量以应对 agent 并发；推理 token 计费与日志存储成本需要打通计量，否则"agent 平民化"会先击穿运维预算。⑤ 前端维度：agent 交互范式（流式、工具调用、多步确认）要求 API 网关与可观测性栈支持流式追踪（trace 与 token 计量对齐），这是数据库/中间件工程师的新战场。
