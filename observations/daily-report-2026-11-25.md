## 16. 行业/技术趋势独立分析

本日最值得注意的结构性信号，不是指数跌幅，而是**「AI 资本开支受益者」与「AI 现金流使用者」的估值分裂**。NVDA 单日 -3.91%（盘中 -9.1%）、ORCL -5.13%、MRVL 一个月 -46%，而 META +3.40%、AAPL 逼近历史新高。市场正在重新回答一个问题：AI 的钱是被「卖铲子的人」赚走了，还是被「用铲子的人」赚走了？过去两年答案是前者，本周开始向后者倾斜。与此同时，SpaceX 获 FCC 批准部署百万颗轨道数据中心卫星，提示算力的物理形态可能从「地面超大规模集群」转向「分布式轨道节点」——这在 3-5 年内是真实变量，在 3 个月内只是叙事噪音。

对工程侧的直接启示有三点：① **推理成本继续下行的确定性高于训练成本**，因为竞争从「堆卡」转向「单位 token 效率」，这会加速 agent 平民化——原本只有大厂能承担的多步 agent 工作流，正变成中小团队可负担的默认架构；② **模型能力商品化 → 价值向数据与工作流迁移**，这意味着「有私有数据 + 有嵌入业务流程」的产品会比「有更强模型」的产品更抗估值下杀，这正是 CRM/PANW 逆势上涨、DDOG 大跌 4.31% 的微观解释（前者嵌入流程，后者是纯工具型可替代层）；③ **前端 agent 交互范式正在从「聊天框」转向「可观测的任务面板」**，用户需要看见 agent 在做什么、花了多少、错在哪——这对可观测性与状态管理提出了新要求。

哪些是情绪、哪些是趋势：**情绪**是「AI 泡沫破裂」的宏大叙事与 NVDA DOJ 传闻；**趋势**是推理成本下降、算力形态分散化、以及资本开支从「无限扩张」转向「 ROI 考核」。市场可能的定价偏差在于：把「资本开支增速放缓」直接定价为「AI 需求见顶」。这两者并不等价——需求可能依然强劲，只是买方开始要求回报率，这会压缩硬件厂商的毛利，但不压缩使用方的需求。若这个判断成立，则硬件链的超跌是估值重估（合理），而软件/应用层的下跌是错杀（不合理）。

### 16.1 数据基建启发（数据库 / 容量规划视角）

本周的数据基建信号是**「成本约束开始反向塑造架构」**。推理单位成本下行 + agent 工作流普及，直接后果是数据量的第二次爆炸，且形态与上一轮完全不同：上一轮是「用户行为日志」（宽表、可聚合、适合 OLAP）；这一轮是「agent 轨迹数据」——每一步的 prompt、tool call、中间状态、检索命中、失败重试，全部需要留存用于回放与评测。这类数据的特点是**写多读少、单条体积大、需要按 session 顺序回放**，天然不适合塞进现有数仓宽表，更接近「事件流 + 对象存储 + 可检索索引」的组合。

容量规划上要预留三个增长点：① **会话级状态存储**（KV/文档型，按 session_id 分区，需要 TTL 与冷热分层）；② **轨迹与向量数据**（单条轨迹可含数十次检索，向量条目数是会话数的 10-50 倍，索引膨胀会先于原始数据触及瓶颈）；③ **评测集快照**（每次模型/提示词变更都要求可复现的固定快照，属典型的「写一次读多次」，适合列存 + 廉价对象存储）。

选型上的具体判断：**向量检索正在下沉进主库**——pgvector / pgvectorscale 这类扩展让「一个 Postgres 同时承担事务与向量」在中等规模（千万级向量以内）成立，显著降低运维面；一旦跨过这个量级，专用引擎（Milvus/Qdrant）的 HNSW 参数调优与分片能力就重新变得必要。**混合检索（BM25 + 向量 + 重排）已是默认配置而非高级特性**，这意味着存储层要同时维护倒排索引与向量索引，写放大是必须提前算进容量模型的成本项。**OLAP/OLTP 边界在 AI 数据面上重新模糊**：轨迹数据既要做点查（按 session 回放）又要做聚合（按工具类型统计失败率），单一引擎很难两头都优，务实做法是「OLTP 存热态 + 列存存冷态 + 一层物化视图」而非追求单一 HTAP。

工程上的三条落地建议：① 把「检索命中率/延迟」与「成本」做成同一条可观测链路（缓存分层：结果缓存 → 语义缓存 → 向量检索 → 重排），否则优化无从下手；② 轨迹数据从一开始就按「可丢弃」设计（分级保留、按价值采样），不要默认全量永久留存；③ 容量模型里必须显式包含「索引体积」与「重排算力」两项，它们是 AI 数据面最常见、也最容易被低估的成本黑洞。
