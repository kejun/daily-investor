## 16. 行业/技术趋势独立分析

当日最值得记录的结构性变化不是指数涨跌，而是**半导体内部的分层**：涨幅榜前列是 MU（+7.6%，存储）、MRVL（+7.3%，定制 ASIC）、COHR/LITE/AAOI（光模块，+8%~+14%），而 NVDA（+0.8%）、AVGO（+3.8%）这些「训练侧旗手」明显落后。这条线索与产业侧的变化一致——当模型能力趋同、推理调用量成为主要成本项时，价值正在从「单卡算力」向「内存带宽 + 光互联 + 定制化」迁移。同时中国芯片股录得史上最大单日涨幅（北京释放市场支持信号），意味着供给侧的国产替代正在从「政策补贴」进入「资本市场定价」阶段，这会长期压低全球半导体设备的边际定价权。

对工程侧的直接启示：推理成本下降不是线性的，它会以「单位 token 成本骤降 → agent 调用次数指数上升」的方式反向推高总成本。当 agent 从「单轮问答」变成「多步规划 + 工具调用 + 自我反思」，一次任务的 token 消耗是聊天场景的 20-100 倍，随之而来的是**轨迹日志、检索索引、会话状态的存储量爆炸**。这不是情绪，是趋势；市场当前把 AI 硬件的下跌解读为「需求见顶」，很可能是定价偏差——真正的风险在应用层的毛利，而非算力层的需求。

**哪些是情绪**：今日 +4.69% 的 SOX 涨幅、+14% 的 COHR，是情绪（空头回补 + 半日市流动性稀薄）。**哪些是趋势**：存储/光互联/定制 ASIC 的相对强势、能源与必需消费的年内超额（XLE +34%、XLP +22%），是趋势。市场可能定价偏差之处在于：把「AI 资本开支放缓」线性外推到「AI 需求见顶」，而实际上资本开支的放缓往往伴随单位算力效率提升与推理需求爆发，最终受益者会换人，但总需求不会消失。

### 16.1 数据基建启发（数据库/容量规划视角）

本周传出的容量信号集中在两处。第一，**推理侧接棒训练侧**：当 MU（存储）与光互联跑赢 GPU 旗手时，意味着数据中心的瓶颈从「算力」转向「数据搬运」——落地到工程上，是 KV cache 的显存/内存分层、向量索引的持久化（而非全内存）、以及 embedding 存储的冷热分层。第二，**agent 会话成为新的数据面**：多步 agent 的每一步都产生可观测数据（prompt、tool call、返回、状态快照），单会话数据量从 KB 级跃升到 MB 级，日活一万的 agent 产品一年就是 TB 级的轨迹数据，且要求「按 session_id 时间序读」——这是典型的 OLTP 写入 + 时序扫描混合负载。

选型上的三个具体判断：① 向量检索正在下沉到主库（pgvector / Postgres 扩展、MySQL 的向量能力），独立向量库的生存空间被压缩到「超大规模 + 极致召回」场景；混合检索（BM25 + 向量 + 结构化过滤）需要在一个查询计划内完成，跨库 join 是性能杀手。② OLAP 与 OLTP 的边界因 agent 可观测性而重新模糊：轨迹分析要跑窗口函数与聚合，但写入是高频小事务，ClickHouse/Doris 类列存适合分析侧，写入侧仍需行存缓冲，**不要用一套引擎硬扛两端**。③ 成本控制的关键是**缓存分层**：KV cache（前缀缓存）→ 结果缓存 → 向量召回缓存，命中率每提升 10 个点，等效于推理成本下降一个档位，这比换更便宜的模型更有效。

容量规划上，若你的产品在 2027 年把 agent 调用量放大 10 倍，存储增长不会是 10 倍而是 30-50 倍（含轨迹、索引、多版本快照）。建议现在就把「按会话 TTL 分级归档」和「向量索引的增量重建」写进架构，否则半年后会被迫做一次痛苦的分库分表。
