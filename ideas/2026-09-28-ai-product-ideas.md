3. **Ember-1 登上 HN 首页（433 分、202 评论）：推理云厂商开始"自产模型"，垂直整合浪潮确认**。Fireworks AI 发布 Ember-1，这是又一家推理服务商推出自研模型——此前 Fireworks 以"跑别人的开源模型跑得最快最便宜"著称。这个动作的行业含义：**推理云正在从"GPU 租赁 + 优化引擎"升级为"模型 + 推理 + 分发"的垂直整合体**，逻辑与当年的云计算厂商自研芯片（Graviton）如出一辙——离客户最近的一方，最清楚该造什么模型。对应用层创业者的双重影响：好消息是推理价格战会继续（自有模型毛利更高，有降价空间）；坏消息是"中立推理层"正在消失——当 Fireworks 自己的 Ember-1 与它托管的第三方模型在同一个 API 网关后面竞争，路由的中立性就成了问题。**判断：应用层需要自己的"模型路由对冲"策略——把模型选择权握在自己手里，随时可以在 Ember-1、DeepSeek、Llama 系之间切换，任何单一模型的深度绑定都是未来的议价劣势**。这与今日 HN 另一条"Owed a billion dollars in Nvidia stock"（485 分、195 评论）对 AI 资本叙事的讨论形成互文：整条产业链都在重新分配话语权。

4. **TabPFN/TabICL 对战调优 XGBoost：14 战 14 胜——"不训练的模型"正在终结表格数据的调参时代**。今日 HN 上一篇技术博客引发讨论（18 分、9 评论，分数不高但信号极强）：作者用 TabPFN 与 TabICL 两个"表格基础模型"（tabular foundation model）对战精心调优的 XGBoost，在 14 个真实数据集上全胜。这类模型的工作方式颠覆直觉——**不训练**：把训练数据直接放进上下文窗口，模型通过"上下文内学习"（in-context learning）当场完成预测，几秒钟出结果，没有超参数、没有交叉验证、没有特征工程马拉松。XGBoost 自 2016 年统治表格数据十年，Kaggle 上几乎所有结构化竞赛的冠军方案都靠它；如今一个"喂数据即预测"的预训练模型把它按在地上摩擦。对行业的含义：**表格数据科学的工作流将被重写**——中小团队不再需要 ML 工程师花两周搭 pipeline，业务分析师上传 CSV 就能得到超越专家调参的预测。风控评分、流失预测、库存预估、医疗预后……所有"小数据、结构化、高价值"的预测场景都在射程内（详见需求 2 与创意 2）。

### 技术趋势

1. **UK AISI × EvalEval：基准测试可复现性成为国家级议题，"评测基建"赛道浮出水面**。Hugging Face Blog 本周发文，宣布英国 AI 安全研究所（AISI）与 EvalEval 项目合作，让基准测试结果可复现。背景是行业积弊：同一个模型在不同评测框架下分数可以差出 10+ 个点（prompt 模板、解析方式、采样温度的细微差异都会改变结果），论文里的 SOTA 声明大量无法复现——HF 自己 9 月 1 日的 BenchMIRT 研究（"LLM 基准到底在测什么"）与 IBM 9 月 15 日的 agent 一致性研究（"你的 agent 做对了任务，它还能再做对一次吗"）都指向同一个危机。**当政府监管机构（AISI）开始亲自下场做评测标准化，意味着"模型评测"正从学术爱好变成合规基础设施**。可预见的产品化方向：第三方评测存证服务（像会计审计一样给模型分数盖章）、企业内部评测流水线（每次换模型/改 prompt 自动跑回归评测）、以及"评测即合同"（供应商 SLA 直接绑定可复现基准）。对创业团队：模型能力趋同的时代，**"证明你的模型/agent 在特定场景下可靠"比"宣称它更强"更有商业价值**。

2. **vercel-labs/scriptc（+102 星/天，5,510 星）：TypeScript-to-Native 编译器登场，TS 正在成为"AI 时代的系统语言"**。Vercel 实验室开源了把 TypeScript 直接编译为原生代码的编译器。表面看是前端圈的又一次越界，深层逻辑与 AI 强相关：**LLM 生成 TypeScript 的能力是所有语言中最强的**（训练语料中 JS/TS 占比第一），如果 TS 能直接编译成原生二进制，那么"AI 写 TS → 编译成高性能原生程序"就成了一条完整通路——绕开了 C/C++/Rust 这些 LLM 相对容易出错的系统语言。想象一个场景：agent 为你的数据处理需求现场写一个 TS 脚本，scriptc 编译成原生二进制，性能接近手写 Rust，而开发体验是 AI 最擅长的 TS。配合本周 HF 的 tokenizers v1（编解码性能实测）、WebGPU kernels（200+ 本地计算内核），**"AI 生成代码的执行效率"正在被整条工具链补齐**——代码生成的下一站不是"写得更像人"，而是"跑得更接近原生"。

3. **边缘具身智能栈成型：LFM2.5-VL-DSpark（低延迟视觉语言模型）× NVIDIA Warp/MjWarp（机器人仿真加速）本周先后发布**。Liquid AI 的 LFM2.5-VL-DSpark 主打"加速视觉语言模型"——为机器人、无人机、AR 设备等边缘场景提供低延迟的多模态理解；NVIDIA 官方博客则详细介绍了 Warp + MjWarp 如何加速机器人仿真与学习工作流（GPU 并行物理仿真，训练效率数量级提升）。两者合看是一条完整的技术叙事：**边缘侧的"眼睛+大脑"（小型 VLM）与训练侧的"健身房"（GPU 并行仿真）同时在 2026 Q3 就位**。行业数据佐证：arXiv 今日 cs.AI 新增 201 篇中，具身智能与机器人学习占比持续走高。对产品经理的含义：机器人/自动化创业的技术门槛正在快速下降——不用自研模型（LFM 系开源）、不用自建物理实验室（仿真训练）、不用自己攒推理栈（边缘芯片 + 量化模型）。**"用开源 VLM + 仿真训练做垂直场景机器人"会在 2027 年成为像今天"用开源 LLM 做垂直 chatbot"一样的标准打法**——仓储分拣、餐厅配送、农业巡检最先受益。

4. **《Thinking fast and slow in AI: The role of metacognition》重上 HN（64 分）：System 1/System 2 双通道成为推理模型的设计共识**。这篇 2021 年的论文把 Kahneman 的"快思考/慢思考"框架引入 AI：System 1（快速、直觉、低算力）处理常规输入，System 2（缓慢、审慎、高算力）只在元认知监测到"这题不简单"时才启动。2026 年的现实意义：**推理模型（o 系列、R 系列、Ember-1 们）最大的成本痛点就是"该快的时候不快"**——简单问题也走完整思维链，token 费用翻十倍。元认知路由（先廉价判断难度、再决定是否深度思考）是公认的解法，但目前都藏在闭源模型的内部。产品机会在两处：其一是"推理预算控制器"——给企业 agent 舰队加装一层元认知网关，按任务价值动态分配思考深度（客服闲聊用 System 1，合同审查用 System 2），实测可省 50-70% 推理成本；其二是可解释性——让用户看到"AI 为什么决定深想这个问题"，这是信任构建的关键界面（详见快速灵感 3）。

5. **MIT Tech Review：五角大楼豪掷 3,030 万美元研发 AI 测谎仪，专家警告"两头的坏处占全"**。美国国防部预算申请显示，"Polygraph+/Polygraph Next"计划将用 AI 打分算法与"standoff sensing"（非接触式生理信号测量）改造传统测谎。MIT TR 引述专家观点一针见血：这是"worst of both worlds"——继承了传统测谎的伪科学基础（生理指标与说谎没有可靠因果），又叠加了 AI 的黑箱问题（算法误判无法质证）。这条新闻的产品启示是反向的：**"AI 判定人的可信度"这个品类会持续吸引政府与大企业预算（安防、边检、招聘、金融风控），但科学有效性危机同样会持续积累**——每一次误判曝光都在为监管铺路。对创业者的警告：不要碰"情绪识别/谎言检测"类 to G 生意，除非你想在五年后面对集体诉讼；但"AI 决策的质证与审计工具"（帮被误判者申诉、帮监管者验证）是一个道德与商业双重正确的反向赛道——参照欧盟 AI Act 已把情绪识别列为高风险/禁止类，合规审查工具的需求是确定的。

## 🎯 潜在需求分析

### 需求 1：隐私级本地语音生产栈（"不出机器的配音工厂"）

**痛点来源**：
- VoiceStudio 单日 +3,086 星、累计 40,944 星——"fully-local ElevenLabs alternative"被开源社区用星数验证为顶级刚需
- 成本断层：ElevenLabs 按字符计费，一部 10 小时有声书的多语言配音成本 $500-2,000；本地推理的边际成本≈电费，批量生产场景差出两个数量级
- 合规断层：声纹是生物特征数据，GDPR/欧盟 AI Act/中国《个人信息保护法》对声纹采集与合成的监管持续收紧；律所会议录音、医疗问诊、企业内部培训这些场景根本不允许音频上云
- 供给断层：VoiceStudio 们提供的是"模型 + 命令行工具"，但内容生产团队需要的是"工作流"——批量任务队列、多角色配音时间轴、术语表一致性、成品审听与导出，这些开源项目都不做

**具体场景**：
一家出版公司每年要把 300 本中文图书制作成多语言有声书（英/日/西/阿）。用云端 API 的账算不过来：每本 8-12 小时成品 × 4 语言 × $0.10-0.30/分钟 ≈ 每本 $200-800，全年预算 $15 万+；而且合同里"未出版书稿音频不得上传第三方"的条款直接把云端方案判了死刑。用本地栈：一台 M4 Max 工作站跑 VoiceStudio 类模型，编辑在时间轴工具里分配角色音色、导入术语表（人名地名读音统一）、夜间批量渲染、早晨人工审听标记返工段落——全年成本≈设备折旧 + 一个音频编辑的工资，且书稿永不出内网。同样的需求结构存在于：播客工作室（多嘉宾节目的降噪+克隆修复口误）、在线教育（课件配音的多语言化）、游戏工作室（NPC 语音的海量草配）。

**市场机会**：
- 目标客户：有声书出版社、播客/MCN 机构、在线教育公司、游戏与影视本地化工作室、以及所有"音频敏感"的企业内训/法务场景
- 品类定义：Local Voice Production Suite = 本地推理引擎（OEM VoiceStudio 类开源模型）+ 制作工作流（时间轴/角色管理/术语表/批量队列）+ 审听协作（标记返工/版本对比）+ 合规存证（声纹授权书管理、生成内容水印）
- 参照系：Descript 之于播客（把"音频编辑"重做成"文档编辑"拿了 $100M+ 年营收）——本地语音栈需要自己的"Descript 时刻"：不是卖模型，是卖工作流
- 定价锚点：单机版 $49-99/月（个人创作者），工作室版 $299-599/月（多席位+批量队列），企业私有部署 $20k-50k/年（含合规存证模块）；对比云端 API 用量账单，批量客户的 ROI 故事一句话讲清："三个月回本"
- 时机判断：开源模型层刚刚成熟（VoiceStudio 40k 星是里程碑），工作流层完全空白；云端巨头因商业模式冲突（按字符收费 vs 本地买断）不会自我革命——**这是典型的"开源击穿成本结构、创业公司在上层收工作流的钱"窗口期，预计 18-24 个月**
- 竞争格局：ElevenLabs（云端 API，无本地版）、Descript（云端为主，编辑工作流强但配音弱）、VoiceStudio 及同类开源（有模型无工作流）；**"本地优先 + 完整制作工作流"的定位暂无头部玩家**

### 需求 2：零训练表格预测服务（"上传 CSV 就出模型，跳过整个 ML 工程"）

**痛点来源**：
- TabPFN/TabICL 对战调优 XGBoost 14 战 14 胜（HN 今日热帖）——表格基础模型的能力已越过"替代专家调参"的临界点
- 现实断层：全球数百万中小企业有结构化预测需求（谁会流失、该备多少货、这笔贷款违不违约），但雇不起 ML 工程师，也玩不转 AutoML 平台——传统流程（清洗→特征工程→调参→交叉验证→部署监控）对 5 人以下团队是天文数字的复杂度
- 认知断层：业务分析师会用 Excel 和 SQL，但"训练一个模型"意味着 Python、scikit-learn、超参数——这套技能鸿沟把 90% 的潜在用户挡在门外
- 技术时机：TabPFN 类模型"不训练"的特性恰好消灭了上面所有复杂度——没有超参数就没有调参，上下文内学习意味着"数据即模型"，秒级出结果意味着可以做成即时交互的产品体验

**具体场景**：
一家 200 人的电商公司，运营总监想知道"哪些客户下个月会流失"。传统路径：招外包数据团队，六周交付一个 AUC 0.78 的 XGBoost，之后每月要人重新训练。新路径：运营总监打开零训练预测平台，上传客户表（RFM 字段 + 历史行为），选目标列（90 天内是否复购），30 秒后得到：每个客户的流失概率、全局特征重要性、以及"如果给流失概率 >0.7 的客户发券，预期挽回 GMV"的模拟——不需要理解任何 ML 概念。同样结构的需求：区域性银行的信贷风控（小样本、监管要求模型可解释）、连锁餐饮的门店级销量预估（300 家店各自是小数据问题，传统方案要 300 次建模）、制造业的设备故障预测（传感器表格数据）。**共同点：数据量在 1K-100K 行之间（恰好是 TabPFN 类模型的甜区）、价值密度高、但没有专职 ML 团队**。

**市场机会**：
- 目标客户：无 ML 团队的中小企业数据/运营/风控部门；先行垂直：电商（流失与销量）、消费金融（评分卡替代）、SaaS（产品分析）
- 品类定义：Zero-Training Prediction Platform = CSV/数据库接入 + 目标列选择 + 秒级预测 + 自动解释（特征归因/反事实模拟）+ 一键部署（API/定时批处理）；卖点不是"AI"而是"跳过 ML 工程"
- 参照系：Airtable 之于 Excel（把电子表格升级成协作数据库，$1B+ 估值）——零训练预测是"把 ML pipeline 升级成一次上传"的同构故事；TabPFN 官方（Prior Labs）已推出商业 API，但停留在开发者工具层，业务用户产品层空白
- 定价锚点：按预测行数计费，$0.001-0.01/行（对比 AutoML 平台的 $1k+/月起步）；团队版 $199-499/月含数据库直连与部署；金融/医疗垂直版收合规溢价（模型文档自动生成——监管要求的模型说明零训练模型反而更好写，因为没有超参数）
- 时机判断：TabPFN 论文 2025 年获 Nature 子刊级关注后，开源实现与商业 API 都在 2026 年成熟；但"业务用户可用的产品化"还没人做完——**窗口期约 12-18 个月，之后云厂商会把该能力做成 BigQuery/Snowflake 的一个按钮**（这正是应该抢在被平台化之前建立垂直纵深的原因）
- 竞争格局：Prior Labs（TabPFN 原厂，开发者向）、DataRobot/H2O（重型 AutoML，贵且复杂）、云厂商内置 ML（绑定生态、面向工程师）；**"面向业务分析师的零训练预测"定位空缺**

### 需求 3：跨厂商 Agent 混编调度层（"让 Claude Code、Codex 和开源模型像一个团队一样干活"）

**痛点来源**：
- openrig（"runs Claude Code and Codex together as one system"）上线即 +114 星/天——单人项目的快速起量说明痛点真实且普遍
- Imp（DSPy → BEAM 移植，HN 71 分）从另一个方向验证：agent 编排需要生产级可靠性基座，Python 脚本级胶水撑不住 7×24 的 agent 舰队
- 企业现实：没有公司只用一家 agent——Claude Code 写业务逻辑、Codex 补遗留代码、DeepSeek 跑批量重构（便宜）、本地模型处理敏感代码（合规）；但每家 agent 的接口、计费、能力边界、上下文格式都不同，混编全靠工程师手写调度脚本
- 昨日日报记录的 paperclip（90,869 星、今日再 +2,401）解决"单一 agent 的管理"，openrig 触碰的是下一层问题："**多个异构 agent 的协作**"——谁干什么、谁审谁、失败怎么重试、成本怎么分账
- 深层驱动力是 Ember-1 揭示的趋势：推理层垂直整合后，任何单一厂商的模型都会有"偏科"，混编对冲是应用层的理性选择——**异构将长期存在，调度层就是刚需**

**具体场景**：
一个 8 人工程团队维护 40 个微服务。技术负责人配置混编策略：日常 feature 开发派给 Claude Code（质量最好）；夜间批量依赖升级派给 DeepSeek agent（成本 1/10）；所有涉及支付模块的代码必须由 Codex 交叉审查（第二双眼睛，防止单一模型的系统性盲区）；含客户数据的仓库只允许本地 Qwen 模型操作（合规红线）。调度层自动处理：任务按标签路由到对应 agent、统一收集 diff 到同一个 PR 流程、按项目维度归集各家 token 账单、agent 失败自动降级重试（Claude Code 超时→换 Codex→再失败才叫人）。周一早上，负责人看的不是四家平台的四个 dashboard，而是一张"混编周报"：本周 213 个任务，Claude Code 完成 58%，DeepSeek 完成 31%，交叉审查拦截 7 个潜在 bug，总成本比全用 Claude Code 低 44%。

**市场机会**：
- 目标客户：同时使用 2+ 家 coding agent 的工程团队（据 GitHub 2026 开发者调查，该比例已超 35% 且快速上升）；扩展场景：非编码 agent 混编（客服用 A 家、营销用 B 家）
- 品类定义：Agent Federation Layer = 统一任务协议 + 能力路由引擎（按任务类型/成本/合规约束派单）+ 交叉审查编排（不同厂商模型互审）+ 统一计费与成本分账 + 故障降级策略
- 参照系：Kubernetes 之于容器（异构工作负载的统一调度成就了 $B 级公司）；多云管理（RightScale/Flexera 吃到了"企业不只用一朵云"的红利）——**"企业不只用一家 agent"是完全同构的故事，且调度层的粘性天然高于单个 agent**
- 定价锚点：按受管 agent 席位 + 路由任务量，$30-80/工程师/月；团队版 $2k-5k/月；企业版（含合规路由、审计日志、私有部署）$50k+/年
- 时机判断：openrig 证明了需求，但它是单人开源项目（1,200 星），产品化程度极低；paperclip 的 90k 星说明"agent 管理"心智已被建立，混编调度是其自然延伸——**现在进入是"品类第二名的位置还没人坐"，12 个月后 paperclip 大概率向下兼容这个场景，窗口不长**
- 竞争格局：openrig（开源原型）、paperclip（单厂商 agent 管理，可能横向扩展）、LiteLLM/OpenRouter（模型级路由，不理解 agent 任务语义）、各厂商自家编排（只管自家 agent）；**"厂商中立的 agent 任务级调度"暂无成型产品**

### 创意 1：「声纹工坊 VoiceForge」——本地优先的多语言配音与有声书生产线

**产品定位**：
面向内容生产机构（出版社、播客工作室、在线教育、游戏本地化团队）的**本地部署语音生产工作流平台**——底层 OEM 集成 VoiceStudio 类开源本地语音模型，上层提供云端级顺滑的制作体验：角色音色管理、多语言配音时间轴、术语表一致性引擎、夜间批量渲染队列、人工审听协作。一句话：**"ElevenLabs 的能力，Descript 的体验，数据永不出你的机房"**。核心差异化不是模型（开源人人可用），而是把"模型能力"翻译成"生产流程"的那层工作流软件 + 合规存证体系。

**核心功能**：
1. **音色库与克隆管理**：从 5 分钟样本克隆音色（本地完成）；音色资产带授权链管理（谁的声纹、授权范围、到期时间），过期自动锁定——把合规做成产品功能而不是法务文档
2. **多角色时间轴编辑器**：导入剧本自动分角色分轨；每个角色绑定音色；支持"口误修复"——选中文字重新合成该句而不重录整段（Descript 式文本编辑音频体验，但全程本地）
3. **术语表一致性引擎**：项目级人名/地名/专有名词读音表（含多语言映射），合成前强制校验——解决批量生产中最恼人的"同一个名字三种读法"问题
4. **批量渲染队列**：整本书/整套课件拆章并行渲染，夜间跑满本地 GPU，晨间生成审听清单；支持"审听标记→定点返工"闭环
5. **生成内容水印与存证**：所有输出音频嵌入不可听水印（C2PA 标准），生产日志本地存证——满足各国"AI 生成内容标识"新规
6. **646 语言字幕/配音联动**：与转写、翻译模型（同样本地）串成流水线：原始音频→转写→翻译→多语言配音→字幕对齐，一条龙不出内网

**技术实现**：
- 推理层：集成 VoiceStudio 类开源模型（TTS/克隆/转写）+ 本地 LLM（翻译与剧本解析，Qwen/Llama 系量化版）；统一用 llama.cpp/MLX 后端，支持 Apple Silicon（工作室）与 NVIDIA 工作站（企业）双硬件路线
- 工作流层：桌面端（Tauri，轻量跨平台）+ 局域网协作服务端（审听、任务队列、资产库）；时间轴编辑器基于 Web Audio API 自研，波形渲染用 WASM 保证大文件流畅
- 一致性引擎：术语表编译为音素级约束注入合成过程（读音字典 + phoneme 强制替换），翻译环节用 constrained decoding 保证术语命中
- 水印：集成开源音频水印方案（如 WavMark 类），C2PA manifest 随文件分发
- 关键取舍：不做云端版本（保持"fully-local"的纯粹叙事），但做"本地集群版"（多台工作站共享渲染队列）满足大客户

**MVP 范围**（3 个月）：
- 只做有声书场景一条流水线：剧本导入→单角色/多角色合成→章节批量渲染→审听标记→返工→导出（含水印）
- 术语表 + 音色授权管理（合规差异化从第一天就在）
- 平台：macOS（Apple Silicon）优先——目标用户（编辑/制作人）的主力机型
- 不做：视频配音对齐、实时语音、云端协作（V2 再说）
- 验证指标：3 家种子出版社完成真实书目生产（每本 ≥8 小时成品），对比其云端 API 账单验证"三个月回本"叙事

**定价策略**：
- **创作者版**：$79/月 或 $790/年，单机、单项目并行，个人作者/小播客
- **工作室版**：$399/月起（含 3 席位），多项目、批量队列、协作审听、局域网服务端
- **出版社/企业版**：$25k-60k/年私有部署，含音色授权合规模块、水印存证、多工作站集群、SLA 支持
- 锚点话术：工作室版年费 ≈ 用云端 API 制作 15 本有声书的账单；企业版 ≈ 一年外包配音预算的 1/5
- 增值收入：官方音色市场（授权声优音色包，平台抽成 30%）——远期生态位

### 创意 2：「表智 TableMind」——业务分析师的零训练预测平台

**产品定位**：
面向无 ML 团队的中小企业业务部门（运营/风控/供应链）的**零训练表格预测平台**——底层用 TabPFN/TabICL 类表格基础模型（上下文内学习，不训练、不调参），上层包装成"上传 CSV → 选目标列 → 30 秒出预测 + 解释 + 模拟"的业务用户体验。一句话：**"把机器学习压缩成一次上传"**。核心差异化：不是更准（打平调优 XGBoost 即可），而是**把六周的数据科学项目变成三十秒的自助操作**，且输出是业务语言（"发券可挽回 ¥42 万 GMV"）而非 ML 语言（"AUC 0.81"）。

**核心功能**：
1. **三步预测向导**：上传 CSV/连接数据库→点选目标列（自动识别分类/回归）→出结果；全程无术语，进度以"AI 正在阅读你的数据"呈现
2. **自动解释面板**：每行预测附 top 特征归因（"该客户流失概率 82%，主要因为：近 60 天登录 0 次 + 上月投诉 1 次"）；全局特征重要性与业务白话翻译（LLM 生成）
3. **What-if 模拟器**：拖动业务杠杆看结果变化——"如果给流失概率 >0.7 的 1,203 人发 ¥20 券（假设响应率 15%），预期挽回 GMV ¥42 万，成本 ¥2.4 万"；模拟基于反事实推断的简化模型，输出带置信区间
4. **一键行动导出**：预测结果直接导出为营销名单（CSV/CRM webhook）、库存建议单、风控评分 API——**预测的价值在触发动作，不在报表**
5. **模型文档自动生成**：一键产出监管风格的模型说明书（数据来源、方法、局限性、验证指标）——金融业客户的合规刚需，零训练模型没有超参数反而让文档更干净
6. **数据体检报告**：上传即扫描缺失值/泄漏列/分布漂移，用业务语言提示（"手机号列与目标高度相关，疑似数据泄漏，建议排除"）——防止新手最常见翻车

**技术实现**：
- 预测引擎：TabPFN v2 / TabICL 开源实现，GPU 推理服务化；>10K 行的数据自动分片集成（TabPFN 的上下文长度限制用 bagging 绕过）；超大数据集自动降级到 LightGBM 快速通道（用户体验无感）
- 解释层：特征归因用 attention 权重提取 + SHAP 近似；业务白话翻译与体检报告用小型 LLM（可本地部署满足隐私客户）
- 模拟层：反事实估计用"特征干预 + 重推理"实现（表格基础模型推理秒级，天然适合蒙特卡洛式模拟）
- 架构：Web SaaS（数据用完即焚 + SOC2）与私有部署（Docker，金融/医疗）双形态；数据库直连（Snowflake/BigQuery/MySQL）企业版提供
- 护城河积累：匿名化的"数据集指纹 + 预测效果"反馈库，用于持续校准默认集成策略——客户越多，开箱越准

**MVP 范围**（3 个月）：
- 只做客户流失预测一个场景（数据最常见、价值最直观、演示最打动人）：CSV 上传→流失概率→归因→发券模拟→营销名单导出
- Web 端，单机 GPU 即可支撑（10K-50K 行数据的甜区）
- 不做：数据库直连、API 部署、时间序列（V2 路线图：销量预估→信贷评分→库存优化，一个场景一个场景纵深）
- 验证指标：20 家种子客户（电商/SaaS 各半）完成真实流失预测并至少触发一次营销动作；对照组（用 Excel RFM 分层）验证增量价值

**定价策略**：
- **免费层**：每月 3 次预测、单次 ≤5,000 行——获客漏斗，让分析师先尝到"30 秒出模型"的爽感
- **团队版**：$299/月，无限次预测（≤50K 行/次）、What-if 模拟、CRM 导出、3 席位
- **企业版**：$1,200-3,000/月，数据库直连、API 部署、模型文档生成、SSO、私有部署选项
- 计费逻辑：不按预测行数收（那会抑制使用），按席位+功能收——**平台的价值主张是"随时可问"，定价必须鼓励高频使用**；对比重型 AutoML（DataRobot $50k+/年）形成 10 倍价差
- 远期：垂直行业模板市场（信贷评分卡模板、餐饮销量模板），模板作者分成——复制 Airtable 的生态打法
