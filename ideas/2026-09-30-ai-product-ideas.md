1. **OpenAI 发布 "dots"：常驻型个人 agent 正式登陆消费市场，AI 助手的产品形态从"对话工具"切换到"24/7 数字分身"**。这是今天整个信息版图的震中。dots 的定位一句话：always-on agents built to handle everything——由 GPT-6 Astra 驱动、每个 dot 拥有自己的云端计算机和浏览器、通过插件生态连接 4,000+ 应用、跨 ChatGPT/Slack/Teams 触达、支持语音通话、随反馈持续学习用户偏好。OpenAI 官方披露的内测场景极具产品想象力：Slack 里出现一个 bug，dots 立即开始排查；设计稿一到，dots 在团队聚焦客户反馈的同时把它变成可运行的 app；早期测试者的 dot 发现他忘了给某刊物开发票，主动准备好发票并在获批后发出。**注意"获批后发出"这个细节——OpenAI 在常驻 agent 的自主性上选择了"主动提议 + 人类批准"的保守闭环，这是对 9 月以来 agent 问责讨论（昨日 MIT TR《Who's liable when AI agents go rogue?》）的直接回应**。产品层面的三个判断：其一，"常驻 agent"品类正式开局——此前 Always-on agent 只是 HN 上小团队的实验（今天榜单上恰好也有独立产品 Dots 同名项目蹭上了热度），OpenAI 入场意味着品类定义权之争开始；其二，**4,000+ 插件生态 = 一个新的分发平台**，围绕 dot 的技能/插件开发会是 2026 Q4 最确定的独立开发者机会（类比 2008 年的 App Store 时刻）；其三，对第三方 agent 产品是降维打击——"通用常驻管家"被 OpenAI 收编后，独立产品的生存空间进一步收窄到垂直工作流、数据主权（自托管）与治理层（详见需求 1、2 与创意 1、2）。

### 技术趋势

1. **arXiv 今日最实用的论文：《TokenCast: Forecasting Token Consumption During LLM Agent Execution》——agent 成本预测有了学术地基，"Agent FinOps"从口号变成可工程化的技术**。TokenCast 做的事：在 agent 执行过程中预测它将消耗多少 token——不是事后统计，而是事前/事中预测。这个能力栈的价值链很直接：预测准确 → 预算告警可以前置（"这个 agent 任务预计还要烧 $40，继续吗？"）→ 成本异常的自动熔断 → 多模型路由的期望成本计算。配合今天的两个产业信号——dots 常驻 agent（7×24 烧 token）与 Pro 500 层级（用户开始关心额度去哪了）——**"agent 财务监控"的需求时钟刚刚开始走动，而学术界已经递上了核心算法**。参照云时代的 FinOps 演化史（Cloudability 被 Apptio 收购、Vantage 融资 $45M），agent FinOps 是结构相同、时间提前重演一遍的赛道（详见创意 1）。

2. **HF 博客《Getting the Source Right, Not Just the Fact》：MCP agent 的"源感知验证"——RAG 的下一个进化点不是检索更准，而是引用可信**。这篇官方文章直指 agent 时代的事实核查痛点：agent 给出的"事实"可能正确但源错误（张冠李戴、过期文档、伪造引用），而 MCP 生态里 agent 自主调用工具链获取信息，源的可靠性无人把关。提出的方案是让 agent 在验证事实的同时验证来源资质。与同日的《Your Agent Aced the Task. Will It Do It Again?》（agent 任务可重复性研究）合起来看，HF 生态正在把火力集中到**"agent 输出的可信度工程"**：可重复、可溯源、可验证。这是昨天"评测存证"叙事的延续，但落地粒度更细：不是给模型打分，而是给每一次 agent 输出盖"源戳"。对企业采购的含义："我们的 agent 引用了哪份文档、那份文档是谁写的、现在还有效吗"即将成为合规审计的标准问题。

3. **NVIDIA 发布 Kumo Tabular：表格预测的新精度-效率前沿——"AI for 表格数据"这个被 LLM 叙事掩盖的干亿级市场正在被巨头重新定价**。Kumo 是 NVIDIA 的表格基础模型（tabular foundation model）系列，本次更新主打在不牺牲精度的前提下大幅降低推理成本。为什么重要：企业世界的真实数据主体不是文本而是表格（交易流水、库存、传感器读数、财务报表），表格预测（销量预测、流失预测、风控评分）是企业 AI 预算的最大单项之一，此前被 XGBoost/LightGBM 统治了近十年。基础模型入场意味着"每个数据集从零训模"的传统范式将被"预训练 + 微调"取代——训练成本降一个数量级、冷启动问题消失。同日 GitHub Trending 上 dbx（Rust 写的数据库工具）也在榜，表格数据基础设施的更新周期在多个层面同时启动。对中小企业的产品机会：把 Kumo 类模型包装成"上传 CSV 就能预测"的零代码工具（详见快速灵感 3）。

4. **《PhoneCLI: From App Interfaces to Callable Commands for Mobile Agents》：手机端 computer-use 的正确打开方式不是截屏点按，而是把 UI 编译成可调用命令**。这篇 arXiv 论文提出了移动端 agent 的关键工程思路：与其让 agent 看着屏幕坐标点击（慢、脆、贵），不如自动把 App 界面抽象成结构化的可调用命令——相当于给每个 App 自动生成一套 CLI。这与 HF 的 Holo4（通用 computer-use agent 专用模型）构成互补：Holo4 提升"看屏操作"的能力上限，PhoneCLI 则绕过"看屏"本身。两条路线的竞赛决定了移动端 agent 的成本曲线：如果 PhoneCLI 路线可行，手机上跑 agent 的 token 消耗会比视觉路线低 10-100 倍——对"常驻 agent 装进每个人手机"的终局叙事至关重要。

5. **GitHub Trending 三连星：VoiceStudio（单日 +4,712，连续三日霸榜）、Hindsight（+2,541，agent 记忆）、paperclip（+2,412，agent 管理）——社区注意力的三极结构：本地语音、agent 记忆、agent 管理**。VoiceStudio 的连续霸榜确认了"本地语音栈"需求的真实性（隐私敏感 + 零边际成本 + 可离线），与今日 Transformers 支持 llama.cpp quants 的本地化大势同频；Hindsight 与 paperclip 连续第二天保持高增速，印证昨日判断：**agent 生态的"记忆层"与"管理层"是当前开源社区最确定的两个基础设施缺口**。另一个值得注意的信号：PostHog 开源了 Jeeves（用推理能力增强 Jev 式决策模型）登上 HN——产品分析公司入场"决策模型"，说明"用小模型 + 推理链做高频产品决策"的工程路线正在被头部开发工具公司采纳。加上 TurboGPT（13 秒训完 22KiB transformer，Show HN 36 分）的教育意义，"小而快"的模型叙事在工程社区持续升温。

## 🎯 潜在需求分析

### 需求 1：Agent FinOps（"每个常驻 agent 的 token 账单都要可预测、可解释、可熔断"）

**痛点来源**：
- ChatGPT Pro 500 热帖 195 条评论里的高频抱怨："我不知道我的订阅额度花在哪了"——AI 消费不透明已从开发者话题扩散到消费者
- dots 发布：常驻 agent = 7×24 小时自主烧 token，用户睡觉时它在干活也在花钱——"失控账单"焦虑是常驻 agent 普及的第一道心理门槛
- TokenCast 论文（arXiv 今日）：agent 执行中的 token 消耗预测已有学术方法，但无任何商业产品化
- HN 上月热帖"我的 Claude 账单一夜 $3,000"类事故每周都在发生：循环重试、上下文膨胀、模型误选是三大账单杀手
- 企业侧：部署 30+ agent 的公司，AI 支出已成 P&L 上增长最快的行项，CFO 开始要"每笔 agent 开销的归因报告"——但没有工具能回答"这个 agent 为什么这周多花了 40%"

**具体场景**：
一家 200 人的电商公司给运营团队配了 12 个常驻 agent（选品、客服、报表、投放）。月底财务发现 AI API 支出环比涨了 3 倍，但没人能回答：哪个 agent 涨的？为什么涨？是任务量增加、上下文膨胀、还是某个 agent 陷入重试循环？CTO 只能手动翻日志。如果有 Agent FinOps 平台：每个 agent 的 token 消耗实时归因到任务/用户/模型；TokenCast 类预测在任务启动时给出成本预估（"这个批量选品任务预计 $12，超出预算阈值，需审批"）；异常模式（循环重试、上下文爆炸、昂贵模型误路由）自动告警甚至熔断；月底一键生成"AI 支出归因报告"给 CFO——就像云时代 Datadog Cost Management 对 AWS 账单做的事。个人重度用户同样需要：Pro 500 订阅者想知道自己的额度花在了哪些 dot 任务上、哪些可以降级到便宜模型。

**市场机会**：
- 目标客户：部署 5+ agent 的技术团队、AI 支出超 $10k/月的中型公司、agent 平台厂商（嵌入 OEM）；二期扩展到 Pro 层重度个人用户（浏览器插件形态）
- 品类定义：Agent FinOps = 实时归因（每笔 token 开销到任务/用户/模型级）+ 成本预测（TokenCast 式执行前预估）+ 预算与熔断（阈值告警、自动降级、循环检测）+ 路由优化建议（"这类任务用 Sol 而非 Astra 可省 80%"）
- 参照系：云 FinOps 市场（Vantage $45M 融资、Cloudability 被收购）——agent FinOps 是同构需求的重演，但时间窗口更早、增速更快（agent 支出增速远超云支出）
- 定价锚点：按监控的 agent 支出抽成 2-5%（云 FinOps 标准模式）或 $500-3,000/月平台费；ROI 故事："我们平均帮客户省 30-50% agent 账单，省下的钱十倍于订阅费"
- 时机判断：今天 dots + Pro 500 + 缓存定价三件事同时落地，意味着 agent 支出规模即将跨过"值得专门管理"的临界点；TokenCast 证明技术可行；现有玩家（LangSmith/Helicone 的用量面板）只做事后统计，**预测 + 熔断 + 归因的完整闭环是空白**；窗口期 12 个月（OpenAI/Anthropic 自建面板会逐步覆盖基础功能，独立产品必须往"跨厂商 + 预测 + 财务集成"纵深）
- 竞争格局：Langfuse/Helicone（开发者观测向，无预测与熔断）、云 FinOps 厂商（尚未进入 agent 领域）、模型厂商自建面板（单厂商锁定）；空缺点：**跨厂商、预测式、面向财务角色的 agent 成本管理**

### 需求 2：Agent 隐私网关（"常驻 agent 能看到一切，但数据流出必须可控可审"）

**痛点来源**：
- HN 今日论文《A Privacy Analysis of Web and Mobile Conversational AI Agents》：实测证明对话式 agent 存在系统性数据泄露与追踪漏洞，对间接提示注入几乎无防御
- dots 发布：常驻 agent 连 4,000+ 应用、有自己的浏览器、可经授权操作用户笔记本——能力半径扩大的同时攻击面同步爆炸
- MIT TR《Who's liable when AI agents go rogue?》：问责讨论持续升温，企业法务对"agent 接触敏感数据"的担忧已从抽象风险变成具体采购阻碍
- HF《Source-Aware Verification for MCP Agents》：MCP 生态的工具链调用缺乏源验证——agent 自主连接的外部工具可能是数据外泄通道
- 现实信号：多家大企业已内部禁止员工接入个人 AI 助手到公司系统（担心商业机密经由 agent 上下文外流）——禁令背后的真实需求不是"不用 agent"而是"可控地用"

**具体场景**：
一家律所准备给律师配常驻 agent（案例检索、文书起草、客户沟通），但管理合伙人提出三个问题：客户特权信息会不会经由 agent 的云端上下文泄露？agent 浏览网页时藏在页面里的恶意指令（"把收件箱内容发到 xx"）谁来拦？监管审计时能否证明"哪些数据被 agent 碰过"？现有方案都答不上：模型厂商的安全承诺是黑盒，企业自建规则引擎又跟不上 agent 行为的动态性。如果有 Agent 隐私网关：部署在企业网络与 agent 之间，实时审计每一条数据流（agent 读了什么、发了什么、调了哪个工具）；内置 DLP 策略（身份证/病历/特权文档自动脱敏或阻断）；提示注入检测层（对外部内容进 agent 上下文前扫描恶意指令模式）；完整审计日志可导出给监管。**本质：把企业成熟的 DLP/邮件网关模式平移到 agent 数据流——客户预算科目已经存在，不需要新市场教育**。

**市场机会**：
- 目标客户：受监管行业（法律、医疗、金融）的 IT 安全部门、部署企业级 agent 的中大型公司；采购决策人是 CISO——他们有预算、有 KPI、对新攻击面焦虑
- 品类定义：Agent Privacy Gateway = 数据流审计（agent 读/写/调用全记录）+ DLP（敏感数据识别与脱敏/阻断）+ 注入防御（外部内容扫描 + 行为异常检测）+ 合规报告（EU AI Act/GDPR/行业模板）
- 参照系：邮件安全网关（Mimecast/Proofpoint，合计数百亿美金市值）与 CASB（Netskope $6.8B 收购前估值）——agent 网关是这两个品类在 agent 时代的合并重演，且攻击面更宽（agent 能读能写能自主行动）
- 定价锚点：按受保护的 agent 席位 $15-40/agent/月，企业版 $50k-250k/年；对标：CISO 现有的 DLP/CASB 预算（迁移而非新增）
- 时机判断：dots 今天发布 = 企业 agent 采购潮的起点，隐私网关是采购清单上的强制附件；HN 论文证明风险已被安全社区实证；现有玩家（Lakera 做注入检测、Prompt Security 初创）都只覆盖单一环节，**完整的"审计 + DLP + 注入防御"三合一是空白**；窗口期 18 个月（之后 Palo Alto/Zscaler 会把能力做成插件）
- 竞争格局：Lakera（注入检测单点）、Netskope/Zscaler（CASB 延伸，agent 感知弱）、模型厂商内置安全（黑盒不可审计）；空缺点：**企业可控、可审计、跨厂商中立的 agent 数据流网关**

### 需求 3：学术与专业内容的"人类贡献度审计"（"这篇论文/报告/申请，AI 写了多少？"）

**痛点来源**：
- HN 124 分：Polson 年产 258 篇论文——AI 代笔让论文产量与质量脱钩，同行评审体系濒临失效
- MIT TR 头条《When can we say AI made a scientific discovery?》："AI 参与"的署名与问责规则完全空白
- arXiv《Failure-Transparent Agents》：agent 系统性低报失败——AI 产出内容的"自我声明"不可信，需要外部审计
- 高校现状：学位论文、基金申请、同行评审报告都被 AI 渗透，但编辑部/学位委员会只有"AI 检测器"这种准确率存疑的粗糙工具（GPTZero 类误报率已被多次证明高得不可用）
- 监管信号：多家顶级期刊 2026 年起要求作者提交"AI 使用声明"，但声明全靠自觉，无验证手段——"需要审计工具"的制度基础已经铺好

**具体场景**：
一家期刊出版社每周收到 2,000 篇投稿，编辑部需要回答：哪些论文存在"AI 代写未声明"？哪些同行评审意见是评审人用 AI 批量生成的（这直接破坏评审质量）？现有 AI 检测器在改写/翻译后准确率崩盘，编辑部不敢依赖。如果有"贡献度审计平台"：不只做文本检测，而是结合过程证据——写作过程日志（编辑器集成，记录人类修改轨迹）、代码/数据可复现性验证（论文附带的实验能否重跑）、引用源验证（HF 源感知验证技术的学术场景应用）、统计异常检测（同一作者产量突变、文本风格漂移）——给出多维度"可信度评分"而非二元判决。学位委员会、基金评审、企业招聘（笔试/作品集审计）同构适用。

**市场机会**：
- 目标客户：期刊出版社（Elsevier/Springer 级 + 长尾）、高校学位办、基金机构、企业招聘（作品集审计）
- 品类定义：Contribution Audit = 过程存证（写作/实验的完整轨迹）+ 多维检测（文本风格/统计/可复现性）+ 声明验证（AI 使用声明与实际证据交叉校验）+ 审计报告（可直接用于撤销/问责程序）
- 参照系：学术查重（Turnitin/iThenticate，数亿美金年收入规模）——贡献度审计是"查重"在 AI 时代的升级版，采购预算科目已存在
- 定价锚点：按审计量计费（$10-50/篇）+ 机构年费（$20k-200k/年，按规模）；对标 Turnitin 机构订阅（高校每年 $10k-100k）
- 时机判断：AI 使用声明制度已在铺开但无验证手段 = "制度先行、工具缺位"的经典窗口；Polson 事件把话题推上 HN 首页说明社区共识正在形成；风险：Turnitin 类巨头转型（对冲：专注"过程存证 + 多维证据"而非文本检测单点，建技术壁垒）
- 竞争格局：GPTZero/Turnitin AI（文本检测单点，准确率争议大）、出版社自建声明制度（无验证）；空缺点：**过程存证 + 多维证据的可审计平台**

## 🚀 新产品创意

### 创意 1：TokenGuard —— Agent 时代的 FinOps 平台（"每个 agent 任务的成本，事前可预测、事中可熔断、事后可归因"）

**产品定位**：
面向部署多 agent 团队与企业的成本治理平台——把云 FinOps 的成熟范式（归因、预测、预算、优化）平移到 agent token 支出。一句话价值主张："平均帮客户省 40% agent 账单，并在账单失控前 30 分钟发出告警"。定位选择今天而非昨天的原因：dots 发布后，常驻 agent 从极客玩具变成企业标配，"7×24 自主烧钱"的焦虑将在未来两个季度集中爆发；TokenCast 论文则证明预测技术已可工程化。

**核心功能**：
1. **实时成本归因（Attribution）**：每笔 token 开销自动打上"任务/用户/agent/模型/工具"五维标签——CFO 问"这个月 AI 支出为什么涨 3 倍"，答案在一张下钻式报表里（哪个 agent、哪类任务、哪次变更）
2. **执行前成本预测（TokenCast 产品化）**：agent 任务启动时给出预估区间（"批量选品 1,000 SKU ≈ $8-14"）；超阈值自动转入审批流；预测精度随使用数据增长（团队级校准）
3. **异常熔断（Circuit Breaker）**：三类杀手自动拦截——重试循环（同一工具连续失败 N 次）、上下文膨胀（单次调用 token 超历史 P99 的 3 倍）、贵模型误路由（简单任务走了旗舰模型），熔断后自动通知而非静默杀死（保留人类决策权）
4. **路由优化顾问（Advisor）**：基于历史任务数据生成"降级建议"——"这类摘要任务 Sol 与 Astra 质量分无显著差异，切换可省 78%"；缓存优化建议（"把系统提示词固定前缀可触发 $0.10/M 缓存价，预计月省 $2,300"）
5. **财务报告自动化**：月度 AI 支出归因报告（PDF/CSV，对接 ERP），预算 vs 实际追踪，部门级分摊（showback/chargeback）

**技术实现**：
- 接入层：LLM 网关代理模式（兼容 OpenAI/Anthropic/HF 推理端点的 API 反代，零代码接入）+ SDK 埋点（深度归因）+ 日志导入（事后分析）
- 预测引擎：复现 TokenCast 方法（基于任务结构/历史执行轨迹的 token 消耗回归），叠加团队级在线校准；预测误差目标 <20%
- 归因引擎：调用链追踪（OpenTelemetry 兼容，gen_ai 语义约定），任务树建模（父子任务/子 agent 调用的成本级联分摊）
- 熔断引擎：流式监测 + 规则引擎（默认规则库 + 自定义），误报率优先于召回率（宁可漏拦不可错杀，避免打断生产）
- 数据层：ClickHouse 存调用明细（成本敏感场景支持客户自托管），隐私模式（只存元数据与统计量，不存提示词正文）

**MVP 范围（3 个月）**：
- 只做网关代理 + 归因看板 + 三类熔断规则 + 月度报告——预测与路由顾问放二期（需要数据积累）
- 目标客户：5-50 个 agent 的技术团队（CTO/平台工程师是买家），先接 OpenAI + Anthropic 两家（覆盖 90% 支出）
- 验证方式：开源归因看板免费获客（Langfuse 模式），熔断与预测做付费层；找 10 个种子团队免费接入，用"第一个月实际省下的金额"做案例营销
- 验证指标：归因覆盖率 >95%、熔断误报率 <5%、种子客户账单降幅 >25%

**定价策略**：
- 开源免费层：归因看板 + 基础告警（获客 + 社区飞轮）
- Team：$199/月（监控支出上限 $20k/月，超出按 1% 抽成）
- Business：$999/月 + 监控支出的 1.5%（预测、熔断、报告全功能）
- Enterprise：$30k-100k/年（自托管、ERP 集成、部门分摊、专属优化审计）
- 锚定逻辑："省下的钱十倍于订阅费"——抽成模式让客户零风险尝试；对标云 FinOps 抽成惯例（2-5%），agent 场景抽成更低但增速更快
- 防御性设计：归因数据可导出（开放格式），不锁客户；隐私模式优先（不碰提示词正文，降低采购阻力）

### 创意 2：Veil —— 企业 Agent 隐私网关（"agent 可以连接一切，但数据只能按规则流动"）

**产品定位**：
部署在企业网络与常驻 agent（dots、Claude、自建 agent）之间的安全中间层：审计每一条数据流、拦截敏感数据外泄、检测间接提示注入、生成监管级审计报告。一句话价值主张："让 CISO 敢把 agent 接入公司系统"。定位选择今天的理由：dots 发布 + HN 隐私论文同日出现，供需两端同时到位——企业 agent 采购潮刚开始，而安全风险已被实证；邮件网关/CASB 的采购预算科目可直接迁移，无需新市场教育。

**核心功能**：
1. **数据流审计（Audit）**：agent 的每一次读（邮件/文档/数据库）、写（发送/修改）、工具调用都生成结构化审计事件——"哪个 agent、什么时间、碰了哪些数据、流向哪里"可回放可检索；审计日志 WORM 存储（不可篡改，满足法务证据要求）
2. **DLP 策略引擎（Redact/Block）**：内置敏感数据识别器（身份证/银行卡/病历/特权文档/源代码秘钥），命中策略可选：脱敏后放行、阻断并通知、转人工审批；策略按 agent/用户/目标应用细粒度配置（"客服 agent 可读工单但不可读薪资表"）
3. **注入防御（Injection Shield）**：对外部内容（网页、邮件、PDF）进 agent 上下文前扫描恶意指令模式（基于分类器 + 启发式规则双引擎）；对 agent 行为做异常检测（突然批量读收件箱、尝试连接白名单外域名 → 自动隔离并告警）
4. **权限影子模型（Shadow Policy）**：把公司现有的数据权限体系（AD 组/RBAC）自动映射到 agent 权限——agent 继承其操作人的权限边界，"实习生配的 agent 读不到董事会文件夹"
5. **合规报告（Compliance）**：一键生成 EU AI Act/GDPR/行业监管模板的 agent 数据处理报告；安全事件时间线可直接用于监管问询响应

**技术实现**：
- 接入形态三种：API 代理（agent 流量经 Veil 转发，零改造）、MCP 网关（拦截 MCP 工具调用，覆盖 dots 插件生态）、浏览器扩展/网络层代理（覆盖 agent 自有浏览器的网页流量）
- 敏感数据识别：正则 + NER 模型双层（准确率优先，误报可白名单化）；支持客户自定义识别器（行业特有文档格式）
- 注入检测：微调的小分类模型（参照今日 arXiv 多篇 injection detection 工作）+ 行为基线异常检测（agent 历史行为分布建模，偏离即告警）；检测在边缘完成（延迟 <50ms，不阻塞 agent 交互）
- 审计存储：结构化事件流（WORM/对象存储 + 哈希链，防篡改），支持 SIEM 转发（Splunk/Elastic）
- 部署：VPC 内自托管优先（目标客户是安全敏感的受监管行业，SaaS-only 方案进不了采购短名单），提供 K8s Helm 一键部署

**MVP 范围（4 个月）**：
- 只做 API 代理形态 + 审计 + DLP 脱敏/阻断（注入检测用规则引擎 v0，模型版二期）
- 先支持 OpenAI dots/Claude 两家流量（企业 agent 主流），MCP 网关二期
- 验证方式：找 3 家受监管行业（律所/诊所/金融科技）做设计伙伴，免费部署换案例与策略模板；发布"agent 数据泄露红队测试报告"做市场教育（参照 HN 今日论文的传播路径）
- 验证指标：审计覆盖率 100%（代理形态天然全覆盖）、DLP 准确率 >98%、延迟开销 <80ms、设计伙伴续约意向

**定价策略**：
- 按受保护 agent 席位：$25/agent/月（<50 agents），阶梯降至 $12（>500）
- Enterprise：$80k-250k/年（自托管、SIEM 集成、合规报告、专属策略工程支持）
- 渠道：与 agent 平台厂商合作 OEM（dots Enterprise 的"安全附件"），分成模式
- 锚定逻辑：对标 CISO 现有 DLP/CASB 预算（迁移而非新增）；ROI 故事："一次 agent 数据泄露事故的均成本（法务 + 声誉 + 监管罚款）是十年订阅费"
- 防御性设计：审计日志客户完全拥有（开放格式可导出）；策略引擎可编程（Terraform 式声明配置），安全团队可审计可定制——"安全产品自身的透明度"就是对黑盒厂商方案的最大差异化
