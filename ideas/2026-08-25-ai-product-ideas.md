## 📊 今日核心洞察

### 热点话题

1. **"Fences, Not Sandboxes"（yegge.ai，37 分/21 评论）+ "LLMs could control their host machines by exploiting inference engines"（70 分/35 评论）——Agent 安全的范式之争正式开打**：Steve Yegge 这篇新文主张：给 agent 建重型沙箱是错误方向（沙箱拖慢 agent、逼走生产力），正确做法是**"围栏"——轻量、策略驱动、内联在 agent 工作流里的权限边界，放行时即时审批，而不是把 agent 关起来**。同屏的 Boyd Kane 安全研究更狠：LLM 推理引擎本身（如某些开源 serving 栈的 parser/deserializer 路径）存在可利用漏洞，攻击者可以让 agent **逃出"看似隔离"的运行时控制宿主机器**——沙箱的安全假设正在被证伪。叠加今天 Show HN 的 **Kern**（43 分，1.5MB 无守护进程的容器运行时，cgroup v2 + namespaces，启动 3.5ms，"为 CLI 和 agents 设计"）：**"给 agent 一个轻到无感的隔离/授权层"正在从理念变成工程实践**。

2. **记忆管理三连：IBM《How Much Memory Does Your Agent Actually Need?》（HF 博客 8/18）** 用 ALTK-Evolve-HMM 研究 agent 记忆的"够用原则"——**记忆不是越多越好，分层（工作/情景/语义）+ 主动遗忘才是正解**；同屏 **Apache Maka**（Incubating，今日 +408 stars）——local-first agent workspace，把 message/tool call/权限决策/终止事件全部记成 **append-only 日志**（可审计的 agent 记忆账本）；**NousResearch/hermes-agent** 登榜，Slogan 就是 **"The agent that grows with you"**（随你成长的 agent）。加上昨日 openhuman（本地优先生活记忆大脑）：**"Agent 该记什么、记多久、记在哪、谁拥有"正在成为 agent 平台的第二战场**——上下文窗口是稀缺资源，记忆管理是它的"虚拟内存"。

3. **arXiv 2608.21357《VIALS: A Benchmark for Visual Interpretation of Artifacts in the Life Sciences》——前沿 VLM 读不懂科学实验图**：VIALS 收集了 161 个生物科技行业真实工作流中的视觉解读任务（凝胶电泳图、显微镜图像、质粒图谱、流式细胞图、分子结构），结论毫不客气：**frontier vision-language models 能流畅描述自然图像，却无法准确解读这些科学图像**——缺的是领域知识与领域视觉推理。作者点出要害：**"AI 读不懂这类图，在专业生命科学工作流里就没用"**。这类图是科学家推理、沟通、决策的核心载体，而目前 VLM 的能力曲线在这里出现断崖——垂直领域视觉理解的缺口 = 垂直 AI 产品的金矿。

4. **arXiv 2608.21356《AI with Authority, from Application to Silicon》——验证让"一人指挥 agent 舰队"成为可审计现实**：一位研究者靠消费级 AI 订阅，**5 周内指挥一小队 agent 从应用代码走完"验证过的编译器 → 执行器 → RISC-V 处理器流片"**，全程零人类 review 的 proof 通过、零人类手写 RTL。核心方法论（Salt method）：**数学声明以"内核验证过的 artifact"在 agent 之间流转**（Lean 4 内核 → SAT 等价性检查到硅边界），人类注意力只留给"陈述、设计、裁决"；错误账本记录到 #256 条，**零错误 proof 进入最终记录**。这是"验证即 referee：让一个人安全地规模化指挥自主机器工作"的完整实证——**AI 时代的"可验证自主工作"标准正在成形**。

5. **Hot Chips 2026: CUDA Targets RISC-V（Chips and Cheese，65 分）** + **LFM2.5-DSpark 3.2x 推理加速（HF 博客 8/20）**——硬件与推理效率双线升温：CUDA 生态开始向 RISC-V 开放（打破"想跑 AI 必须买 NV 专用栈"的隐含垄断），Liquid AI 用稀疏化（DSpark）把推理再提速 3.2 倍。延续 8/22-8/24 的"算力效率军备竞赛"主线：**每一 Token 的边际成本还在被继续打下去**。

6. **ai-job-search（MadsLorentzen）登榜——"跑在你机器上的求职"**：基于 Claude Code 的 AI 求职框架：评估职位匹配度、定制简历、写求职信、模拟面试，**数据全部本地、可 fork 可拥有**。叠加 **Agent Lightning v1.0（Microsoft，HN 22 分）** 发布：微软继续给 agent 开发脚手架打地基。**"找工作"这种高重复、高个性化、高情绪消耗的流程，正在被 agent 逐个环节接管**——求职是 agent 化最快的个人生产力场景之一。

7. **MIT TR 8/24 教育双稿：课堂 AI 政策（Making AI Work 系列）+ 《Kids outlearn AI — and we still don't know why》**：前者记录了 Cheshire Academy 的实操——**"红绿灯"式作业标注**（绿=AI 全放开 / 黄=部分工具可 / 红=禁用）、MagicSchool 这类 $100/年的教师专用平台、教师用 AI 备课但不敢用 AI 给学生写反馈（质量/隐私顾虑）；后者是数据效率 gap：**孩子学语言的数据效率是 LLM 的十万倍级**，科学家想反推儿童学习机制来造更省数据的模型。教育 AI 的痛点已经从"怎么防作弊"进化到"**学校需要一套可执行的 AI 使用治理与教学增强体系**"。

8. **延续信号复盘**：昨日免费的 **free-claude-code**（聚合免费 token）与 **claude-plugins-community**（今日 +490 stars）继续在榜，**skills 生态与免费 token 套利两条线热度不退**；**PostHog 官方仓库简介全面转向 "AI observability for self-driving products"**——数据基础设施公司集体向 agent 可观测性迁移，验证了 8/17 AgentOps 主线的机构级共识；昨天预告的"技能质量度量"（utility score）暂无新进展，但 **Maka 的 append-only 账本**补上了"技能行为审计"的另一角。

### 技术趋势

1. **Agent 安全从"沙箱"转向"围栏"**——重型隔离（VM/容器沙箱）被证伪为"又重又不保险"（推理引擎漏洞可穿透），**策略驱动的内联授权 + 轻量运行时隔离 + 行为审计**成为新方向，Kern 这类 1.5MB 运行时是"轻"的工程化身。
2. **Agent 记忆分层化**——HMM 研究给出"够用原则"（分层 + 主动遗忘），Maka 给出"append-only 账本"（可审计），openhuman/hermes-agent 给出"本地优先、随用户成长"（所有权）——**记忆层的标准形态还没定，但三块拼图已齐**。
3. **垂直领域视觉理解是 VLM 的最后一公里**——自然图像理解已红海，**科学/工业/医疗图像（凝胶、切片、质粒图、缺陷图）才是 frontier 模型的真实短板**，也是垂直数据壁垒最厚的地方。
4. **验证驱动的 agent 自主性**——"AI with Authority"证明：**只要 proof 由机器内核把关、审计账本完整，一个人可以安全地让 agent 舰队干完一个芯片**——验证基础设施（Lean/SAT/账本）将从学术界走向 agent 平台标配。
5. **推理效率继续边际革命**——CUDA 开源化到 RISC-V + 稀疏化推理 3.2x：**模型能力军备竞赛趋缓，单位算力产出竞赛加速**。
6. **个人高重复流程全面 agent 化**——求职（ai-job-search）、教学（MagicSchool 模式）、搜索已被逐个接管；**下一个被接管的是"需要持续个性化 + 多轮迭代"的知识工作流程**。

## 🎯 潜在需求分析

### 需求 1：企业想让 agent 干活，但"全沙箱太慢、裸奔太险"——缺一个轻量、策略驱动的 Agent 权限围栏层

**痛点来源**：
- **Yegge《Fences, Not Sandboxes》直接点破**：给生产级 agent（coding agent、CLI agent、运维 agent）套重型沙箱 = 每次工具调用都要穿越慢速边界，agent 生产力被砍；但**裸奔的 agent 有真实事故记录**（误删、越权、被 prompt 注入操控）
- **Boyd Kane 的研究**：**推理引擎本身是可利用的攻击面**——攻击者通过恶意的 tool result / 文档内容 / 模型输入触发解析器漏洞，让 agent 逃出"隔离"控制宿主机器。**这意味着"关起来"的安全假设本身就不可靠**，安全必须落在"行为层"而非"边界层"
- 与 8/18 的 AI 安全三段论（MCP Guard 事前扫描 → LiabilityChain 审批 → TracePilot 观测）对比：那些是**外部安全工具**；今天的需求是**内嵌在 agent 运行时的授权围栏**——agent 每次调用工具/访问资源时，由策略引擎实时裁决"放行 / 降权 / 问人"
- Kern（1.5MB，3.5ms 启动，专为 CLI 和 agents 设计）证明：**开发者已经自发开造轻量隔离件**，但 Kern 只解决"资源限制"，不解决"策略与授权"
- 现实的断层：企业试点 coding agent 时，要么给满权限（出事），要么塞进 K8s 沙箱（慢到没人用），**中间地带（细粒度策略 + 即时审批 + 可审计围栏）是空的**

**具体场景**：
某中大型 SaaS 公司的平台团队开始让 Claude Code / Codex 进生产仓库改代码。安全团队要求"所有 agent 操作必须隔离"，于是他们用容器沙箱包了一层——结果 agent 每次读 Git 历史、跑测试、查内部 API 都要等沙箱初始化，**一个 10 分钟的任务变成 40 分钟**，工程师开始偷偷绕过沙箱。他们真正想要的是：**agent 默认只能做"读"级操作；写文件要过策略（比如只能写 src/ 和 tests/，不能碰 deploy/）；调生产数据库 API 必须弹出人工审批（像 sudo 一样）；敏感操作（git push、删分支）自动降权；所有决策留痕可回放**。同时安全团队还想要"**如果攻击者通过恶意文档注入 prompt，围栏能否兜住**"——即工具调用层面按"最小必要权限"逐次授权，即使 agent 被操纵，也拿不到超出围栏的能力。

**市场机会**：
- 目标客户：已把 coding agent / 内部 agent 投入生产的团队（安全团队是采购方，开发者是使用者）；AgentOps 平台（8/17 主线）的补位组件
- TAM：对标云 IAM / 权限管理市场（Okta、AWS IAM 心智）在 agent 时代的重新定义；每个生产级 agent 部署都需要"围栏"——**这是 agent 平台的必装件而非选装件**
- 付费意愿：企业为"防事故 + 过审计"付费是成熟习惯；按 agent 席位 $15-30/月 或按"受管工具调用量"计费；**事故成本（一次误删生产数据 = 数十万美金）是天然的价格锚点**
- 竞品空白：沙箱类（Docker/K8s/gVisor）太重且不解决行为层；策略类工具散落在各家 agent 框架的 plugin 里，**无独立、跨框架（Claude Code/Codex/自建 agent）的统一围栏层**；Kern 只做资源隔离——**"轻量运行时 + 策略引擎 + 人工审批流 + 审计账本"一体化产品无人做**

### 需求 2：Agent 的上下文窗口是稀缺资源，记忆混乱导致"越用越笨、越用越贵"——缺"Agent 记忆层"产品

**痛点来源**：
- **IBM《How Much Memory Does Your Agent Actually Need?》**：记忆不是多多益善——**无差别堆记忆会稀释相关性、拉高延迟和成本**；正确形态是分层（工作记忆 / 情景记忆 / 语义记忆）+ **主动遗忘与压缩**（HMM 式演化）
- **Maka 的 append-only 账本**暗示另一面：记忆要**可审计**（谁在什么时候调用了什么、授权了什么），否则出了事无法复盘——**记忆不只是存储，还是责任链**
- **hermes-agent "grows with you" + openhuman 的"生活记忆"**：个人/团队希望 agent 跨会话记住用户偏好、项目上下文、历史决策，但**现有实现要么是"全塞进 system prompt"（贵且超窗），要么是"RAG 一把梭"（召回质量差）**
- 现实断层：一个跑了 3 个月的 agent 项目，会话历史几万条 message，用户发现：agent 忘了上周定下的架构决策、重复问已经答过的问题、上下文越塞越长每次调用费用肉眼可见上涨——**记忆的"容量管理 + 成本管理 + 质量管理"都是问题**
- 与 8/18 记忆主线的延续：个人数据主权（Hister、openhuman）之后，今天补上了**科学支撑**（HMM 分层）和**审计形态**（Maka append-only）——记忆层产品的前提条件已齐

**具体场景**：
一个 8 人 AI 产品团队用 agent 管理一个长期项目（需求池、代码库、客户反馈）。现状：每周都能遇到 agent "失忆"事故——不记得两周前定下的技术选型、在客户邮件里给出与新策略矛盾的答复、每次开会前要把过去的决策重新喂一遍。他们想要一个**记忆层**：agent 自动把重要决策、用户偏好、项目规则写入"语义记忆"（长期、可检索、压缩过）；日常对话进"工作记忆"（短期、自动过期）；**记忆有成本仪表盘**（这个月记忆相关的 token 花了多少钱、哪些记忆从未被召回可以淘汰）；**记忆可审计可导出**（出了争议能查"agent 当时依据什么做的决定"）；甚至**记忆可跨 agent 共享**（另一个 agent 接手同一项目时直接继承语义记忆）。市场上没有现成的"记忆即服务"——各家 agent 框架只给"上下文管理"原语，不给"生命周期管理"。

**市场机会**：
- 目标客户：重度使用 agent 的团队（agent 已成日常工作流）、个人知识工作者（长期个人助理场景）、AgentOps 平台（作为记忆模块集成）
- TAM：对标 Redis/向量数据库的"状态层"心智——**记忆是 agent 应用的状态，每个长时间运行的 agent 都需要**；同时是 LLM 成本优化的直接抓手（记忆管理好 = token 费下降）
- 付费意愿：按"管理的记忆量 + 召回次数"计费（类似向量库定价），或按席位 $10-20/月；**"省下的 token 钱"是即时可算的 ROI**（企业客户月 token 账单 $10K+ 时，15-30% 的节省非常可观）
- 竞品空白：LangMem / Mem0 是开发者库（要自己集成和运维），向量数据库只解决"存"不解决"分层、压缩、遗忘、审计"；**"分层记忆 + 生命周期管理 + 成本优化 + 审计导出"的开箱即用 SaaS 层无人做**

### 需求 3：生物科技公司每天要人眼解读大量实验图（凝胶、切片、流式图），前沿 VLM 又读不懂——缺"科学视觉解读"垂直助手

**痛点来源**：
- **VIALS 基准（arXiv 2608.21357）**：161 个真实工作流任务，frontier VLM 在凝胶电泳带型、显微镜图像、质粒图谱、流式细胞图等**专业图**上表现远低于领域专家——"能描述自然图像"≠"能解读科学证据"，**领域知识与领域视觉推理是硬缺口**
- 这些图是实验的核心证据载体：科学家每天花大量时间**人眼比对、标注、判断**（这块凝胶的条带是目标蛋白吗？这个质粒图谱的酶切位点对吗？）——**高重复、高耗时、高 expertise 门槛**
- 更麻烦的是**跨人一致性**：同一张图，两个技术员解读结论可能不同（主观判断），实验室的 SOP 记录、审计、论文复现都受影响
- 与 8/22 "AI 署名污染科研"的呼应：论文工厂问题之外，**科研界对"AI 读懂科学图像"是刚需但极缺可信工具**——现有通用 VLM 不可信（VIALS 已证明），垂直工具几乎没有
- 现实的断层：商业 VLM API 价格便宜但读不懂专业图；自研需要**领域数据（实验图像 + 专家标注）**——这东西恰恰只存在于实验室内部，是天然的垂直数据壁垒，**谁能拿到数据谁就能做出别人做不出的模型**

**具体场景**：
一个中型生物科技 CRO（合同研发组织）实验室，每天产出 500+ 张凝胶电泳图、200+ 张细胞图像、若干流式细胞图。现在由 4 个技术员轮流肉眼判读并填表，**每人每天 2-3 小时花在看图上**，且新员工培训 3 个月才能独立判读。他们想要一个内部工具：上传实验图 → AI 自动判读（条带/阳性对照/分子量标记）→ 输出结构化结论 + 置信度 → 技术员只审核异常项；**异常图自动标记**（出现非预期条带、污染迹象）；**所有判读留痕**（论文/审计可追溯）；**用公司自己的历史标注数据持续微调**，判读准确率越用越高——而不是像通用 VLM 那样"读个大概"。

**市场机会**：
- 目标客户：生物科技实验室/药企研发/CRO（图像密集的 wet-lab 环节）、大学科研组、BioTech 数据团队
- TAM：科研软件 + 实验室数字化市场（$10B+ 量级）中的"视觉解读"子集；**每个 wet-lab 实验室都是潜在客户，AI 解读是实验室自动化的下一个抓手**
- 付费意愿：按实验室席位 + 图量计费（$300-2000/月/实验室），或按"解读次数"计费；**替代的是技术员 2-3 小时/天的人力，ROI 是 3 个月内回本**；企业愿为"内部数据不出域"付 premium（本地/私有化部署）

### 创意 A：FenceGuard——Agent 权限围栏运行时（"Fences, Not Sandboxes"的产品化）

#### 产品定位
**一句话**：给生产级 agent 装上"数字化围栏"——默认最小权限、逐次授权、即时人工审批、全量审计，不牺牲 agent 速度（对标 Yegge 式"围栏而非沙箱"）。

#### 核心功能

1. **策略引擎（Policy-as-Code）**
   - 声明式围栏规则：`读全部 / 写 src,tests / 禁 prod / git push 需审批`
   - 按 agent、仓库、资源、敏感度分级策略（对标 IAM 的 role 心智）
   - 规则可视化 + 冲突检测（两条策略打架时编译期报错）

2. **内联授权代理（Inline Authorization Proxy）**
   - 透明代理 agent 的每个工具/API 调用（MCP 层注入），运行时逐次裁决：放行 / 降权（只读化）/ 弹审批
   - **sudo 式即时审批**：敏感操作在终端/IM 弹出确认，支持"本次允许 / 本次会话允许 / 永久允许"
   - 延迟预算：裁决 < 5ms（内存态策略），不拖慢 agent

3. **推理引擎加固与逃逸检测**
   - 对 tool result / 文档输入做解析器加固（缓解 Boyd Kane 式引擎利用）
   - 行为基线 + 异常检测：agent 行为偏离围栏预期（如突然访问 ~/.ssh）立即熔断并告警

4. **审计账本（Append-only）**
   - 每个决策（放行/拒绝/降权/审批人）追加式记录，可回放、可导出（SOC2 友好）
   - 与 Apache Maka 的 workspace 日志格式兼容（借鉴 append-only 账本思路）

5. **跨框架适配**
   - 支持 Claude Code、Codex、Gemini CLI、自建 agent（LangGraph 等）——统一接入层

#### 技术实现
- **接入方式**：CLI wrapper + MCP 代理 + 环境变量注入，三合一（对现有 agent 无侵入）
- **策略引擎**：OPA（Open Policy Agent）或 Cedar（AWS 开源策略语言），Rego/Cedar 规则编译为本地决策树
- **运行时**：借鉴 Kern 思路做可选轻量资源围栏（cgroup v2），默认纯用户态（零权限要求）
- **审计存储**：本地 SQLite（默认）+ 可选 remote（S3/ClickHouse）——local-first 起步
- **审批通道**：Slack/飞书/Discord bot + 终端 TUI（阻塞式等待）
- **语言**：Rust（核心，单二进制分发，对标 Kern 的 1.5MB 哲学）+ TypeScript（控制台）

#### MVP 范围（6 周）

| 周次 | 目标 |
|------|------|
| 1-2 | 策略引擎 + Claude Code/Codex 接入（读/写/执行三类动作裁决） |
| 3-4 | 即时审批流（终端 TUI + Slack bot）+ 审计账本 + 回放视图 |
| 5-6 | 异常行为告警 + 降权模式 + 3 家 beta（安全团队试用） |

**MVP 成功标准**：
- 3 家 beta 团队日常使用，agent 任务耗时增加 < 10%（对比沙箱方案的 +300%）
- 100% 敏感操作有审计记录
- 至少 1 次成功拦截"被注入的 agent 越权行为"的演练

| **Free** | $0 | 个人开发者 | 单 agent、基础策略、本地审计 |
| **Team** | $19/席位/月 | 小团队 | 多 agent、审批流、Slack 集成、异常告警 |

### 创意 B：MemLayer——Agent 记忆层（分层记忆 + 生命周期管理 + 成本优化）

#### 产品定位
**一句话**：给 agent 装"多级缓存式的记忆"——工作记忆短期自动过期、语义记忆长期可检索、主动压缩与遗忘控制成本，记忆可审计可继承（IBM HMM 论文 → 产品的直接落地）。

#### 核心功能

1. **三层记忆模型**
   - **工作记忆**（短期）：当前任务上下文，自动过期（比如 48h）
   - **情景记忆**（中期）：会话/任务摘要，自动压缩（HMM 式演化更新）
   - **语义记忆**（长期）：用户偏好、项目决策、领域规则——高价值、低冗余，只此层进向量库
   - 记忆"温度"机制：频繁召回的记得牢，从不召回的自动淘汰

2. **记忆写入管线**
   - 监听 agent 会话（LangGraph/MCP/CLI wrapper 接入），自动判定"哪些对话值得沉淀"
   - 决策/约定识别：判定为"项目决策"的内容自动提炼进语义记忆并标注时间线
   - 去重与合并：同一主题多条记忆自动融合（避免 50 条"用户喜欢简洁"的冗余）

3. **记忆召回 API**
   - `remember(query)` → 跨层检索 + 相关性排序 + **引用来源**（这条记忆来自哪次会话）
   - 权限过滤：不同 agent/用户看到的记忆范围不同（项目隔离）
   - 低成本召回：优先查本地小索引，命中率 < 阈值才调 embedding API

4. **成本仪表盘**
   - 记忆相关 token 花费追踪（写入/召回/注入各多少）
   - "记忆 ROI"报告：哪些记忆被高频使用（留下）、哪些从未命中（建议删除）
   - 注入预算控制：每次会话最多注入多少 token 的记忆（防止记忆把上下文撑爆）

5. **审计与继承**
   - append-only 变更日志（借鉴 Maka）：谁写入、谁修改、何时过期
   - **记忆导出/迁移**：换 agent 框架、换项目时一键带走
   - 跨 agent 共享：新 agent 接手项目时继承语义记忆（团队 onboarding 加速）

#### 技术实现
- **SDK 层**：Python/TypeScript SDK + MCP server（agent 通过 MCP 调用记忆工具）
- **存储**：本地 SQLite (FTS5 全文索引) + 可选 pgvector/Qdrant（语义层）；**默认 local-first**
- **抽取**：小模型（Qwen3 系 / Gemma 系本地跑）做"值得沉淀吗 → 提炼 → 压缩"三步，避免每次提炼都调大模型烧钱
- **压缩**：HMM/演化式摘要（引用 IBM ALTK 思路），按 token 预算做迭代压缩
- **召回**：BM25 优先 + embedding 兜底（混合检索），命中校准
- **计费**：用量采集 + 按量计费网关

#### MVP 范围（6 周）

| 周次 | 目标 |
|------|------|
| 1-2 | 三层记忆模型 + SQLite 存储 + 写入管线（接入 Claude Code 会话） |
| 3-4 | 召回 API + 注入预算控制 + 成本仪表盘 v1 |
| 5-6 | 记忆审计日志 + 导出/继承 + 3 家 beta（agent 重度团队） |

**MVP 成功标准**：
- beta 团队 agent "失忆"事故率下降 50%+
- 记忆相关 token 成本下降 ≥ 25%（压缩/遗忘生效）
- 单次召回延迟 < 100ms（本地索引）

### 创意 C：SciLens——生命科学实验图像解读助手（凝胶/切片/流式图专用）

#### 产品定位
**一句话**：给 wet-lab 科学家的"第二双眼睛"——读懂凝胶电泳、显微镜、流式细胞等实验图，输出结构化判定 + 置信度，用实验室私有数据越用越准（VIALS 缺口的产品化）。

#### 核心功能

1. **专业图像判读（首批三类）**
   - **凝胶电泳**：条带识别、分子量标记比对、阳性/阴性对照判定、异常条带/拖尾/污染提示
   - **显微镜图**：细胞计数、形态分类、荧光共定位粗判
   - **流式细胞图**：门控区域识别、种群比例粗算（与 FlowJo 导出兼容）
   - 每张图输出：结构化结论 + 置信度 + 判定依据（圈出的区域可视化）

2. **异常与质控哨兵**
   - 偏离预期的条带/形态自动标记（非预期条带、空泳道、边缘效应）
   - 实验质控检查单（对照是否齐全、标记是否正确）自动核对
   - 审稿/审计场景：复现性检查（同一实验多张图一致性比对）

3. **私有数据闭环**
   - 实验室上传自己的历史标注 → 持续微调领域模型（数据不出域，支持私有化部署）
   - 人机协同标注台：技术员快速标注/纠错，标注即训练数据

5. **与现有工具链兼容**
