## 🎯 潜在需求分析

### 需求 1：空间情报的**合规商用工作台**——让"看着地球做判断"从情报机构专属变成企业可用的能力

**痛点来源**：
- `gods-eye-view` 的爆红证明"卫星影像 + 3D 地球 + 实时空间分析"的技术栈已经开源可复现，但它的默认形态是**面向极客的炫技模拟器**：数据虽真实，却停留在"看"，没有"用"——不能生成结论、不能对接业务流程、没有合规边界。
- 真实世界的空间情报需求极其旺盛且高度付费化：**保险定损/农险**（灾后地块评估）、**大宗商品**（港口库存、油罐阴影、船运流量）、**地产与基建**（施工进度、土地变化）、**碳与 ESG**（森林覆盖变化、甲烷泄漏）、**供应链风险**（工厂开工率、库存堆积）、**政府/应急**（洪水、山火、灾害响应）。
- 现有工具割裂：遥感平台（Planet、Sentinel Hub）只管"拿图"，GIS（ArcGIS/QGIS）只管"画图"，分析师仍要**手工挑图、肉眼看、凭经验下结论**，无法规模化、无法审计、无法复现。

**具体场景**：
一家做农产品期货的机构，想每周追踪北半球主要产区的作物长势与受灾情况。今天要么买昂贵且口径不透明的数据服务，要么养一支会写 Python 的分析师团队手工处理 Sentinel 影像。**若能把"目标区域定义 → 自动拉取匹配时段影像 → 变化检测/长势指数（NDVI）/洪涝范围识别 → 生成带置信度与来源的分析简报 → 推送到交易员"串成一条可复现的 agent 流水线**，同样的追踪可从"周级、手工、不可复现"变成"日级、自动、每次结论都能追溯到具体影像与算法"。真正需要的产品是：**一个"有合规边界（数据授权、地理围栏、用途审计）的空间情报工作台"**。

**市场机会**：
- 目标客户：大宗商品/期货机构、保险与再保险、地产与基建、碳与 ESG 服务商、政府与应急部门
- 付费意愿：$50k-500k / 年（按监控区域数、分析频率、是否含定制算法分级），金融/保险场景预算刚性、结论直接关联真金白银
- 竞品空白：遥感平台无分析工作流，GIS 无 agent 编排，情报级服务贵且不透明，**"开源数据 + 自动化分析 + 合规审计 + 业务推送"几乎空白**
- 时机判断：`gods-eye-view` 证明技术栈成熟且大众关注度被点燃；开源数据成本趋零，先做出"可交付结论"的合规产品者可抢品类定义权

### 需求 2：Agent 的**上下文治理与成本套利基础设施**——把"垃圾工具输出"挡在模型之外

**痛点来源**：
- `context-mode` 的自述就是最诚实的市场调研：**工具输出占了 98% 的上下文，真正有用的信息被淹没**，导致 agent 变慢、变贵、还变笨（关键信息被挤出窗口）。这是所有跑 agent 的团队每天都在流血的地方。
- 三个真实痛点：①**成本失控**——一个复杂 agent 任务动辄几十万到上百万 token，绝大部分是日志、HTML、重复文件；②**记忆断裂**——会话一断、任务一长，agent 就"忘了"之前做过什么，反复踩同一个坑；③**多平台路由混乱**——同一团队在 Claude Code / Codex / 各类 IDE 插件间切换，上下文格式互不兼容。
- 现有做法是各自写胶水脚本：压缩日志、手写摘要、打补丁式记忆——**没有统一、可观测、可治理的层**。

**具体场景**：
一个团队用 coding agent 做大型代码库重构，agent 每执行一次测试就灌入数百行日志，跑十几轮后上下文爆炸、成本飙升、还开始丢关键约束。**若有一个"上下文治理代理"驻留在 agent 与工具之间：对工具输出做结构化沙箱（只留摘要与关键片段，降幅 90%+）、把会话记忆落到可检索的外部存储、按任务类型自动路由到最划算的模型/平台**，同样的重构任务可显著降本且更稳。真正需要的产品是：**一个 agent 运行时旁边的"上下文防火墙 + 记忆层 + 路由层"**，且必须可观测（每笔 token 花在哪、省了多少）。

**市场机会**：
- 目标客户：所有自建 agent 的工程团队、AI 编码工具的深度用户、agent 平台厂商（作为基础设施 OSS/SDK 分发）
- 付费意愿：按席位 $20-100/月，或按"节省的 token 成本"分成，工程团队对"直接降本 + 提成功率"的付费意愿极强
- 竞品空白：现有方案是单点脚本或绑定单平台，**跨 harness、跨模型的统一上下文治理层几乎空白**
- 时机判断：context-mode 已在 Trending 验证需求真实；coding agent 普及率仍在快速上升，治理层是典型的"卖水"生意

### 需求 3：**模型路由与算力套利平台**——让"选对模型、压平成本、保持可交付"变成自动能力

**痛点来源**：
- `free-claude-code` 的爆红背后是一个尴尬现实：**模型与工具从未统一，用户被迫在多订阅、多 API、多客户端间疲于奔命**，而不同任务的"性价比最优模型"又各不相同（简单改写不值得用最贵的，复杂推理用便宜模型会翻车）。
- 三个真实痛点：①**成本与质量的错配**——绝大多数请求用"杀鸡牛刀"或"小马拉大车"；②**可用性与稳定性**——单一 provider 限流/宕机就把整条业务打断；③**本地 vs 云端的决策**——结合 AirLLM/BitNet 的能力，很多请求本可端侧零成本完成（隐私也更好），却被无脑发往云端。
- 现有做法：硬编码单一模型、粗暴重试、人工切换——**没有"按任务、按成本、按隐私、按可用性"的策略化路由**。

**具体场景**：
一家做垂直 SaaS 的团队，产品里嵌了 AI 能力，每月 API 账单高企且波动大，还偶发因某 provider 限流导致大面积失败。**若接入一个"推理路由器"：按请求复杂度自动分流（简单请求走端侧小模型/廉价模型、复杂请求走旗舰模型）、按隐私级别决定是否出域、按实时健康度做多 provider 容灾、并给出统一的成本与质量看板**，同样的产品可显著降本、提升可用性、并对合规友好。真正需要的产品是：**一个对应用透明的"智能推理网关"**，把"用哪个模型、在哪跑、花多少钱"从人工决策变成策略化自动执行。

**市场机会**：
- 目标客户：嵌入 AI 的 SaaS/应用团队、成本敏感的中小开发者、对数据出域敏感的行业（金融、医疗、政务）
- 付费意愿：按调用量抽成或订阅 $99-999/月，客户省下的钱直接构成付费理由（成本可证明的 ROI）
- 竞品空白：现有网关多只做"多 provider 代理"，**结合端侧推理 + 隐私分级 + 成本最优路由的一体化方案几乎空白**
- 时机判断：AirLLM/BitNet 让端侧可选，多 provider 竞争让价格差拉大，**"路由"正从工程技巧变成明确的可收费能力**

## 🚀 新产品创意

### 创意 1：**GeoScope（空间情报合规工作台）——把"开源卫星数据"变成业务可交付的结论**

**产品定位**：
面向金融/保险/供应链/政府团队的空间情报 AI 工作台。核心理念：**用户定义"看哪里、看什么变化"，系统交付"带来源与置信度的可复现结论"，而不是一堆影像和图层**。一句话——把 `gods-eye-view` 的"炫技"升级为"能进业务决策、可审计、可复现"的生产工具。

**核心功能**：
1. **任务化监控**：自然语言定义监控区域与关注事件（如"长三角主要港口的集装箱堆场周环比变化"），系统自动解析为地理边界 + 影像需求 + 分析算子
2. **多源数据接入与对齐**：接入 Sentinel/Landsat/开源高分辨率影像与遥感指数，自动做时间对齐、云量剔除、几何校正
3. **变化检测 Agent 流水线**：长势指数（NDVI/EVI）、水体/洪涝范围、建筑与施工变化、油罐/储运阴影等多算子，agent 自动选算子、跑分析、生成结论
4. **带溯源的分析简报**：每条结论附带所用影像 ID、时间、算法版本、置信度，支持一键复现
5. **业务推送与合规闸门**：结论推送到 Slack/邮件/API；地理围栏、数据授权、用途审计、敏感区域阻断等合规控制

**技术实现**：
- 数据层：STAC 客户端拉取分析就绪影像（COG），对象存储 + 分块瓦片
- 算法层：PyTorch/ONNX 变化检测模型 + 经典指数算子，DuckDB/PostGIS 做时空查询与索引
- Agent 层：任务编排 + 算子选择 + 结论生成（LLM 负责"翻译成人话"与简报），全链路留痕
- 前端：3D 地球（Cesium/MapLibre）+ 时间轴对比 + 结论卡片

**MVP 范围**（6-8 周）：
- 只做 1 个垂直场景（建议：农业/大宗商品的作物长势与灾害追踪，或港口库存的储运变化）
- 支持 3-5 类分析算子 + 定时任务 + 邮件/Slack 简报
- 先接 Sentinel 免费数据；合规部分只做账号级用途声明与日志
- 输出"周报 + 事件告警"两种形态验证付费意愿

**定价策略**：
- **Starter** $499/月：3 个监控区域、每周一次分析、邮件简报
- **Growth** $2,500/月：20 个区域、每日分析、实时告警、API 接入
- **Enterprise** $50k+/年：无限区域、定制算子、私有部署、合规审计报告、SLA
- 增值：定制算法开发、历史回算（backfill）、专家解读服务按次计费

### 创意 2：**ContextGuard（Agent 上下文治理与记忆层）——把 98% 的垃圾 token 挡在模型之外**

**产品定位**：
面向所有自建 agent 团队的"上下文防火墙 + 持久记忆 + 多平台路由"基础设施。核心承诺：**在不牺牲 agent 成功率的前提下，把 token 成本与延迟大幅压缩，并让 agent 拥有跨会话的可靠记忆**。它是 agent 运行时旁边的一层，而非替代 agent。

**核心功能**：
1. **工具输出沙箱**：拦截 bash/日志/HTML/文件读取等大体积工具输出，自动结构化压缩（保留摘要、错误、关键片段），目标降幅 90%+
2. **持久会话记忆**：把会话状态、已完成步骤、关键约束落到可检索存储（向量 + 结构化），断线/长任务可续接
3. **智能路由**：按任务类型、上下文长度、成本预算自动选择模型（端侧小模型 / 廉价云模型 / 旗舰模型）与 harness
4. **可观测看板**：每笔请求的 token 花在哪、省了多少、成功率如何，支持按项目/团队归因
5. **策略与合规**：隐私分级（哪些内容禁止出域）、平台白名单、审计日志

**技术实现**：
- 拦截层：MCP server + hooks 或代理进程，兼容 Claude Code / Codex / OpenCode 等主流 harness
- 压缩层：规则 + 小模型摘要双通道，失败时回退保留原文关键段
- 记忆层：向量库 + KV/关系库混合，支持增量更新与检索召回
- 路由层：策略引擎 + 实时 provider 健康探测 + 成本模型估算
- 可观测：OpenTelemetry 埋点 + 自建看板

**MVP 范围**（4-6 周）：
- 只做 **1 个 harness（如 Claude Code）+ 工具输出沙箱 + 基础记忆**，验证"降本不降成功率"
- 提供 CLI 一键接入 + 本地数据库（不上云）
- 看板先给"节省 token / 成本"单页指标
- 暂不做多 provider 容灾，先证明核心价值
