## 🎯 潜在需求分析

### 需求 1：AI 科研发现的"验证-复现-转化"基础设施

**痛点来源**：
- Opus 5.5 agent 发现室温磁性半导体候选材料（HN 132 points）后，社区第一反应是质疑：计算参数是什么？DFT 泛函选的哪个？别人能复现吗？
- AI for Science 产出正在指数增长（arXiv cs.AI 单日 266 篇新论文），但"AI 声称的发现"与"实验验证的发现"之间缺少标准化的中间层
- 高校/企业实验室有验证能力但缺少筛选入口；AI 团队有发现能力但找不到湿实验合作方

**具体场景**：
某材料实验室博士生看到 AI agent 发现的两种磁性半导体候选材料，想复现计算：论文只给了结论表格，没有完整的计算输入文件、收敛参数和随机种子。他花了两周逆向猜测计算设置，最终算出的性质与声称值偏差 15%——他无法判断是自己设置错了，还是 AI 流水线本身有系统性误差。

**市场机会**：
- 目标客户：材料/化学/生物医药领域使用 AI 的研究团队（全球数万个）、制药与半导体企业的研发部门、科研资助机构（需要评估 AI 产出质量）
- 付费意愿：企业研发 $1,000-10,000/月（验证流水线 + 实验对接）；学术版免费增值；资助机构按报告付费
- 竞品空白：现有平台（Materials Project 等）只做数据存取，不做"AI 发现的可信度评级 + 自动复现 + 湿实验对接"闭环
- 时机判断：AI 发现刚开始涌现，验证标准尚未确立——先建标准者将成为该领域的"信用评级机构"

### 需求 2：Agent 交付物的"验收测试"平台（Agent QA）

**痛点来源**：
- 微软 ThinkingBox 直指核心：agent 自报完成 ≠ 系统状态真实变更；IBM altk-evolve 证明 agent 任务表现波动巨大（同一任务多次运行结果不一致）
- tester-army/e2e 单日 +1,430 stars 反映开发者对 AI 时代测试工具的饥渴
- 企业部署 agent 的最大阻力不是能力，而是"我如何知道它没搞砸"——每次人工抽查成本抵消了自动化收益

**具体场景**：
某电商公司用 agent 自动处理退款工单，agent 汇报"已处理 100% 工单"。一周后财务对账发现 3% 的工单只更新了状态字段、没有实际触发退款 API。团队想加验证，但为每个业务动作写断言脚本的成本比雇人工抽查还高。

**市场机会**：
- 目标客户：部署生产级 agent 的企业（客服、运维、财务、代码 agent），保守估计全球 10 万+ 团队
- 付费意愿：$200-2,000/月/团队（按验证的 agent 会话量计费）；企业版含合规审计报告
- 竞品空白：LangSmith/Braintrust 侧重 trace 观测和评测集，不做"运行时验收断言"；e2e 测试框架测的是应用不是 agent
- 时机判断：验证主题在 HF Blog 密集出现说明行业共识正在形成，但产品化窗口刚刚打开，12-18 个月内会有整合

## 🚀 新产品创意

### 创意 1：VerifyLoop —— Agent 交付验收平台（"给 Agent 请一个质检员"）

**产品定位**：
面向生产环境 agent 的运行时验收测试平台。一句话定位："LangSmith 告诉你 agent 做了什么，VerifyLoop 告诉你它有没有真的做到。"核心差异化：不依赖 agent 自报状态，而是直接断言业务系统的真实状态变更（数据库行、API 副作用、文件、邮件、工单状态），并输出带证据链的验收报告。

**核心功能**：
1. **声明式验收规则**：用 YAML/自然语言定义"完成"的机器可验证标准（如"退款工单 closed ⇒ payments 表存在对应 refund 记录且 created_at 在会话时间窗内"）
2. **影子验证器（Shadow Verifier）**：独立小模型 + 确定性查询双通道核对 agent 声明与系统状态，冲突时自动拦截并升级人工
3. **回放测试集**：把生产会话自动转成回归测试用例，agent 换模型/改 prompt 后一键回放，输出一致性分数（呼应 IBM altk-evolve 的 k-consistency 思路）
4. **证据链审计**：每次验收生成不可篡改的证据快照（查询语句、返回行、时间戳），满足 SOC2/金融合规
5. **来源感知校验**：对 agent 引用外部信息的场景，验证"事实正确 + 来源正确"双维度（借鉴 MultiverseComputing 思路）

**技术实现**：
- 接入层：MCP server + OpenTelemetry 钩子，兼容 Claude Code / LangGraph / CrewAI / 自研 agent 框架
- 验证引擎：SQL/API 断言器（确定性）+ 小模型裁判（模糊语义），二者投票仲裁
- 规则生成：从历史会话轨迹自动挖掘"agent 声称 → 系统变更"的映射，用 LLM 起草验收规则，人工确认后固化
- 存储：证据链写入追加式日志（类 Merkle 结构），支持第三方审计验证

**MVP 范围**（6-8 周）：
- 只做数据库断言 + REST API 副作用验证两类
- 支持 LangGraph 和 Claude Code 两种接入
- Web 控制台展示验收通过率、冲突案例、证据详情
- 目标：3-5 家已部署客服/运维 agent 的种子客户，跑通"发现一次真实事故"的价值时刻

**定价策略**：
- 免费层：每月 1,000 次验证，开源核心断言库（社区分发）
- Pro：$299/月/团队，5 万次验证 + 回放测试集
- Business：$1,500/月起，按验证量阶梯 + SSO/审计报告/私有化部署
- 定价锚点：一次未被发现的 agent 事故（错误退款、数据污染）平均损失远超全年订阅费

### 创意 2：DiscoveryDesk —— AI 科研发现的可信度评级与复现平台

**产品定位**：
AI for Science 时代的"发现信用评级机构 + 复现工厂"。为 AI agent/模型产出的科学发现（材料、分子、蛋白质、数学猜想）提供标准化可信度评级、自动复现验证和湿实验对接服务。目标用户是 AI 研究团队（背书自己的发现）、传统实验室（筛选可信发现）、资助机构与药企/材料企业（评估 AI 产出）。

**核心功能**：
1. **发现登记（Discovery Registry）**：AI 团队提交发现声明 + 完整计算流水线（输入、参数、随机种子、代码版本），获得时间戳存证
2. **可信度评级（Trust Score）**：从五个维度自动打分——计算可复现性、方法学严谨性（泛函选择/收敛标准）、与已知数据一致性、不确定性量化、独立性（是否多个流水线交叉验证）
3. **自动复现集群**：一键在独立环境重跑 DFT/MD/对接计算，输出复现报告（复现值 vs 声称值偏差）
4. **实验对接市场**：高评级发现自动匹配有验证能力的实验室/合同研发机构（CRO），平台抽成
5. **领域看板**：如"AI 发现的磁性半导体 Top 榜"，按可信度排序，附复现状态

**技术实现**：
- 复现引擎：容器化的计算化学栈（PySCF/VASP 接口/ASE/RDKit），GPU 集群按需调度
- 评级模型：规则引擎（硬性方法学检查）+ LLM 评审（论文级语义分析）+ 历史复现数据训练的校准模型
- 存证层：发现哈希上链或写入透明日志（类 Certificate Transparency），防"事后修改声明"
- 数据接口：对接 Materials Project / COD / PDB 做已知数据一致性检查

**MVP 范围**（8-10 周）：
- 聚焦计算材料学单一领域（DFT 类发现），其他领域后续扩展
- 实现发现登记 + 自动复现 + 三维评级（可复现性/方法学/一致性）
- 冷启动策略：主动复现近期热点 AI 发现（如磁性半导体候选材料），公开复现报告引流——"我们验证了那个刷屏的 AI 发现"天然具备传播性
- 目标：10 个 AI 材料团队登记发现，完成 5 份公开复现报告

**定价策略**：
- 登记与基础评级：免费（做大 registry 规模，形成标准）
- 完整复现报告：$2,000-8,000/次（按计算量），AI 团队为自己的发现买"信用背书"
- 企业订阅：药企/材料公司 $20K+/年，含发现推送、评级 API、批量复现折扣
- 实验对接：按项目金额 5-10% 抽成
- 长期壁垒：复现历史数据本身就是护城河——评级模型随数据积累越来越准，形成类似信用评分的网络效应

### 创意 3：AgencyKit —— 一人公司的 AI 团队操作系统

**产品定位**：
面向独立开发者、小微创业者和自由职业者的"虚拟公司"订阅服务。灵感直接来自今日 GitHub Trending 的两个信号：`msitarzewski/agency-agents`（预置人格化专家 agent 的完整 AI 代理公司）和 `cloudflare/cloudflare-os`（带公司上下文的 agent 工作空间）。一句话定位："雇不起团队之前，先雇一个 AI 团队。"差异化不在单个 agent 的能力（那是模型厂商的事），而在**角色分工剧本、协作流程和交付物标准**——把"公司"这种人类协作了几百年的组织形态，压缩成可订阅的软件。

**核心功能**：
1. **角色编制库**：预置 12 个经过调优的角色 agent——产品调研、前端工程、文案、SEO、社区运营（Reddit/X/小红书各有人格）、客服、财务对账、法务初审、"创意注入器"、"现实检查员"（专门泼冷水的红队角色）等，每个角色带人格设定、工作流程和交付物模板
2. **项目自动组队**：输入项目目标（如"上线一个 SaaS 落地页并获取前 100 个用户"），系统自动拆解任务、组建对应角色的 agent 编队、分配依赖顺序
3. **公司上下文层**：统一的品牌语料、产品文档、财务数据、历史决策记录，所有角色共享（借鉴 cloudflare-os 的 company context 设计），支持跨会话持久记忆
4. **交付物验收**：内置 VerifyLoop 式验收规则（呼应创意 1）——每个角色的产出必须通过确定性检查才能流转到下一环节
5. **周报与董事会模式**：每周自动生成"公司经营报告"；用户可随时召开"董事会"——所有角色 agent 对同一议题给出各自立场的分析，辅助决策

**技术实现**：
- 编排层：基于 LangGraph/自研 DAG 引擎的角色工作流，支持串并行混合与人工审批节点
