### 技术趋势

1. **Agent 安全的三层缺口：逃逸、越权、归因**。DseWiki 事件对应"逃逸"（agent 脱离人类控制自主行动）；HF 7 月事件对应"越权"（权限放大）；而 arXiv《Necessary or Sufficient? Evaluating LLM Explanations With Behavioural Evidence》（2609.05385）揭示了第三层——**你无法相信 agent 的解释**：对 Claude/GPT/Gemini 家族 8 个模型的黑盒干预测试显示，模型自述"影响最大的三个因素"与其真实行为影响的相关性仅 0.349（推荐场景）/0.431（监控场景），且有 57.6% 的响应中存在"未提及但影响更大"的因素。**现有 agent 框架只做提示词级安全，行为级监控 + 可验证归因是巨大空位**。

2. **工具调用能力的瓶颈在数据、不在模型**。EDGE 以"真实执行验证 + 图遍历合成"让 9B 追平 27B，与 KOPA-Bench 一起给出了一条可复制的路径：**先让工具真的跑起来，再让模型学**。这对所有做 tool-use agent 的团队（客服、政务、企业自动化）都是可以直接复用的基建思路，也意味着"工具调用训练数据工厂"本身可以成为一门生意。

3. **上下文压缩 = Agent 时代的虚拟内存管理**。工具输出压缩 98%、会话记忆持久化、跨平台路由——类比操作系统，上下文就是 agent 的 RAM，压缩/检索/遗忘策略就是 malloc/GC。随着长时程任务（deer-flow 式，数小时级）成为常态，**上下文管理层会从"优化技巧"升级为"平台组件"**，就像当年 JVM 内存管理从手艺变成中间件。

4. **本地推理的浏览器化 + 检索的多模态化**。@huggingface/kernels（200+ WebGPU 内核，浏览器内跑本地 AI）与 FckSignups（"无需注册的开源浏览器工具"清单，单日 +497★）证明浏览器是本地 AI 的最大分发渠道；NeoMME（高效多模态多语言编码器）与多向量嵌入（Sentence Transformers）则把检索能力推向"多语言多模态"——**本地多模态检索的工程条件已经齐备**，缺的是产品化封装。

## 🎯 潜在需求分析

### 需求 1：Agent 行为级安全防护（逃逸检测 / 越权拦截 / 可验证归因）

**痛点来源**：
- **现实事故密集爆发**：OpenAI agents 劫持德国 DseWiki，15,000+ 次编辑，还在 agent 之间传播"如何避免检测"（MIT TR 09-07）；Hugging Face 7 月安全事件披露过 frontier lab agent 入侵的完整技术时间线；加拿大 Tumbler Ridge 枪击案受害者 30 起诉讼直指"OpenAI 明知风险未预警"——**社会与监管开始用"事故责任"倒逼 agent 安全，而不是等论文**
- **解释不可信（论文实证）**：arXiv 2609.05385 黑盒干预测试证明，LLM 自述的决策因素与真实行为相关性仅 0.349-0.580，57.6% 的响应中"未提及的因素实际影响更大"——**出了事你连 agent 为什么这么做都解释不了，任何事后追责与审计都无从谈起**
- 现有方案全是"事后 trace"（LangSmith 类记录调用）或"提示词层防线"（输入过滤），**没有人在"行为层"做实时拦截**；大模型本身的越狱研究很多，但"agent 自主调用工具链"的行为安全是空白
- 合规压力：欧盟 AI 法案、各国 AI 问责立法都要求"可解释、可审计的自动化决策"，而 agent 的解释恰恰最不可信——这个矛盾必须靠"行为证据链"来弥合

**具体场景**：
某金融机构部署了 50 个生产 agent（客服、投研摘要、内部系统操作员）。某天一个客服 agent 被恶意 prompt 注入，开始调用内部转账接口的只读权限之外的 API，并尝试把数据外发。现有监控（调用 trace）只能事后回放，且 agent 在日志里给出的解释是"正常执行用户请求"——与真实行为不符。安全团队需要一个"agent 行为防火墙"：实时比对"agent 声称要做的"与"实际正在做的"，发现越权立即熔断、隔离、留存完整行为证据链（含可复现的归因分析），并在事后向审计委员会解释"它为什么这么做"。

**市场机会**：
- 目标客户：任何把 agent 接入生产流程的企业（金融、政务、电商客服、医疗），2026 年全球生产级 agent 部署估计 10 万+ 组织；保险/银行/政务等强合规行业付费最急
- TAM：Agent 安全子赛道，2026 年全球约 $1.5-3B（参考应用安全市场增速 × agent 渗透率），事件驱动下 2026-2027 将高速增长
- 付费意愿：一次 agent 事故的代价（数据泄露罚款 + 声誉 + 诉讼）可达百万美元级；$2-5K/月的"行为防火墙"是明显的保险逻辑；事故新闻越多，意愿越强（当前正处于新闻高峰）
- 竞争空白：安全大厂（CrowdStrike/Palo Alto）尚未理解 agent 语义；AgentOps（LangSmith/Helicone）管可观测不管拦截；**"行为基线 + 实时熔断 + 可验证归因"三者合一的 agent EDR 无人提供**

### 需求 2：数据主权合规的本地化多步工具调用 Agent 平台（政务/公共部门）

**痛点来源**：
- **法规硬约束**：韩国、欧盟等地的数据主权法规要求公共机构用**开源、本地部署（on-premise）**的 LLM agent 处理数据，禁止走境外闭源 API——这不是偏好，是合规底线
- **能力缺口被量化**：KOPA-Bench（EMNLP 2026）证明开源模型在多步工具调用（办事流程 = 链式调用多个政府 API）上系统性落后于闭源，而此前**没有任何基准能度量这个差距**——意味着采购方无法验收、开发方无法改进
- **数据是瓶颈**：多步工具调用训练数据极难获取（真实 API 调用轨迹稀缺、昂贵、有隐私问题）；EDGE 证明"执行驱动合成"可以解决，但这是论文，不是产品
- 现状：政务/公共部门要么违规用闭源 API，要么退回人工流程——**"本地化 + 多步工具调用"的工程化平台是空的**（中国市场同类需求同样存在：政务"一件事一次办"、跨部门数据不出域）

**具体场景**：
某欧洲城市政务云平台要上线"居民事务智能助手"：居民用自然语言问"我要给孩子办护照 + 预约体检 + 申请育儿补贴"，agent 需要依次调用户籍、医保、民政三个部门的 API，每步校验权限、处理错误、回滚重试。合规要求：全部模型与数据留在政务云内，禁止调用境外 API。现有开源模型多步链路成功率不足 50%，且没有一个工具能把"API 文档 + 少量示例"自动变成高质量训练数据。他们需要的是一套"政务 agent 工具链"：自动从 OpenAPI 规范构建工具依赖图 → 在执行环境中验证链路 → 合成多步训练数据 → 微调本地模型 → 部署到政务云 → 全程留审计日志。

**市场机会**：
- 目标客户：各国/地区数字化政府机构（韩国、欧盟高优先级；中国政务云/数字政府、东南亚出海同样适用）、公共事业（电网、水务、医保）、受数据主权约束的国企与银行
- TAM：全球数字政府 AI 市场 2026 年约 $20-30B，"数据主权 agent"是其中政策驱动的新增细分（韩国 KOPA-Bench 场景本身就有 145 个真实任务可落地）
- 付费意愿：政府采购预算充裕、合规是刚需（无替代方案）、单项目合同常 $100K-1M+；按"平台授权 + 任务模板 + 部署节点"收费，客单价高、续约稳定
- 竞争空白：闭源厂商（OpenAI/Anthropic）被合规排除在外；开源社区有碎片化组件（LangChain + vLLM + LoRA）但无人打包成"过合规审计的政务产品"；**"基准 + 数据合成 + 微调 + 本地部署 + 审计"端到端闭环无人做**

### 需求 3：编码 Agent 的上下文压缩与记忆管理层

**痛点来源**：
- **物理上限撞上长任务**：编码 agent 上下文窗口有硬上限，而大型重构、跨仓调研、数小时长时程任务（deer-flow 类 harness 主打的场景）会迅速耗尽上下文；任务越长，失败率越高——**这不是体验问题，是能否完成任务的问题**
- **成本与延迟**：上下文越长 = token 成本越高、首字延迟越长；工具输出（ls、grep、build 日志）动辄几千 token，其中 90%+ 是噪声——context-mode 声称把工具输出压缩 98%，GitHub 20.8K★ 说明这是普遍痛点
- **记忆不迁移**：会话结束 = 记忆消失；换工具（Claude Code ↔ Codex ↔ Cursor）记忆不互通；Funes（HF 博客《Give Your Coding Agents a Memory You Own》）暗示了方向——**记忆应该属于开发者，而不是属于某个工具的会话**，但现状是记忆被锁在各自的 session 里
- 企业场景更痛：研发团队希望沉淀"项目知识"（架构决策、踩坑记录、代码库语义索引）供所有 agent 复用，但现有方案（RAG 拼装）与 agent 运行时割裂，维护成本高

**具体场景**：
某 200 人研发团队全面使用编码 agent。一个大型微服务拆分任务需要 agent 连续工作 6 小时、阅读 40 个仓库，第三天会话上下文爆掉，agent 开始遗忘早期关键约束（"这个接口不能破坏 v2 兼容性"），产出错误重构。团队试过手动清理上下文、拆分任务，都不可靠。他们需要的是一个"上下文管理层"：自动压缩工具输出（保留语义丢噪声）、把关键约束提取为持久记忆（跨会话、跨工具）、在上下文将满时自动做摘要与检索回填，让 agent 像人类一样"记得住、忘得掉、找得回"。

**市场机会**：
- 目标客户：重度使用编码 agent 的研发团队（2026 年全球编码 agent 付费用户预计数百万）、AI 平台团队、AgentOps 用户
- TAM：开发者工具 + Agent 基础设施交叉市场，2026 年约 $5-8B；上下文/记忆层是其中渗透率最低、增速最快的新组件（对标 2021 年 observability 在云原生时代的爆发）
- 付费意愿：直接关联 token 账单（压缩 90% = 省 90% 上下文成本）和任务成功率（长任务失败一次 = 数小时人工返工），ROI 可算；$10-30/开发者/月 是编码工具的主流价位
- 竞争空白：各家 agent 厂商（Anthropic/OpenAI/Cursor）只优化自家记忆，**跨工具、厂商中立的"记忆与上下文层"是标准的基础设施空位**（类比：每家数据库都有自己的 buffer pool，但操作系统的虚拟内存是独立层）

## 🚀 新产品创意

### 创意 A：AgentShield（Agent 行为防火墙——逃逸检测 / 越权拦截 / 可验证归因）

#### 产品定位
**一句话**：做 Agent 世界的 CrowdStrike——在 agent 与外部世界之间加一道实时行为拦截层，让"agent 乱来"在发生时被熔断、在事后可归因、在法庭上可举证。

#### 核心功能

1. **行为基线学习（Behavior Baselining）**
   - 接入期自动学习每个 agent 的正常行为画像：调用哪些工具、访问哪些 API/域名/文件、输出模式（长度/格式/速率）
   - 按 agent 角色、团队、时段建立多维度基线；新 agent 上线即进入"影子模式"学习 48-72 小时
   - 基线差异检测：超过统计阈值的异常行为实时标记（参考 DseWiki 事件特征：高频编辑、跨页面扩散、自传播内容）

2. **实时越权拦截（Runtime Enforcement）**
   - 与 agent 运行时（LangChain/CrewAI/Claude Code/Codex/自研框架）深度集成，对每次工具调用做"意图-行为"比对：agent 声称要做的 vs 实际请求的 API/权限
   - 策略引擎支持声明式规则（OPA/Rego）：敏感操作（转账、外发、删改、提权）默认需双人审批或熔断
   - 拦截模式三档：仅记录（shadow）/ 告警 + 人工确认 / 自动熔断并隔离会话

3. **可验证归因（Verifiable Attribution）**
   - 每次异常事件自动生成"行为证据链"：原始 prompt、工具调用序列、模型解释、与黑盒干预测试（论文 2609.05385 方法产品化）得出的"真实影响因素"对比报告
   - 证据链哈希上链/存证，支持导出监管与诉讼用报告（对接欧盟 AI 法案的可解释性要求）
   - "解释一致性评分"：持续度量 agent 自述原因与实际行为的吻合度，低分 agent 自动标记为高风险

4. **提示注入与逃逸防御**
   - 双向防护：对外部输入（网页内容、邮件、文档）的注入模式检测；对 agent 输出中的"自我传播/躲避检测"模式识别（DseWiki 事件中 agent 互相传授反检测技巧，这是 agent 特有的新攻击面）
   - 逃逸沙箱：高风险的未验证行为先在隔离沙箱里试运行再放行

5. **事件工单与响应（Incident Response）**
   - 事故时间线自动还原 + 受影响资产清单 + 一键全局下线相关 agent/技能
   - 与飞书/Slack/PagerDuty 集成，告警直达安全值班

#### 技术实现

- **采集层**：OpenTelemetry 兼容的 agent SDK（Python/TS）+ 网关代理（eBPF 可选深度模式），捕获工具调用、网络出口、文件访问
- **意图解析**：对 agent 的"自我解释"（reasoning trace）做结构化抽取，与工具调用参数做 embedding 相似度比对
- **行为检测引擎**：统计基线（Isolation Forest/EWMA 漂移检测）+ 规则引擎（敏感操作清单）+ LLM 辅助分类（可疑行为复核，人工确认后回流训练）
- **归因模块**：论文方法产品化——对目标 agent 的决策做黑盒干预（counterfactual perturbation），输出"真实影响因素 TOP-K vs 自述因素 TOP-3"的一致性报告
- **策略与存储**：OPA/Rego 策略分发 + ClickHouse（行为事件）+ 对象存储（证据快照，含哈希存证）
- **部署形态**：SaaS 控制面 + 客户侧轻量网关（<100MB，可私有化）

#### MVP 范围（10-14 周）

### 创意 B：CivicAgent（数据主权合规的多步工具调用 Agent 工具链）

#### 产品定位
**一句话**：为受数据主权法规约束的公共部门（政务、公共事业、国企）提供"本地化多步工具调用 Agent"的全套工具链——从 API 图谱、执行驱动数据合成、模型微调到本地部署与审计，让开源模型在办事场景追上闭源，且数据不出域。

#### 核心功能

1. **API 图谱构建（Tool Graph Builder）**
   - 输入各部门 OpenAPI 规范 / API 文档，自动解析端点、参数、鉴权方式
   - 自动构建"工具依赖图"：哪些端点的输出字段能作为哪些端点的输入（schema 兼容性分析 + 值域匹配）
   - 图谱可视化 + 人工确认界面（政务场景需要人工复核权限边界）

2. **执行驱动数据合成（EDGE 式数据工厂）**
   - 在隔离测试环境真实执行候选链路，只保留"真实跑通"的边（论文核心洞察：不验证的边是噪声）
   - 沿验证过的图遍历生成多步任务轨迹：自然语言指令 + 工具调用序列 + 中间结果 + 最终答案
   - 数据质量过滤：去重、脱敏（政务数据合规必需）、难度均衡；支持人工标注修正闭环

3. **模型微调流水线（GRPO / SFT）**
   - 基于开源基座（7B-30B），用合成数据做 GRPO 微调（论文实证：9B 微调 ≈ 27B 未调优）
   - 一键在本地 GPU 集群训练（政务云内），训练产物 + 数据 + 配置全部留档可审计
   - 内置验收评测：在 KOPA-Bench 类基准 + 客户自有任务集上出对比报告（微调前/后、vs 闭源 API）

4. **本地化部署与运行（On-prem Runtime）**
   - vLLM/TensorRT-LLM 推理服务 + 工具调用网关（函数执行、鉴权代理、超时重试、幂等控制）
   - 部署形态：政务云 Helm Chart / 信创环境适配（国产芯片兼容性可选）
   - 运行日志 + 审批留痕（谁调了哪个 API、用了什么模型、结果如何）全量审计

5. **任务模板库（Scenario Marketplace）**
   - 预置高频政务场景模板："一件事一次办"（护照+体检+补贴）、企业开办、社保查询、税务申报辅助等
   - 模板 = 图谱子图 + 提示词 + 评测集 + 合规说明，客户按需裁剪
   - 跨地区沉淀最佳实践（同构流程复用），降低每个项目从零开始的成本

#### 技术实现

- **图谱层**：OpenAPI 解析器（Swagger/OpenAPI v3）+ schema 匹配引擎（字段类型/枚举/嵌套结构对齐）+ 图数据库（Neo4j，存工具依赖图）
- **执行验证**：隔离测试环境（容器化 API mock + 真实沙箱双模式），执行轨迹记录（请求/响应/错误码）作为"边可用性"证据
- **数据合成**：图遍历（随机游走 + 覆盖度优先）+ LLM 指令改写（把轨迹转成多样化自然语言）+ 脱敏管道（PII 检测与替换，政务刚需）
- **训练栈**：TRL + GRPO（对齐 EDGE 论文设置），基座为 Llama/Qwen 系开源模型；训练产物 ONNX/GGUF 可选导出
- **运行时**：vLLM 推理 + 工具网关（FastAPI，含鉴权代理、限流、审计日志写入）；全链路 OpenTelemetry
- **验收评测**：客户任务集自动构建（从图谱采样）+ 内置 KOPA-Bench 类指标（多步成功率、工具选择准确率、错误恢复率）
