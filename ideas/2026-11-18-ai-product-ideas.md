## 📊 今日核心洞察

### 一句话：模型已经变成零件，值钱的是"这个零件是谁装的、装的什么、装完谁签的字"

今天有四组信号，从四个不同方向指向同一个结论：**AI 的竞争焦点，已经从"模型多强"彻底下沉到"装配层可不可信"。**

**信号一：GitHub 日榜前十，六个在"给 Agent 装能力"或"给人看住 Agent"。**

- `elementalsouls/Claude-BugHunter`——一天 1007 星，一个 Claude Code skill 包：**82 个 skill、15 个斜杠命令、681 条已披露报告的模式库，横跨 24 类漏洞**，还附带企业身份与基础设施攻击矩阵。
- `Tencent/LoopForge`——590 星，"自托管的编码 Agent 交付工作流"，编排 CodeBuddy / Codex / Claude Code，**核心卖点只有四个字：人工审批门（human approval gates）**。
- `backnotprop/plannotator`——691 星，Agent 审阅工作台：批注、决策、计划、把反馈一键送回 Agent。
- `ag-ui-protocol/ag-ui`——1444 星，Agent 与前端的交互协议。
- `google-labs-code/stitch-skills`、`obra/superpowers`、`affaan-m/ECC`（Agent harness 性能优化系统）、`cursor/plugins`、`mvanhorn/last30days-skill`（跨 Reddit/X/YouTube/HN/Polymarket 的研究 skill）。

这张榜单里**没有一个是新模型**。全是中间件。而且注意 `Claude-BugHunter` 的形态：它不是软件，它是**一堆自然语言指令 + 脚本，直接进入你的 Agent 上下文，以你的 Agent 的全部权限运行**。它有 9000+ star、1300+ fork，意味着已经有上千个开发者把它接进了自己的机器。

**信号二：同一篇 arXiv 论文把"名字"这层信任打穿了。**

`When Tool Names Are Not Identities: Measuring Provider Misbinding in MCP-Based AI Agents`——标题就是结论：**在基于 MCP 的 Agent 里，工具名不等于身份**。Agent 靠工具名（`read_file`、`send_email`、`query_db`）决定调谁，但名字可以被另一个 provider 抢占、复刻、劫持。模型看到的是一串字符串，它没有能力验证"这个 `send_email` 是不是我以为的那个 `send_email`"。

配套的还有两篇，几乎是同一件事的三个切面：

- `Safe Resemblance, Silent Propagation: Limits of Text-Similarity Guardrails for AI Agent Safety`——**文本相似度护栏在 Agent 与 Agent 之间传话时失效**。A 说的话看起来无害，B 转述给 C 之后变成有害指令，而相似度检测每一跳都放行。风险不是被拦住的，是被**稀释后静默传播**的。
- `Optimistic Verifiers Get Hacked: Reward Hacking Under an Exact Process Oracle`——乐观的验证器会被反向利用。你越相信"通过了校验就是安全的"，攻击面就越是校验器本身的盲区。

**信号三：连"分数"本身都不能信了。**

`Benchleaking Is Accelerating: Benchmark contamination has worsened sharply in the past month -- from post-training down to pre-training base models`——基准污染在一个月内急剧恶化，**从后训练一路污染到预训练基座**。这句话的含义很直接：你今天看到的榜单排名，可能有一部分是"背题"背出来的。

**信号四：harness 的价值被量化了，而且高得离谱。**

`Harness Leverage Across Model Size: A Ladder of Five Local Agent Harnesses from 0.75B to 4.7B`——同一个模型换一套 harness，能力差异可以跨好几个档位。再叠加 `Latent Lattice Language Models`（把"每层常驻状态"当成新的扩展轴，406M 参数把困惑度从 15.41 降到 13.61）和 `ViRA`（用对比集训练视觉 Agent，逼它**去读证据而不是靠常识猜**，27B 打赢 Claude Haiku 5.5 和 GPT-6-Luna）——**能力正在快速商品化，装配正在快速专业化。**

**把四条拼起来：**

> Agent 生态今天的状态，非常像 2012 年的 npm。
> 包（skill）供给爆炸、安装只需一行、生态极其活跃，
> 但**没有签名、没有权限清单、没有版本锁定、没有 SBOM、没有运行时沙箱**。
> 唯一的区别是：npm 包最多偷你的密钥；skill 包能替你发邮件、改数据库、点"同意"。

这就是今天所有需求的原点。

## 🔍 潜在需求分析

### 需求一：技能（Skill）与 MCP 工具的"身份 + 权限"治理——装得起，但不敢装

**痛点来源**

`Claude-BugHunter` 是今天最好的样本。它一天涨 1007 星，说明需求真实且强烈：安全团队想要一个"什么都能查"的 Agent 助手。但它同时暴露了三个没人解决的问题：

1. **它是 82 个 skill + 15 个斜杠命令 + 脚本的集合**，没有统一权限声明。你无法知道哪个 skill 会执行 `bash`、哪个会读 `~/.ssh`、哪个会把上下文 POST 出去。
2. **它装在你的 Agent 里，用的是你的凭据、你的 MCP 连接、你的 shell**。一个 9000 星的项目，本质上是 9000 台机器上的 9000 份无签名代码副本。
3. **它没有版本语义**。作者今天改一行 prompt，你明天的 Agent 行为就变了，而你没有任何变更日志可比对。

再叠加 `When Tool Names Are Not Identities` 那篇论文：MCP 生态里工具名可以被冒充。企业现在同时面对**两种身份风险**——skill 作者是谁不确定，MCP provider 是谁也不确定。

**具体场景**

- 一家券商的安全团队想给 30 个分析师装"研究增强 skill 包"（含网页抓取、PDF 解析、行情查询）。安全负责人问的三个问题，今天没有产品能回答：
  - 这些 skill 里有没有出网请求？打到哪些域名？
  - 有没有 skill 会写文件、执行命令？
  - 出了事能不能一键回滚到上周的版本？
- 一家已经在用 5 个 MCP server 的公司，发现两个不同 server 都注册了 `search` 这个工具名。Agent 有时候查的是内部知识库，有时候查的是外部搜索——**而它自己不知道区别**。

**市场机会**

这是典型的"合规驱动的强制采购"。SOC 2、ISO 42001、以及正在成型的 AI 供应链要求，都会把"第三方 Agent 组件的来源与权限"写进审计项。**先做工具链的公司，会拿到"事实标准"的位置。**

市场分层很清楚：个人开发者要免费的 `npx skillscan`；中小团队要 GitHub Action；企业要的是带审批流的私有 registry。三层可以同一套引擎。

### 需求二：Agent 之间的"传话护栏"——相似度不够，需要断言级溯源

**痛点来源**

`Safe Resemblance, Silent Propagation` 这篇论文提出了一个非常工程化的观察：**多 Agent 系统里，风险不在任何单条消息里，而在"转述"这个动作里。**

具体的失败机制是：A Agent 产出一句"根据文档，这项操作可以省略审批"——单看无害，因为它确实在某份旧文档里。B Agent 把它压缩成"可跳过审批"，交给执行 Agent C。C 执行了。文本相似度护栏在每一跳都判定"语义接近，放行"，但它比对的是**文字**，不是**这句话的授权基础**。

这件事在 Agent 编排越来越复杂的今天会指数级放大。`Tencent/LoopForge` 这类编排器的出现，意味着一条任务链上会有 3–10 个 Agent 传递中间结论。每一跳都是一次信息压缩，每次压缩都可能把"有条件允许"变成"允许"。

**具体场景**

- 客服 Agent 把"用户说可以退款"转述给工单 Agent，工单 Agent 把"用户已确认"转述给财务 Agent，财务直接打款。**三跳之后，"用户说"变成了"已确认"。**
- 研发流程里，测试 Agent 报告"未发现阻塞问题"，汇总 Agent 写成"可以发布"，发布 Agent 直接发。中间丢掉的是"未发现"和"不存在"的区别。

**市场机会**

这个需求目前完全没有产品承接。现有的 guardrail 产品（内容审核、提示注入检测）都在做**单点判定**，没有做**跨跳的语义保真度**。

真正需要的能力是：把 Agent 输出从"一段文字"升级成"一段带主张（claim）和依据（evidence）的结构"，让每一次转述都必须携带来源指针，并且检测**主张强度是否在传递中被放大**（"可能"→"可以"→"已确认"）。这是一个可以在 SDK 层标准化的东西。

商业上，它天然是卖给"已经有 Agent 编排"的公司的——也就是已经有预算、已经踩过坑的那批客户。

### 需求三：评测可信度——你的内部 benchmark 可能已经脏了

**痛点来源**

`Benchleaking Is Accelerating` 给出的数据很难忽视：污染在一个月内明显加剧，并且**从后训练下沉到了预训练基座**。意思是，即使你自己微调，基座模型也可能已经见过你的测试题。

配套还有两篇：`Optimistic Verifiers Get Hacked`（验证器被反向利用）和 `SciResearch-Eval`（自主实验 Agent 的科学判断力评估）。它们共同说明一个事实：**"跑个分"这件事，正在从"工程惯例"退化为"安慰剂"。**

**具体场景**

- 一家公司花两个月搭了 500 条内部评测集，用来选模型。半年后换模型，分数涨了 12 个点，上线后实际效果变差。原因是这 500 条里有相当一部分已经被新模型在预训练阶段"见过类似题"。
- 一个 Agent 产品团队每次改 prompt 都跑同一套回归集，全部通过。但用户投诉在涨——因为回归集覆盖的是"当年想到的坏情况"，而不是"现在的真实流量"。

**市场机会**

这里的机会不是"再做一个评测平台"（已经很卷），而是做**评测集健康度**这件事：污染检测（n-gram / 嵌入近邻 / 生成式改写探针）、难度衰减曲线、与线上真实流量的分布对齐度、以及"每次模型升级自动重算基线"。

买单的人很明确：所有在做模型选型和 Agent 回归的团队。定价可以按"评测集条数 + 月度复检次数"。

## 🚀 新产品创意

### 创意一：SkillGate —— Agent 技能的"签证与护照"系统

**产品定位**

> 面向企业 Agent 生态的**技能供应链网关**。一句话：给每一个被装进 Agent 的 skill 发一本护照，记录它是谁做的、要什么权限、装进谁的身体、什么时候必须被吊销。

它不训练模型，不写 skill，只做一件事——**在你按下"安装"之前，告诉你这个 skill 会以什么身份、拿到什么钥匙、做哪些事情。**

**核心功能**

1. **静态解剖（Lint + SBOM）**
   - 解析 `SKILL.md` / `plugin.json` / MCP manifest，抽取：调用的工具、声明的文件路径、出网域名、可执行脚本、读取的环境变量。
   - 生成 **Skill-SBOM**：这个 skill 依赖哪些其他 skill、哪些 MCP server、哪些 shell 命令。
   - 输出"权限指纹"——一张固定格式的卡片，可直接贴进 PR。

2. **权限意图推断（不是因为声明了才检查，是因为没声明才危险）**
   - 声明了 `network` 的 skill 很正常；**声称"只读文档"却出现了 `curl` 的 skill**，才是重点。
   - 用轻量 LLM 对 skill 的自然语言指令做意图标注，与静态扫描结果对账。不一致即红灯。

3. **运行时沙箱与熔断**
   - 在容器 / 本地 microVM 里首次运行，记录 syscall 与出网行为，产出"实际行为画像"。
   - 上线后做**行为漂移检测**：上周只读文件的 skill，这周开始写文件了 → 自动降级为只读或直接熔断。

4. **签名与版本锁定**
   - Skill 内容哈希 + 作者密钥签名。锁文件（`skill.lock`）固定版本与哈希，`skillgate install` 校验不通过就拒绝。
   - 与 CI 集成：哈希变化的 skill 必须走一次人工确认，等同于依赖升级审阅。

5. **MCP 身份绑定**
   - 直接对应 `Tool Names Are Not Identities` 那篇论文：在注册表里给每个工具建立 **name → (provider pubkey, endpoint, schema hash)** 的三元绑定，任何一项变动都要求 Agent 侧重新确认，不做静默替换。

**技术实现**

- 解析层：AST + 正则双路（Python / Node / Shell / Markdown 指令块）。
- 判定层：规则库（覆盖常见外传、反连、凭据读取模式）+ 小模型分类器（1–3B 足够，本地跑）。
- 沙箱层：Firecracker / gVisor，采集 eBPF 出网与文件事件。
- 分发层：私有 registry（可自托管），签名用 Sigstore 体系，天然可被审计。
- 集成：CLI、GitHub Action、VS Code 扩展、Claude Code / Cursor / Codex 的 pre-install hook。

**MVP 范围（8–10 周）**

只做三件事，做深：

1. `skillgate scan <path>` → 权限指纹 + 风险分级（红/黄/绿）+ JSON 输出。
2. `skillgate lock` → 生成并校验 `skill.lock`（哈希锁定）。
3. GitHub Action：PR 里出现新 skill 或 skill 哈希变化时，自动贴出差异报告。

先只支持 Claude Code skill 与 MCP server 两种形态——**这两个占据了今天榜单的绝大多数**。不做沙箱（第二阶段），用"静态 + 声明对账"就能拦下 70% 的问题。

**定价策略**

| 层级 | 价格 | 内容 |
|---|---|---|
| Free | ¥0 | 单机 CLI，公有 skill 风险查询（相当于"这个 skill 有没有人报过毒"） |
| Team | ¥299/人/月 | 私有 registry、锁文件、GitHub Action、Slack 告警 |
| Enterprise | ¥15 万/年起 | 自托管、SSO、审批流、审计导出（对接 SOC 2 / ISO 42001）、行为漂移检测 |
| Registry 索引 | 按调用计费 | 给平台方（如 Cursor、Claude Code 生态）提供"安装前风险查询" API |

变现的关键在第三层：**这不是开发者工具生意，是合规生意。** 定价锚点不是"省了多少时间"，而是"审计不过关要损失多少"。

### 创意二：RelayGuard —— Agent 之间的"断言保真"中间件

**产品定位**

> 在多 Agent 协作链路中，保证**结论在传递过程中不被放大**。它不拦"坏内容"，它拦"变强的结论"。

一句话对比现有产品：内容审核看的是"这句话该不该说"，RelayGuard 看的是"这句话还是不是原来那句话"。

**核心功能**

1. **断言结构化（Claim Extraction）**
   - 把 Agent 的自由文本输出解析为 `(主体, 谓词, 强度, 依据指针)` 四元组。
   - 强度分级是关键设计：`疑似 < 可能 < 建议 < 应当 < 已确认 < 已完成`。一条链路的风险，往往就是强度在某次转述里跳了两级。

2. **强度单调性检查（Monotonicity Guard）**
   - 规则极简但极有效：**下游断言的强度，不得高于其依据链上最强的那条。**
   - 转述允许降级、允许同义、允许压缩，**不允许升格**。一旦升格，即刻打回并附上原始依据。

3. **依据指针与可追溯链**
   - 每个 claim 带 provenance：来自哪次工具调用、哪份文档的第几段、哪个用户原话。
   - 链路末端执行危险动作（退款、发布、删库、发邮件）时，反向展开完整依据树。任何一环是"模型推断"而非"外部事实"，标黄。

4. **冲突检测（跨 Agent 一致性）**
   - 同一事实在不同分支得出不同结论时（测试 Agent 说"无阻塞"、监控 Agent 说"错误率上升"），在汇总前强制暴露冲突，而不是让汇总 Agent 自己"综合判断"掉。

5. **审计与回放**
   - 全链路 claim 图落盘，可回放。出事后能回答唯一重要的问题：**"是哪一跳把'可能'变成了'已确认'。"**

**技术实现**

- 抽取层：结构化输出（约束解码 / JSON schema）优于后处理，优先要求 Agent 输出 claim 结构；对不支持的老 Agent 用轻量抽取模型兜底。
- 判定层：**规则为主，模型为辅**。强度比较、指针完整性、冲突检测都是确定性逻辑——这是核心差异点，因为 `Optimistic Verifiers Get Hacked` 已经证明"全靠模型判"会被反向利用。
- 存储：claim 图用轻量图库（SQLite + 邻接表即可撑到千万级）。
- 接入形态：作为 LLM 网关的旁路（proxy 模式），零改造接入；或 SDK（LangGraph / AutoGen / 自研编排器）。

**MVP 范围（10–12 周）**

1. Proxy 模式：拦 OpenAI 兼容请求，做 claim 抽取 + 强度检查，超限则返回结构化拒绝并附依据。
2. 支持单场景：**退款 / 工单升级**这条链路（场景窄、痛感强、可量化）。
3. 一个仪表盘：本周有多少次"结论升格"被拦下，分别发生在哪一跳。

先不做通用编排集成。用一个高频、高损失、结构清晰的场景把"拦得住且不误伤"证明出来，再横向复制到发布审批、合同条款、医疗分诊。

**定价策略**

- 按"受保护决策数"计费，而不是按 token：**¥0.02/次受保护动作**，含依据链留档。
- 起步套餐 ¥3000/月（含 15 万次），企业版按年 + 私有化部署。
- 附加价值包：审计报告导出（给合规/法务），这是真正的溢价点——**它把"AI 做了什么"变成一份可以签字的文件。**

### 创意三：BenchAudit —— 评测集的"体检中心"

**产品定位**

> 不是又一个评测平台，而是**评测集的污染检测与折旧管理**。定位类似"体检"而非"医院"：定期告诉你，你赖以决策的那套题，还剩多少可信度。

**核心功能**

1. **污染检测三件套**
   - n-gram 重叠（快速，覆盖逐字记忆）；
   - 嵌入近邻（覆盖改写记忆）；
   - **生成式探针**：让目标模型在只给题目前半段的条件下续写，若续写与标准答案高度一致，判定为"见过"。这一招对预训练污染尤其有效——正是 `Benchleaking` 指出的新问题。
2. **难度折旧曲线**
   - 每道题记录"历史通过率随模型代际的变化"。长期 100% 通过的题自动标为"已饱和"，建议退役。评测集应该像资产一样折旧，而不是永久有效。
3. **上浮/下沉偏差报告**
   - 对比你的评测集与线上真实流量的分布。评测集里 60% 是代码题、线上 80% 是客服对话——这种错配今天几乎无人测量。
4. **基线重算与版本对比**
   - 模型一升级，自动重跑并给出"净提升 vs 污染带来的虚高"拆解。这是产品最有说服力的一张图。

**技术实现**

- 探针生成用便宜的小模型批量跑，成本可控（一道题 3 次探针 ≈ 几百 token）。
- 嵌入用本地小模型，避免把客户评测集传到第三方——**这是企业客户的第一顾虑，必须在架构上先解决**。
- 输出：健康分 + 逐题标签（干净 / 疑似 / 已污染 / 已饱和）+ 可执行的"退役/替换"清单。

**MVP 范围（6–8 周）**

只做一件事：**上传评测集 + 指定模型 → 输出逐题污染概率与健康分**。不做评测执行、不做排行榜、不做数据标注。一个 CLI + 一份 PDF 报告即可开卖，因为客户要的是"结论"，不是"平台"。

**定价策略**

- 按评测集规模：¥2000 / 1000 题 / 次体检；订阅制 ¥5 万/年含 12 次体检 + 月度自动复检。
- 与模型厂商的合作可能比 to B 更顺：**厂商愿意为"证明自己没背题"付费**——这是一张可以公开引用的事实性凭证。

## 🧭 落地建议：先做哪个

**排序：SkillGate > RelayGuard > BenchAudit。**

理由不是市场大小，而是**交付确定性**：

- **SkillGate 的判定是静态的**。一个 skill 里有没有 `curl`、有没有读 `.ssh`，这是客观事实，不依赖模型判断，误报可以解释清楚。今天榜单已经把这个需求顶到了脸上（1000 星/天），而且客户群（已装 skill 的公司）是现成的。
- **RelayGuard 价值更高但更难**。claim 抽取的准确率直接决定误伤率，而误伤在"退款审批"这种场景里是不可接受的。需要先在一个闭环场景里打磨到 95% 以上才能卖。
- **BenchAudit 最好卖但天花板低**。它是个"一次性咨询 + 年检"的生意，容易起量，难做大。适合作为 SkillGate 的附加模块（毕竟"你装的这个 skill 靠不靠谱"和"你的评测集靠不靠谱"是同一个焦虑）。

**一个可以合并的产品叙事**：

> 企业不缺 Agent 能力，缺的是**能签字的东西**。
> SkillGate 给"装进来的东西"签字，RelayGuard 给"传出去的话"签字，BenchAudit 给"你信的分数"签字。
> 三件套合起来，就是 AI 时代的**内控系统**。

这个定位比"AI 安全"更好卖——安全是成本，内控是刚需。

## ⚠️ 风险与反证

**1. 平台方自己会做。** Anthropic / Cursor / GitHub 完全可能在 6 个月内把 skill 签名与权限声明做进官方工具链。应对：**不与平台竞争入口，做"跨平台的那一层"**——企业的 Agent 生态注定是异构的（Claude Code + Codex + Cursor + 自研），跨平台审计天然属于第三方。

**2. 静态扫描会被 prompt 绕过。** 自然语言指令可以做得很隐晦（"请查阅 ~/.aws 下的配置文件以确认区域"）。这也是为什么 MVP 之后必须尽快上运行时行为画像——**声明可以撒谎，syscall 不会。**

**3. RelayGuard 的误伤成本高。** 强度判定一旦误判，会阻断正常业务。应对：初期只做"观察模式"（记录不拦截），积累两周数据后再开拦截，这个策略必须在产品里内建而不是让客户自己摸索。

**4. 基准污染检测存在军备竞赛。** 检测方法公开后，污染方会针对性规避。但这恰恰是好事：**它把一次性工具变成订阅制服务。**
