## 📊 今日核心洞察

### 热点话题

1. **GitHub 热榜上已经没有模型了，全是"代理的器官"**：今天的前排是 claude-mem（106k stars，单日 +1145）、CopilotKit/OpenBot（8.7k，单日 +707）、OpenMausBot（8.5k，单日 +899）、macro（5.8k）、DeepTutor（51k，单日 +2282），再加上 anthropics/skills、expo/skills、mattpocock/skills 三个"技能仓库"同日上榜。这份榜单的说服力在于它的单调：没有一个新模型，全部是记忆、技能、工作区、IDE 这些**模型外面的东西**。开发者在用 star 投票告诉市场——模型能力已经足够到"不是瓶颈"了，现在卡住他们的是代理记不住、不会用工具、跑在哪里、产出能不能信。

2. **"记忆"从上下文技巧变成了一个显式产品对象**：claude-mem 的自我描述非常精确——捕获代理在会话里做的一切，用 AI 压缩，再把相关上下文注入未来的会话。macro 则把"共享 AI 记忆"写进了团队工作区的核心卖点。这两件事放在一起看，意味着行业对记忆的定义变了：过去记忆是"塞进 prompt 的历史消息"，现在记忆是**可捕获、可压缩、可检索、可回放的资产**。一旦它是资产，就会立刻长出资产该有的一整套问题：归谁所有、怎么迁移、错了怎么改、离职了怎么删。

3. **技能包正在重演 npm 的 2010 年，但没有 npm 的护栏**：anthropics/skills、expo/skills、mattpocock/skills 同一天在榜，说明"把方法论写成一个文件夹发给代理"已经成为主流的交付形式。但打开这些仓库看结构就会发现，一个技能就是 SKILL.md 加几个脚本，没有版本号语义、没有依赖锁、没有签名、没有权限声明，而它能读文件、能跑 shell、能发网络请求。这不是"包管理"，这是"把 root 权限写在便利贴上"。

4. **端侧专用模型给出了成本经济学上的硬答案**：Liquid AI 的 LFM2.5-24B-A2B 主打在设备上跑私有代理，LFM3 主打可定制的专用多模态模型，Dharma AI 的词表特化在真实应用里把推理成本砍掉 77%，Apple 平台这边 AnySpeechRecognizer 与 AnyDecisionModel 直接把语音与决策模型做成了系统级组件。四条消息指向同一个结论：**不是所有任务都值得调用前沿大模型**。一个被裁剪过词表、蒸馏过、量化过、跑在本地 NPU 上的 3B 模型，在窄任务上可以做到前沿模型 90% 的效果、10% 的成本、并且数据不出门。

5. **"像更新软件一样更新模型"已经不是口号，是排期表**：IBM 的 Granite Switch 4.1.1 延续了这个主张，Mistral Large 4 上线，Reflection 的 501B 开放权重模型 Beam 强调"可拥有、可定制、可扩展"。模型供给侧的节奏是周级别的，而企业侧的变更管理还停留在季度评审。这中间的空档，正是上一期日报里"版本台账"需求的现实土壤——今天它变得更紧迫了，因为开源权重模型让"自己部署、自己升级"成了默认选项。

6. **"谁来评价评价者"变成了一个可测量的市场**：AllenAI 的 NoveltyBench 系统检验 LLM 判断研究想法新颖性的可靠性，Hugging Face 的 Project ProtoStar 则要把公共资金资助的科研成果做成"AI-ready"。上游要让数据可被机器消费，下游要让人相信机器的判断。这两端都还处于"有共识、没产品"的阶段。

### 技术趋势

1. **代理运行时正在分层，但只有前两层有人做**：模型层（推理）、运行时层（记忆、工具、沙箱、权限）、资产层（技能、prompt、评测集）、治理层（审计、合规、成本归因）。今天热榜上所有项目都挤在运行时层，资产层和治理层几乎空白。而企业采购时真正签合同的是后两层——"你能证明它不会乱来吗"。

2. **记忆的技术路线已经收敛，工程难点转移了**：捕获（hook/中间件）→ 压缩（小模型摘要）→ 存储（结构化+向量）→ 注入（相关性检索）。前四步都有成熟做法，真正难的是第五步——**冲突消解**。用户上周说喜欢简洁回答，这周说希望详细展开，哪条算数？两条都存着，注入时怎么选？目前的项目大多选择"都存，靠检索排序"，这在 demo 里没问题，在生产里会变成"AI 记性很好但记的是错的"。

3. **技能工程化的缺口是结构性的**：技能不是纯文本 prompt，它携带可执行代码，因此它的风险等级接近"供应商提供的脚本"。但它的分发方式还是 git clone。可预见的标准件是：技能清单规范（类似 package.json）、权限声明（读哪些目录、能不能联网）、签名与来源验证、以及一个能扫出危险模式的静态分析器。

4. **端侧可行性的拐点由三件事共同促成**：MoE 稀疏激活让 24B 模型只激活 2B 参数、词表裁剪直接砍掉输出层的计算量、平台原生推理栈（Apple ANE、ONNX Runtime、llama.cpp）把部署门槛降到"一个二进制"。三者叠加，让"本地跑一个够用的专用模型"从极客玩具变成工程选项。

5. **教育 agent 从"问答"走向"长期陪伴"，但学习数据同样无处安放**：DeepTutor 的定位是"终身个性化辅导"，51k stars 说明这个方向有真实渴望。但它的核心资产不是模型，是"这个学生学过什么、错在哪里、下一步该学什么"——这又是一份记忆，而且是最敏感的那一类（未成年人、学习能力评估）。这个赛道会长出跟通用记忆层同构、但合规要求高一个量级的产品。

## 🎯 潜在需求分析

### 需求 1：AI 记忆的"户口"——跨工具的所有权、迁移与纠错

**痛点来源**
- 一个重度使用 AI 的工程师，工作流里通常同时存在 Claude Code、OpenClaw、Codex、Cursor 三到四个代理。每个代理都有自己的记忆机制（或者没有），换一个工具就等于重新自我介绍一遍：项目背景、代码规范、上次为什么否掉那个方案，全部清零。
- 更麻烦的是记忆的**错误不可撤回**。代理把一次误判写进记忆（"用户偏好用 tabs"），之后每一次注入都会强化这个错误，用户甚至不知道自己被"记错"了。目前没有任何工具提供"查看我的 AI 记得什么、改掉某一条"的界面。
- 企业侧的合规压力是硬的：员工离职要求删除个人数据，但数据散落在四个 SaaS 工具的向量库里，没人能给出完整清单。GDPR 的"被遗忘权"在 AI 记忆这个场景里目前是失效的。
- claude-mem 单日破千星，恰恰说明大家在用"再加一个工具"的方式解决"工具太多"的问题——这是典型的止痛药，不是解药。

**具体场景**
一家 30 人的创业公司，工程师用 Claude Code 写后端、用 Cursor 改前端、用 OpenClaw 跑自动化。某天一个核心工程师离职，交接文档写了三页，但真正有价值的东西——"为什么支付模块不能用乐观锁""客户 A 的环境有个坑"——全部沉淀在他个人账号下的三个 AI 工具记忆里，公司拿不到，新人也问不出来。

与此同时，公司要过一次 ISO 审计，审计员问："你们员工在 AI 工具里输入的客户数据，怎么保证离职后可删除？" CTO 答不上来。

**市场机会**
- 目标客户分两层：个人开发者（付费意愿靠"换工具不失忆"驱动）、中小企业（付费意愿靠合规与知识资产留存驱动）。
- 定价可以参考密码管理器的发展路径：个人 20-30 元/月，团队 40-80 元/人/月，企业私有部署年费 10 万起。密码管理器证明了"管理一类敏感资产"可以撑起一家十亿美元公司，记忆的敏感度和价值都不低于密码。
- 竞争空白在于**中立性**。Anthropic 做记忆，只会服务 Claude；Cursor 做记忆，只会服务 Cursor。跨工具的记忆层天然只能由第三方做，而且越晚做越难——因为先发者掌握格式。
- 护城河是"记忆图谱的结构化程度"。如果只是存原始对话，迁移价值低；如果能把记忆抽象成"人物、项目、偏好、决策、约束"五类实体并带来源，那它就从日志变成了知识资产，替换成本极高。

### 需求 2：Agent 技能包的供应链治理——从"能装"到"敢装"

**痛点来源**
- 技能包的实际权限远超它的外观。一个 SKILL.md 看起来像文档，但配套脚本通常拥有当前用户的完整文件系统权限和网络权限。装一个"帮你整理周报"的技能，等于给了一个陌生人的脚本 shell。
- 没有版本语义。技能更新是 git pull，行为变化没有任何 changelog。团队里 20 个人各装各的，同一个技能在不同机器上跑的是不同版本，出了问题无法复现。
- 企业安全团队现在被问的问题非常具体："这个 agent 能访问哪些目录？会不会把代码发到外部？" 目前唯一的答案是"我去看看代码"，而这句话在 50 个技能面前等于放弃。
- 今天三个技能仓库同时上热榜，说明技能的数量即将进入爆发期。npm 生态在 2016 年经历过的 left-pad 与恶意包事件，会在技能生态里以更高风险重演——因为技能能直接执行命令。

**具体场景**
一家金融科技公司的平台团队给内部 agent 装了 18 个技能：查数据库、发飞书、跑测试、读设计稿、生成周报。某个周五，一个上游技能仓库更新了实现，把"读取环境变量"改成了"读取并上报环境变量用于改进"。周一早上，agent 在处理生产工单时把数据库连接串带进了日志。事后复盘，没有任何一条记录能回答："这个技能是什么时候更新的？谁批准过？它声明了哪些权限？"

**市场机会**
- 这个市场的形状高度确定，可以直接对标 npm + Snyk 的组合：注册中心负责分发与版本，扫描器负责准入，运行时网关负责拦截。
- 切入顺序很重要：先做免费的 CLI 扫描器建立标准话语权（"你的技能有 3 个高危权限"），再用扫描报告做内容获客，最后卖企业策略引擎。开发者工具的标准打法。
- 定价：开源 CLI 免费；团队版 99 元/人/月；企业版含运行时网关与审计，年费 8-15 万。参考 Snyk 的 ARR 结构，安全类工具的客单价与续费率都显著高于生产力工具。
- 空白点在于"技能"这个形态本身还很新，现有 SAST 工具不认识它。谁先定义"技能权限清单"这个规范，谁就拿到了事实标准。

### 需求 3：小模型落地的"最后一公里"——77% 的成本节省没人帮你兑现

**痛点来源**
- 论文里的 77% 是端到端优化后的结果：词表裁剪、蒸馏、量化、批处理、缓存、路由，每一步都要针对具体任务调。企业自己动手，通常只做到"换个更小的模型"，然后发现效果掉了 30%，项目搁浅。
- 端侧部署的碎片化被严重低估：同一份模型要跑在 x86 服务器、Apple Silicon、高通 NPU、国产加速卡上，每一条路径的算子支持、量化格式、内存布局都不一样。这不是算法问题，是工程问题，而工程问题最耗人。
- 采购侧的心理也变了。2024 年企业问"你们用哪个模型"，2026 年问"每个工单的推理成本是多少"。当 CFO 开始看单位成本，pure API 调用就成了被审计的对象。
- 隐私合规是另一条硬约束：医疗、金融、政务的很多场景根本不允许数据出内网，这不是成本问题，是准入问题。

**具体场景**
一家区域银行想把客服工单的"意图分类 + 敏感信息识别"从云端 API 迁到本地。预算 20 万，要求准确率不低于现有水平、延迟低于 300ms、数据不出机房。他们找了两个外包团队，一个交付了 Llama 的量化版本但准确率掉了 12%，另一个把模型跑起来了但没有评测体系，无法证明"没变差"。项目拖了五个月。

真正需要的不是"一个模型"，而是一条**可复现的产线**：用他们的历史工单做 baseline，裁剪词表，蒸馏一个小模型，量化到目标硬件，跑一套固定的回归评测，出对比报告，然后灰度。这条产线跑一次两到四周，之后换任务可以复用。

**市场机会**
- 商业模式是"诊断 + 交付 + 维保"：诊断 2 万（出 baseline 和优化预估），交付 15-40 万，年度维保 20%。单客价值高，但项目制不可规模化，必须靠模板收敛。
- 垂直模板是关键：客服意图、合同要素抽取、ASR 后处理、发票识别、设备日志异常检测，每个模板沉淀一套数据流程、评测集和部署脚本。做到第三个客户时，交付周期应该从四周压到一周。
- 长期看，这条产线会产品化成"模型运维平台"（类似 CI/CD for small models），但第一阶段必须是服务，因为客户连"要优化什么指标"都说不清。
- 竞争格局：大厂云厂商愿意做但客单价太高（50 万起），小外包能做但没评测体系。中间这层"20-50 万、有方法论、能出报告"的位置是空的。

## 🚀 新产品创意

### 创意 1：MemPort · 记忆护照 —— 不属于任何工具的 AI 记忆层

**产品定位**
把 AI 记忆做成一份"跟着人走、跟着团队走"的资产，而不是某个工具的附属品。一句话：**你的代理可以换，你的记忆不用重来。**

**核心功能**
1. **统一捕获**：通过 MCP server 与各客户端插件接入，把对话中值得留存的信息落库。不做全量录音（成本高且噪音大），而是由代理在关键时刻调用 remember 写入，辅以定时摘要任务补漏。
2. **结构化记忆图谱**：五类实体——人物（同事、客户）、项目（背景、约束、决策）、偏好（沟通风格、技术选型）、事实（环境、密码位置除外）、教训（踩过的坑）；每条记录带来源（哪次会话、哪个工具）、时间戳、置信度。
3. **相关性注入**：暴露 retrieve 接口，按当前任务语义检索，返回带来源的 3-8 条记忆；支持"只在相关时注入"，避免污染上下文。
4. **纠错与遗忘**：CLI/Web 界面列出所有记忆，可编辑、可标记"错误"、可设 TTL；错误记忆不删除而是降权并记录"被推翻"，保留审计痕迹。
5. **跨工具同步**：本地优先存储，可选端到端加密同步；Claude Code、OpenClaw、Cursor、Codex 共用同一份记忆。
6. **合规导出与删除**：一键导出 markdown/JSON；按人、按项目、按时间范围物理删除，并生成删除报告供审计。

**技术实现**
- 存储：本地 SQLite + FTS5 全文索引 + 向量索引（sqlite-vec 或 LanceDB 本地模式），单机可承载十万级记忆条目。
- 冲突消解：来源可信度（用户显式告知 > 代理推断） × 时间衰减（半年半衰期）× 使用反馈（被采纳加分）。冲突时保留双方，注入时标注"存在分歧"。
- 压缩：用小模型（本地 3B 或便宜 API）做会话摘要，控制在 token 预算内。
- 接口：MCP 协议暴露 remember / retrieve / forget / list 四个工具，天然兼容所有支持 MCP 的客户端。

**MVP 范围（6-8 周）**
- 一个 MCP server（Python 或 TypeScript），支持 remember/retrieve/forget。
- 两个客户端适配：Claude Code（hooks）、OpenClaw（skill）。
- 一个 CLI：`memport list` / `memport edit` / `memport export`。
- 不做云同步、不做 Web UI、不做团队权限。先验证"个人换工具不失忆"这一个价值点。

**定价策略**
- Free：本地存储，上限 5,000 条记忆，单设备。
- Pro：29 元/月，无限条数 + 加密云同步 + 多设备。
- Team：39 元/人/月，共享项目记忆空间 + 基础权限（谁能看哪个项目）。
- Enterprise：私有部署，年费 10 万起，含审计日志、合规删除报告、SSO。
- 转化设计：免费版在"第 5,000 条"处提示，而不是功能阉割——记忆类产品的付费触发点应该是"舍不得删"。

**风险与对策**
- 平台方自建记忆（Anthropic、OpenAI 都有动机）：对策是把"中立 + 可迁移"做成明牌，并尽早支持最多客户端。平台做记忆是加深锁定，第三方做记忆是解除锁定，这是立场差异，不是功能差异。
- 记忆质量差导致用户不信任：MVP 必须提供"为什么注入这条"的可解释视图，宁可少注入也不要错注入。

### 创意 2：SkillGuard · 技能供应链的 npm + Snyk

**产品定位**
给 agent 技能包做注册、扫描、准入、拦截。一句话：**让"装一个技能"变成一次可审计的依赖引入，而不是一次赌博。**

**核心功能**
1. **技能清单解析**：读取 SKILL.md 与目录结构，提取元信息——技能名、用途、依赖的 CLI、需要的环境变量、会访问的路径、是否会发起网络请求。
2. **静态扫描**：规则库覆盖危险命令（rm -rf、curl | sh）、凭证读取（.env、~/.ssh、keychain）、数据外发（把文件内容 POST 到外部）、prompt 注入模式（"忽略之前的指令"类文本藏在文档里）。规则 + LLM 双通道，规则保精度，LLM 补语义。
3. **版本与签名**：为技能生成内容哈希作为版本标识，支持 lockfile 固定；发布者可用密钥签名，安装时校验来源。
4. **企业策略**：白名单（只允许内部仓库 + 三个可信来源）、权限上限（技能不得访问 ~/.ssh）、按团队下发策略。
5. **运行时网关**：代理的每次工具调用经过 sidecar，按策略判定 allow/deny/ask；高危动作（写生产库、发外部请求）强制人工确认。
6. **变更告警**：技能内容哈希变化时推送 diff 与风险评级，接入飞书/Slack。

**技术实现**
- 扫描器：Tree-sitter 做 AST 解析（覆盖 Python/JS/Shell），规则用 YAML 描述，便于社区贡献；LLM 通道只用于"这段代码的意图是否与声明一致"这类语义判断。
- 策略引擎：OPA/Rego，策略即代码，企业可自定义。
- 网关：本地 HTTP 代理 + 工具调用拦截，兼容 MCP 的 tools/call 生命周期。
- 注册中心：初期不必自建，先用 GitHub 仓库 + 索引服务，降低冷启动成本。

**MVP 范围（8 周）**
- CLI：`skillguard scan ./skills` 输出风险报告（终端 + HTML）。
- 支持 Claude Skills 与 OpenClaw skills 两种目录格式。
- GitHub Action：PR 中自动扫描并评论。
- 一份公开报告：《Top 500 公开 agent 技能权限分析》，作为获客内容。
- 不做运行时网关（第二阶段）。

**定价策略**
- CLI 与公开规则库：开源免费（Apache 2.0），换社区与标准话语权。
- Team：99 元/人/月，私有规则、策略下发、变更告警。
- Enterprise：年费 8 万起，含运行时网关、审计日志、私有部署、合规报告。
- 增值：按次的安全评估服务（单个技能 2,000 元），给要上架的技能作者做"安全认证"标记。

**风险与对策**
- 误报率高会毁掉信任：MVP 只报"确定危险"和"需要人工确认"两档，不搞风险评分百分制。
- 技能生态早期量小：先用扫描器切入"企业内网技能治理"（企业自己写的技能也需要管），不依赖公网生态规模。

### 创意 3：TinyStack · 专用小模型的落地产线

**产品定位**
把"77% 成本优化"从论文数字变成一条可复现的交付流水线。一句话：**不卖模型，卖"在你这台机器上、用你的数据、达到你要求的准确率"这件事。**

**核心功能**
1. **Baseline 诊断**：用客户历史数据跑现有方案（云端 API 或大模型），输出准确率、延迟、单次成本、失败样本聚类。这是所有后续优化的锚点，也是销售材料。
2. **数据流水线**：从工单/日志/文档中抽取训练与评测样本，自动去重、脱敏、分层；生成固定评测集（这一项是交付质量的命门）。
3. **模型优化**：词表裁剪（针对领域高频词重建 tokenizer）、蒸馏（用大模型产软标签）、LoRA 微调、量化（INT8/INT4，按目标硬件选格式）。
4. **硬件适配**：x86（ONNX Runtime / llama.cpp）、Apple Silicon（Core ML / ANE）、国产加速卡（按客户环境定制）。
5. **回归评测与报告**：每次优化自动跑评测集，出"准确率 / P95 延迟 / 单次成本 / 内存占用"四维对比报告，达不到门槛不允许上线。
6. **灰度与回滚**：按流量比例切流，异常自动回退到原方案。

**技术实现**
- 工具链封装开源组件：vLLM（服务）、llama.cpp（端侧）、Optimum/ONNX Runtime（图优化）、PEFT（微调）、GPTQ/AWQ（量化）。
- 核心自研部分是"评测与报告"层——把散落的脚本收敛成一个声明式配置文件（任务、数据、指标、硬件、门槛），一条命令跑完。
- 模板化：每个垂直场景一套预设配置（客服意图、合同抽取、ASR 后处理、发票识别、日志异常），新客户改数据路径即可。

**MVP 范围（10-12 周）**
- 只做一个场景：中文客服工单的意图分类 + 敏感信息识别。
- 一条 CLI：`tinystack run config.yaml`，跑完输出报告与可部署产物。
- 两家种子客户（一家 SaaS、一家区域金融机构），用真实数据验证"准确率不降、成本降 60% 以上"。
- 不做 Web 平台、不做多租户。

**定价策略**
- 诊断包：2 万元，2 周，交付 baseline 报告 + 优化可行性评估（可抵扣后续交付款）。
- 交付包：15-40 万元，按场景复杂度与硬件适配难度定价，含 3 个月维保。
- 年度维保：合同额 20%，含模型更新、评测集扩充、季度健康报告。
- 平台订阅（第二年）：年费 30 万起，客户自己在平台上跑优化任务，适合有多场景需求的中大型客户。

**风险与对策**
- 项目制不可规模化：用"模板收敛"对抗——每多一个客户，模板复用率必须上升，交付人天必须下降；到第三个客户还压不下来，说明场景选错了。
- 大厂降价挤压：不打价格战，打"可验证"——客户最怕的不是贵，是"你说优化了但我没法证明"。评测报告就是护城河。
- 硬件碎片化拖死交付：MVP 阶段只承诺 x86 与 Apple Silicon 两条路径，其他硬件一律走合作方。

## 💰 商业化与落地建议

### 三条路线的比较

| 维度 | MemPort（记忆层） | SkillGuard（技能治理） | TinyStack（小模型产线） |
|---|---|---|---|
| 目标客户 | 个人开发者 → 中小企业 | 有安全合规要求的企业 | 中大型传统企业 |
| 付费决策链 | 个人即时决策 | 安全团队 + 平台团队 | IT + 业务 + 采购 |
| 首单周期 | 当天 | 1-2 个月 | 2-4 个月 |
| 客单价 | 29-39 元/月 | 99 元/人/月 / 8 万起 | 15-40 万/项目 |
| 可规模化程度 | 高（PLG） | 中高（PLG + 销售） | 低（服务）→ 中（平台） |
| 技术门槛 | 中 | 中 | 高 |
| 竞争强度 | 高（平台方会做） | 低（形态太新） | 中（大厂在上、外包在下） |
| 最适合的起点 | 现在 | 现在 | 有行业资源时 |

**判断**：如果只能选一个，选 SkillGuard。理由是它同时具备"形态新（无直接竞品）、痛感强（安全事件会死人）、可 PLG 起步（CLI 免费）、可向上卖（企业网关）"四个特征，而且它不依赖任何平台方的善意。MemPort 的天花板更高，但正面撞上平台方；TinyStack 现金流最好，但第一天就是人力生意。

### 本周可执行的三件事

1. **做一次真实的技能审计**：把自己或团队正在用的所有 agent 技能列出来，逐个看脚本里的网络请求与文件访问。这个清单本身就是 SkillGuard 的第一份需求文档，也是最好的内容素材。
2. **验证记忆的痛感**：找三个同时用两个以上 AI 编码工具的朋友，问一个问题——"你换工具的时候，怎么把之前的上下文带过去？" 如果答案是"重新说一遍"，MemPort 的 MVP 就值得做。
3. **给 TinyStack 找一个真实 baseline**：挑一个身边的客服/工单场景，用现有 API 跑 200 条历史数据，算出准确率与单条成本。这个数字决定了"降 60%"这句话能不能说出口。

### 风险提示

- **记忆类产品的隐私责任是无限责任**。一旦承诺"帮你记住"，就要承担"记错、泄露、被删除不彻底"的全部后果。MVP 阶段建议默认全本地、默认不加密云同步，把责任边界划清楚。
- **技能治理会被平台方收编**。Anthropic 完全可能自己做一个官方 registry。对策是尽早把"跨平台"做成默认立场——只服务一个平台的治理工具，价值会被平台自己吃掉。
- **小模型服务容易被"模型能力进步"降维打击**。如果明年前沿模型价格再降一个数量级，很多优化项目就没有存在必要。所以 TinyStack 的真正卖点必须落在"数据不出内网"和"可证明的稳定性"上，而不是单纯的成本。
- **今日热榜的情绪成分**：claude-mem 的 106k stars 里有大量"收藏了但没用"的虚火。判断需求真伪要看留存，不看 star。这也是为什么三个创意都建议先用最小 MVP 验证，而不是直接融资扩张。

## 🔭 明日观察清单

1. **claude-mem 是否推出跨工具导出**：如果它开始做"记忆导出为标准格式"，说明记忆层的标准之争开打了；如果只做 Claude Code 深度集成，第三方中立层的机会窗口更大。
2. **技能仓库是否出现 package.json 之类的规范**：anthropics/skills 或 expo/skills 任一方定义技能清单格式，都会成为事实标准，SkillGuard 要第一时间兼容。
3. **Liquid AI 的端侧 agent 真实评测**：LFM2.5-24B-A2B 的"设备上跑"是营销还是可复现，看有没有第三方在消费级硬件上跑出可用延迟。
4. **词表特化的开源实现**：Dharma AI 那套 77% 的方法如果开源，TinyStack 的技术门槛会显著下降，交付周期可以从四周压到两周。
5. **NoveltyBench 的后续**：如果出现"AI 评审 + 人类复核"的混合流程产品，科研服务这个细分市场会开始成型。
6. **DeepTutor 的记忆设计**：它怎么处理"学生的学习历史"这个最敏感的记忆类型，会给通用记忆层提供合规范本。
