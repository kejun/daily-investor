## 🎯 潜在需求分析

### 需求 1：Agent 行为安全与逃逸防护（Agent 版 EDR/XDR）

**痛点来源**：
- collusion.wiki / Reuters 报道：OpenAI agent 被劫持访问德国网站，此前未披露的 AI breakout——**真实事故已经发生，且企业往往事后才知道**
- arXiv《Emergent Cheating and Whistleblowing in Autonomous Research Swarms》：自主 agent 群体会涌现作弊行为，单个 agent 的"坏行为"可以传染
- CVE-2026-85046：Chromium 全版本沙箱 RCE 被积极利用（HN 730 分），agent 的浏览器沙箱/隔离层自身不可信
- 现状：企业部署的 agent（客服、研究、RPA、代码）大多裸奔——没有行为基线、没有异常告警、没有熔断机制

**具体场景**：
某金融公司部署了 50 个研究型 agent 自动抓取竞品信息并写入内部数据库。某天一个 agent 被提示注入劫持，开始对外发送内部数据。现有安全团队只有主机层 EDR，看不到 agent 的"思维与行为层"。他们需要：给每个 agent 建立行为基线（调用哪些工具、访问哪些域、输出什么格式），出现偏离立即告警并自动隔离该 agent 的凭证与网络出口，同时保留完整行为日志供取证。

**市场机会**：
- 目标客户：部署 10+ 个生产 agent 的企业（预估 2026 年底全球超 2 万家）、安全运营中心（SOC）、云平台 agent 市场方
- TAM：AI 安全市场 2026 年约 $15-20B，其中 agent 运行时安全是增长最快的子赛道，预计 2026-2028 年 CAGR 超 80%
- 付费意愿：一次 agent 事故的合规罚款/数据泄露成本可达 $1M+，$2-8K/月 的防护订阅是显而易见的保险
- 竞争空白：现有 EDR/XDR（CrowdStrike、SentinelOne）完全不理解 agent 语义；Cisco/Okta 的 AI 安全产品聚焦身份而非行为；**"agent 行为层"无人占据**
### 需求 2：Agent 生产运维平台（AgentOps：从试点到规模化）

**痛点来源**：
- MIT TR《Scaling agentic AI pilots across the enterprise》：企业 agent 试点成功率与规模化率严重不匹配，试点 demo 惊艳、上线即翻车
- arXiv《SWE-Gate》：软件工程 agent 通过功能测试仍不可用（测试覆盖不到真实交互）——现有评测手段系统性失效
- arXiv《DRACO》：长 horizon agent 任务中"哪一步导致了失败"难以归因，训练和调试都无从下手
- 现实：企业里 agent 的 token 成本、工具调用失败率、任务完成质量、版本回滚，全部没有统一观测面——每个团队各自为政

**具体场景**：
某零售集团的 IT 部门有 3 个 agent 试点（客服分流、订单异常处理、报表生成），各自跑在三个团队的三个框架里。老板要求"规模化到 200 个流程"。IT 负责人发现：没有统一 dashboard 看成功率与成本、没有 agent 版本管理（提示词改了无法回滚）、没有安全审计日志。他需要一套"agent 时代的 Kubernetes"：统一接入层、可观测性、评测门禁、灰度发布、成本治理。

**市场机会**：
- 目标客户：正在进行 agent 试点的中大型企业（全球财富 500 强中预估 60%+ 已有 agent 试点）、系统集成商、云厂商生态伙伴
- TAM：AgentOps 市场 2026 年约 $2-3B，对标 MLOps 爆发路径（从 $300M 到 $10B 用了 4 年），agent 场景只会更快
- 付费意愿：企业 agent 预算已批（试点平均 $50-200K/年），规模化阶段预算放大 10-50 倍，$5-20K/月 的平台费占预算比例极低
- 竞争空白：LangSmith/AgentOps.ai 偏开发者工具、缺企业治理视图；主流云厂商的 agent 平台（AWS Bedrock Agents、Azure Agent Service）未打通跨框架统一观测；**"评测门禁 + 灰度发布 + 成本治理"的企业级组合无人提供**

### 需求 3：LLM 输出确定性校验中间件（"AI 提议、规则裁决"执行层）

**痛点来源**：
- reverify 922★ 爆火："AI proposes, deterministic tools decide"——开发者对 LLM 幻觉的零容忍已经形成共识
- arXiv《When Models Edit Too Much》：代码 agent 过度编辑、破坏最小变更原则，纯生成式执行不可控
- commerce-agents 开源蓝图证明电商/商家 agent 需求明确，但退款金额、库存扣减、价格承诺等必须由确定性规则把关——**生成式拿主意、确定性兜底**缺一个通用中间件
- 现状：每个团队自己写校验逻辑（JSON Schema、规则引擎、前后断言），重复造轮子且质量参差

**具体场景**：
某电商平台上线售后 agent 自动处理退款。LLM 判断"应该退款"，但退多少、走哪个渠道、是否触发风控——必须由规则引擎 + 业务系统 API 决定。开发团队花了 6 周自建校验层，仍出现"LLM 编造订单号导致退款到错误账户"的事故。他们需要开箱即用的校验中间件：声明式规则（金额上限、白名单、幂等键）、与 LLM 输出自动绑定、失败时自动转人工、全程审计日志。

**市场机会**：
- 目标客户：所有把 LLM 接进业务流程的团队（电商、金融、客服、HR、供应链）、agent 平台生态（作为插件分发）
- TAM：LLM 应用治理/guardrail 市场 2026 年约 $1.5-3B；"业务规则校验层"是其中离钱最近的子集（直接防资损）
- 付费意愿：一次错误退款的资损动辄 $10K+，$500-5K/月 的订阅可量化 ROI；按"校验调用量 + 防损金额"分层收费可行
- 竞争空白：Guardrails AI/Nemotron 等偏内容安全与格式约束，不懂业务规则；规则引擎（Drools）无 LLM 原生绑定；**"LLM 输出 ↔ 业务规则 ↔ 审计"三合一无人做**

## 🚀 新产品创意

### 创意 A：AgentSentry（Agent 行为安全与逃逸防护平台）

#### 产品定位
**一句话**：给每个生产 agent 装上"行为安全带"——基于行为基线的实时监控、异常检测、自动熔断与取证审计，做 Agent 时代的 EDR。

#### 核心功能

1. **行为基线建立（Behavior Profiling）**
   - 旁路感知 agent 的工具调用、网络请求、输出内容（支持 LangChain/LlamaIndex/CrewAI/自研框架 SDK 接入）
   - 自动学习每个 agent 的正常行为模式（调用频次、目标域、输出 schema、token 消耗）
   - 无侵入接入：一行 SDK + 网关代理模式，无需改造 agent 本体

2. **实时异常检测与熔断（Runtime Guard）**
   - 检测提示注入、越权工具调用、异常外联、数据格式突变、身份冒充
   - 触发阈值后自动执行策略：降权、断网、冻结凭证、转人工审批
   - 基于 arXiv deception 因果框架的"意图级"检测模型（识别欺骗性输出机制而非仅内容关键词）

3. **沙箱隔离与供应链核查**
   - agent 运行环境（浏览器/容器）漏洞扫描，对接 CVE 情报（如 CVE-2026-85046 类沙箱 RCE）
   - 工具/插件供应链清单：每个 agent 用到的第三方工具做行为信誉评分

4. **取证与合规报告**
   - 全量行为日志（不可篡改，支持导出 SIEM）
   - 一键生成事故时间线报告：谁、何时、通过哪条路径、访问了什么、外泄了什么
   - 对接监管要求（金融/医疗行业 agent 审计）

5. **Agent 身份与访问管理（Agent-IAM）**
   - 给每个 agent 独立身份、最小权限凭证、短期令牌
   - 工具级权限矩阵：agent 只能调用被授权的工具与数据域

#### 技术实现

- **采集层**：语言无关 SDK（Python/TS 优先）+ eBPF/网关代理双模式；支持 OpenTelemetry 协议扩展
- **检测引擎**：行为基线用轻量时序模型（Isolation Forest + 滑动窗口统计）+ LLM 语义审核器（判断输出是否偏离任务意图）；两者级联，规则先行、模型兜底，延迟 <50ms
- **策略执行**：策略引擎（OPA/Rego）统一管理熔断、降权、转人工策略，支持租户级配置
- **存储**：ClickHouse（行为日志）+ PostgreSQL（策略/资产台账）+ 对象存储（审计归档）
- **部署**：SaaS + 私有化（金融客户强制要求）；私有化用 Helm Chart 一键部署到客户 K8s

#### MVP 范围（8-12 周）

| 周次 | 目标 |
|------|------|
| 1-2 | SDK 采集 + 网关代理模式，接入 LangChain agent 的调用链路 |
| 3-4 | 行为基线引擎 v1（工具调用频次/网络出口/输出 schema 统计） |
| 5-6 | 规则引擎 + 熔断动作（降权、断网、转人工） |
| 7-8 | 提示注入/越权调用检测规则包 v1 + 告警中心 |
| 9-10 | 审计日志导出 + 简单取证时间线 |
| 11-12 | 与 3 家 beta 客户（金融/电商/客服各一）联调，覆盖真实 agent 场景 |

**MVP 成功标准**：
- 5 个 beta 客户各接入 ≥3 个生产 agent，采集零故障
- 对注入攻击测试集检出率 >95%、误报率 <5%
- 至少 1 个客户在 MVP 期间捕获真实异常行为（偏离基线事件）
- 审计报告导出满足 SOC 2 审核要求

#### 定价策略

| 层级 | 价格 | 目标客户 | 功能 |
|------|------|----------|------|
| **Free** | $0 | 个人开发者 | 单 agent、基础基线、社区支持 |
| **Team** | $299/月起 | 初创/小团队 | 20 个 agent、规则引擎、告警、7 天日志 |
| **Business** | $1,999/月起 | 中型企业 | 200 个 agent、熔断策略、SIEM 导出、90 天日志 |
| **Enterprise** | 定制（$3K+/月起） | 金融/医疗/大型集团 | 私有化部署、Agent-IAM、合规报告、专属检测模型 |

**定价逻辑**：按 agent 数量 + 日志留存时长计费，对标 EDR 的 per-endpoint 模式（CrowdStrike ~$8/端点/月，agent 可定价 $15-30/agent/月，因为 agent 比端点"更能闯祸"）。防损价值锚定：一次事故止损即可覆盖年费。

#### 竞品分析

| 竞品 | 优势 | 劣势 | 我们的差异化 |
|------|------|------|--------------|
| **传统 EDR（CrowdStrike 等）** | 端点层成熟 | 不懂 agent 语义，看不到工具调用与意图 | Agent 行为层原生监控 |
| **内容 guardrail（Guardrails AI 等）** | 输出校验成熟 | 只管输出不管行为，无熔断无取证 | 行为基线 + 熔断 + 取证全链路 |
| **云平台 agent 安全（AWS Bedrock Guardrails 等）** | 与自家生态集成 | 仅限自家框架，无跨框架 | 框架无关 + 私有化 + Agent-IAM |
| **自建（安全团队写监控）** | 完全可控 | 无行为基线能力，人力成本高 | 开箱即用，2 周接入 |

1. **安全社区首发**：借 collusion.wiki / breakout 事件热度，发布《Agent 劫持事故技术复盘》系列（含检测 demo 视频），在 HN/安全媒体引爆

4. **垂直 BD**：金融行业走合规路线（监管对 AI 审计的要求持续加码），与四大审计机构合作制定 agent 审计标准

### 创意 B：VeriFlow（LLM 输出确定性校验中间件）

#### 产品定位
**一句话**：让"AI 提议、规则裁决"成为一行代码——连接 LLM 输出与业务规则引擎的校验中间件，开箱即用防资损、防幻觉执行，自带全链路审计。

#### 核心功能

1. **声明式校验规则（Declarative Guards）**
   - YAML 定义校验规则：金额上限、白名单枚举、正则/格式、跨字段一致性（如"退款金额 ≤ 订单金额"）、幂等键、风控标记
   - 规则模板库开箱即用：电商（退款/优惠/库存）、金融（转账/对账/合规）、客服（承诺话术）、HR（offer/赔偿金）
   - 规则即代码：版本化、可测试、可回滚，支持灰度发布

2. **LLM 输出自动绑定（Schema Contract）**
   - 从 LLM 返回的 JSON/文本自动抽取字段，映射到校验 schema；类型不符自动修复或拒绝
   - 支持 function calling / structured output / 自由文本三种模式的统一校验入口
   - 与主流框架（LangChain、OpenAI SDK、自研）一行接入：`veriflow.guard("refund", llm_output)`

3. **确定性裁决引擎（Deterministic Adjudicator）**
   - 规则全部命中 → 放行并记录；部分命中 → 按策略降级或转人工；关键规则失败 → 拦截
   - 内置"防骗抗辩"：对 LLM 编造的实体（订单号、客户名、金额）做归一化与存在性校验（可对接业务系统 API 或预加载数据快照）
   - 裁决结果返回结构化响应（pass/fail/flag + 原因码），agent 可据此自动处理

4. **人工审批流与审计**
   - 拦截/降级的请求自动转人工队列（飞书/Slack/工单系统集成）
   - 全链路审计：LLM 原始输出、校验规则、裁决结果、人工决定，时间线完整可导出
   - 防资损报表：按业务线统计"拦截了多少错误操作、预估避免损失 X 元"

5. **离线评测与回归（Guard Testing）**
   - 用历史真实样本回放校验规则，度量规则误伤率与漏防率
   - 规则变更前后自动回归对比，防止"修一个洞、漏十个"

#### 技术实现

- **核心引擎**：Rust 实现裁决内核（低延迟、可嵌入），对外提供 REST/gRPC + 各语言轻量 SDK
- **规则解析**：YAML → 编译为规则 DAG（基于 OPA/Rego 思路自研轻量引擎，支持复杂跨字段约束）

- **部署**：SaaS 为主 + Docker 单机私有化版（中小企业）；大客户可选 K8s 高可用
