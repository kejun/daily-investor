## 🎯 潜在需求分析

### 需求 1：机器人能力的**"技能市场 + 编排层"**——让"让机器人干活"像调 API 一样可组合、可计量、可追责

**痛点来源**：
- Physical Intelligence 开放机器人基础模型 API 是里程碑，但它解决的是"单模型能听懂指令"，**没有解决真实产线最痛的部分：一个完整任务要跨越多种机器人本体、多种传感器、多个模型（视觉/规划/控制），并要保证在客户的场地里安全、可重复、可回滚**。
- 今天每落地一个机器人场景，团队都在重复造轮子：标定新硬件、把业务流程翻译成动作、处理异常（抓空了、被人挡了、料不对）、做安全边界。**这些"任务级的胶水与护栏"没有任何标准形态**，全靠项目制人力堆。
- 结果就是：基础模型越强，落地的"最后一公里"反而越显得人力密集、不可复用、无法规模化复制到下一个客户。

**具体场景**：
一家做仓储自动化的集成商，想给客户上线"拣选 + 复核 + 异常上报"整条机器人流程。今天它要：按客户的机器人型号做适配 → 把拣选流程拆成动作序列 → 定义异常处理规则 → 做安全限速与人工接管 → 上线后靠工程师现场调。**若能把"机器人能力（抓取/移动/视觉检查）"封装成可组合的 skill，把"业务任务"用可视化编排串成流程，并内置安全护栏、异常回退、逐次计量与回放审计**，那么同一套流程可以在不同客户、不同本体间快速复制——从中"卖人力项目"变成"卖可复用的能力与编排平台"。

**市场机会**：
- 目标客户：仓储/物流集成商、制造业产线、实验室自动化、农业/巡检、服务机器人运营商
- 付费意愿：$50k-500k / 年（按机器人席位、任务数、安全/审计模块分级）；集成商有极强的"复制下一个客户"的降本动机
- 竞品空白：机器人厂商各自闭源生态，基础模型方只提供 API 不做编排，**"跨本体技能封装 + 任务编排 + 安全审计 + 计量"几乎空白**
- 时机判断：API beta 刚发布、开发者注意力正在涌入；先做出"可复制交付"的平台者可抢品类定义权

### 需求 2：AI 生成代码的**"技术债度量与治理"平台**——把"写得太多"从隐性成本变成可管理的工程指标

**痛点来源**：
- Parsimony 的爆红直接说破了一个被忽视的事实：**现有评测奖励"解决"，不惩罚"多写"，而 AI 恰恰非常擅长用冗余代码"堆出"能跑的结果**。短期看解率漂亮，长期看代码库被无意义的新增代码拖垮——更难读、更难改、更难交接。
- 真实痛点有三层：①**增量失控**——每次 agent 任务都往上叠代码，没人看得见净增量趋势；②**审查缺位**——人类 reviewer 对 AI 大块补丁习惯性放过，review 质量下降；③**无标尺**——团队没有任何工具能回答"这个模型/这个 agent 到底让代码变干净还是变臃肿"。
- 现有工具全是"测功能对不对"，**没有一条把"净代码增量 / 冗余度 / 可维护性"当一等公民来度量与治理**。

**具体场景**：
一个中型研发团队全面引入 coding agent 后，有人发现三个月内主仓库净增数十万"coding units"，其中大量是重复工具函数与防御性冗余。**若有一个平台，能持续计算每个 PR / 每个 agent 会话的净代码增量、识别重复与死代码、给每个模型/agent 打"代码卫生分"，并在 CI 里设置增量预算（超预算就提醒或拦截）**，团队第一次能像管覆盖率一样管"代码膨胀"。它既能省 review 时间，也能作为"选哪个模型/agent"的客观依据。

**市场机会**：
- 目标客户：中大型研发团队、平台工程/DevEx 团队、AI 编码工具厂商（作为内置质量层）
- 付费意愿：$15-40 / 开发者 / 月，企业版 $10k+/年；价值直接绑定"维护成本"与"审查工时"
- 竞品空白：静态分析/质量平台不测"AI 净增量"，benchmark 只做离线评测不嵌入工作流，**"CI 内持续度量 + 模型横向对比 + 增量预算治理"空白**
- 时机判断：Parsimony 已经点燃讨论；把它从"benchmark 网站"做成"嵌入式治理产品"是明确的下一步

### 需求 3：开源大模型的**"合规与安全网关"**——让企业敢用开源权重，且用得可审计

**痛点来源**：
- MIT Tech Review 报道的 Anthropic 对 Z.ai 开源模型的安全警告，暴露了企业的真实两难：**开源模型省钱、可控、可私有部署，但"人人可下载可修改"意味着企业无法证明自己用的这个权重是安全、合规、无后门的**。
- 三个具体痛点：①**评估无标尺**——企业没有能力自己红队测试一个开源权重是否存在越狱、后门、有害微调残留；②**分发无追溯**——权重从 Hugging Face 下载、内部微调、跨团队流转，没有来源与变更的审计链；③**合规无背书**——监管/客户要求"你用什么模型、怎么保证安全"，企业拿不出证据。
- 现有市场要么是"闭源模型厂商自己出安全报告（利益相关）"，要么是"零散的开源红队脚本"，**没有一个面向企业的中立、可审计、可集成的合规网关**。

**具体场景**：
一家金融/医疗企业想用开源模型做内部知识助手，法务要求提供"模型安全评估 + 来源溯源 + 微调合规"的证据链。**若有一个网关，能在模型进入企业的那一刻自动做安全扫描（越狱/后门/有害能力探测）、生成可复现的评估报告、给权重打来源与微调溯源标签，并在每次分发/更新时强制走合规检查 + 留审计日志**，企业就能像管依赖库漏洞一样管"模型权重风险"，把"敢不敢用"变成"流程化地可以用"。

**市场机会**：
- 目标客户：金融、医疗、政务、法律等强监管行业，以及给这些行业做交付的 AI 集成商
- 付费意愿：$30k-300k / 年（按模型数、评估频次、审计与私有部署分级），合规是刚性的"通过/不通过"，预算确定
- 竞品空白：安全厂商不懂模型权重、模型厂商不中立、红队公司只做一次性项目，**"中立评估 + 来源溯源 + 分发审计 + 企业集成"空白**
- 时机判断：开源安全争论正处高点、监管压力上升，先建立"评估标准 + 审计留痕"者可成为事实上的合规层

## 🚀 新产品创意

### 创意 1：**SkillMesh（机器人技能编排云）——把"让机器人干活"做成可复用、可审计的流水线**

**产品定位**：
面向机器人集成商与终端工厂的"技能封装 + 任务编排"平台。它把基础模型（如 Physical Intelligence 的机器人 API）输出的原子能力，包装成**可组合、可版本化、可跨本体复用的技能（skill）**，让交付团队用可视化方式拼出完整任务流，并内置安全护栏、异常回退与逐次审计。一句话：**把机器人交付从"一次性项目"变成"可复制的产品"。**

**核心功能**：
1. **技能注册中心**：把抓取/移动/视觉检查/力控等能力封装成带输入输出契约、适用本体、精度边界的 skill，可搜索、可版本化、可复用
2. **可视化任务编排**：拖拽式编排技能与业务逻辑，支持条件分支、并行、循环与人工接管节点
3. **安全护栏引擎**：可配置的速度/力/工作空间约束、地理围栏、异常自动停机与回滚
4. **异常与回退**：抓空、被遮挡、物料不符等常见异常的标准处理库 + 自定义策略
5. **计量与回放审计**：每次任务逐次记录动作、模型调用、耗时与结果，可完整回放，支撑追责与优化
6. **跨本体适配层**：把技能与具体硬件解耦，换本体只需重标定映射，流程无须重写

**技术实现**：
- 编排层：DSL + 可视化编辑器（编译为可执行任务图），支持热更新
- 技能 SDK：统一 skill 接口规范（输入/输出/约束/回退），适配 Physical Intelligence 等基础模型 API 与厂商控制栈
- 安全层：实时约束校验 + 异常检测（视觉/力/时序）+ 硬急停联动
- 数据层：任务事件流（时序库）+ 技能/流程版本库 + 审计日志
- 仿真先行：接入仿真环境做流程预演与安全边界验证，降低现场调试成本

**MVP 范围**（6-8 周）：
- 只支持 **1 类本体 + 3-5 个核心技能 + 单条流程编排**，验证"流程可在两个客户间复用"
- 安全护栏只做速度/工作空间两类，异常库先覆盖抓取失败
- 提供本地/私有部署 + 回放审计单页
- 暂不做多厂商适配，先把"复制一个客户省多少人力"讲清楚

**定价策略**：
- **Starter**：开源 skill SDK + 本地单机编排，建立开发者生态
- **Growth** $1,500/月：云端编排、技能库、计量与回放、2 台机器人席位
- **Scale** 按机器人席位阶梯：跨本体适配、团队协作、安全策略中心、SLA
- **Enterprise** 定制：私有部署、行业技能包、审计与合规、按"复制交付节省的成本"分成
- 核心卖点：**第一次交付贵，第二次交付几乎白送**——复用本身就是付费理由

### 创意 2：**CodeBudget（AI 代码卫生治理平台）——把"写得太多"变成 CI 里看得见、管得住的指标**

**产品定位**：
面向采用 coding agent 的研发团队的"代码膨胀治理"平台。它持续度量每次 agent 会话 / 每个 PR 的**净代码增量、冗余度与可维护性**，在 CI 里设置"增量预算"，并给不同模型/agent 打"代码卫生分"。一句话：**像管测试覆盖率一样管 AI 写出来的代码量。**

**核心功能**：
1. **净增量度量**：基于 coding units（语句/调用/标识符/字面量），减去删除量，算出每个 PR 的净增量
2. **冗余与死代码检测**：识别重复实现、未被引用的新增、防御性冗余
3. **增量预算与门禁**：超预算的 PR 在 CI 里被标注/拦截，逼出"最小改动"的 agent 用法
4. **模型/Agent 卫生分**：跨模型横向对比"解同一任务加了多干净的代码"，作为选型依据
5. **PR 级洞察**：自动生成"这个补丁为什么被认为是臃肿"的可读说明，辅助 review
6. **趋势看板**：仓库/团队的代码膨胀趋势、重灾区模块定位

**技术实现**：
- 解析层：多语言 AST 解析，抽取 coding units；diff 与删除量对齐（复用 Parsimony 思路）
- 重复检测：结构哈希 + 语义近似（嵌入）双通道
- CI 集成：GitHub Actions / GitLab CI 插件 + bot 评论 + 门禁规则
- 评分模型：增量 + 冗余 + 复杂度加权，可自定义阈值
- 数据层：指标时序库 + 模型对比报告

**MVP 范围**（4-6 周）：
- 只支持 **2-3 种主流语言 + GitHub PR 集成**，验证"增量预算能被接受"
- 先做净增量 + 重复检测 + bot 评论，门禁作为可选开关
- 提供"模型卫生分"对比页，用少量真实任务做样例
- 暂不做语义重复的深度分析，先证明度量本身有价值

**定价策略**：
