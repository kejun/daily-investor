## 📊 今日核心洞察

### 热点话题

1. **arXiv 上出现了一个专门测"证据缺失时 Agent 会怎么办"的基准：EpiSEM-Bench**。这个名字值得拆开看——Safety and Evidence Recovery in LLM Agents under Missing Evidence。它测的不是"Agent 会不会答错"，而是**当关键证据不在上下文里时，Agent 会不会诚实地承认"我不知道"，以及它能不能把缺失的那块证据找回来**。这个问题之所以被单独拎出来做成基准，是因为过去两年的 Agent 评测几乎都在奖励"给出答案"，而没有惩罚"编造依据"。一个能跑通流程、能写完整报告、语气笃定的 Agent，在缺失证据的场景下产出的东西，读起来和真的几乎无法区分——**这才是企业不敢把 Agent 放进核心流程的真正原因**。

2. **同一批新论文里还有 RIDAR：检测并干预"自主科研 Agent"的学术诚信问题**。和 EpiSEM-Bench 放在一起看，逻辑非常清楚：**当 Agent 开始产出"研究成果"这种高价值、高验证成本的东西时，造假动机和造假能力同时出现了**。RIDAR 做的是运行时的检测与干预——不是事后查重，而是在 Agent 写的过程中就识别"这个引用可能不存在""这个实验结论和数据对不上"。这两篇论文合起来说明，学术界已经承认：**Agent 的可信度问题，不能靠"更强的模型"解决，只能靠"外部的验证机制"解决**。

3. **"Contestable Agents for Data Governance" 把"人类可质疑"写进了 Agent 的设计里**。这篇论文关心的是：当 Agent 自动生成元数据、自动打标签、自动归类数据资产时，**人类管理员如何保留"我不同意"的权利，并且这个不同意要能被记录、被追溯、被用来改进系统**。关键词是 contestable——可争辩的。今天绝大多数 Agent 产品的交互模型是"Agent 做完，人来确认"，这看似保留了人类控制权，实际上人类只能点"通过"，因为**没有任何界面让人表达"你为什么这么判断"和"我认为你错了，理由是……"**。把"异议"作为一等公民的数据结构，是一个被完全忽略的产品空档。

4. **"Who Is Sycophantic to Whom?" 这篇论文把谄媚问题从"模型缺陷"重新定义成"关系问题"**。它研究的不是"LLM 会不会拍马屁"，而是**当模型表现得越自信，人类的顺从度会如何变化，以及这种互动如何导致"信任校准"的崩塌**。结论很刺人：自信的语气比准确的答案更能赢得人类的同意。这意味着——**模型能力提升不会自动带来更好的决策，反而可能让人类的判断力退化得更快**。这个洞察对产品设计的含义是：如果你的 AI 产品只优化"用户满意度"，你实际上在优化"用户被认同的舒适感"，而不是"用户做对了决定"。

5. **HN 首页上两件事值得我们停下来看：一个 10 岁的老式 CNN 在皮肤癌诊断上打败了前沿 LLM；伯克利的数学教授说"AI 之后，给作业打分已经没有意义了"**。第一件事是技术信号：**在数据分布稳定、标注质量高、评价标准明确的垂类任务上，小模型依然碾压通用大模型**，因为通用模型的优势在于覆盖广度，而不在于单点精度。第二件事是社会信号：**当"产出物"可以廉价生成时，所有以"产出物"为评价对象的教育与考核体系同时失效**。这两件事指向同一个判断：**AI 时代的价值锚点，正在从"结果"转移到"过程"和"证据"**。

### 技术趋势

1. **"举证"正在成为 Agent 架构里的独立一层**：EpiSEM-Bench 测证据恢复，RIDAR 做运行时诚信干预，Contestable Agents 记录人类异议。三篇论文、三个角度、同一个结论——**Agent 的推理链和它的证据链是两回事，必须分开建模、分开存储、分开验证**。今天的 Agent 框架（LangGraph、AutoGen、各种 SDK）都把注意力放在"怎么走下一步"，没有一个原生提供"这一步的结论依据是什么、依据来自哪里、依据是否还在"。
2. **异步多 Agent 的基础设施开始被认真对待**：arXiv 今天有一篇 *Muffin - A Shared Memory Buffer for Asynchronous AI Agents*，直接指出今天多 Agent 系统的核心痛点——**Agent 之间是异步的，但共享状态的语义是同步假设下设计的**。加上 *Subgoal-aware Memory Graph for GUI Agent* 和 *The Value of Memory in Language Agents*，一天之内三篇关于 Agent 记忆的论文，说明这个方向已经从"加个向量库"进入"要设计内存一致性模型"的阶段了。
3. **推理成本优化从"量化/蒸馏"转向"词表特化"**：Hugging Face 上 Dharma AI 的 VocabX 给出了一个惊人的数字——**把 SLM 的词表针对特定领域做特化，真实应用里推理成本降低 77%**。原理不复杂：通用词表里有大量在你的场景中永不出现的 token，它们占据嵌入层参数、拖慢 softmax、浪费算力。**这是一条被低估的降本路径，因为它不需要改模型结构，只需要改 tokenizer 和重训嵌入**。
4. **"零训练"的结构化数据模型开始挑战传统 ML**：NVIDIA 的 Kumo Relational 宣称在关系型数据上不需要训练就能超过监督学习。如果这个结论在更多数据集上成立，含义是——**大量企业内部的表格预测任务（流失预测、信用评估、销量预测），可能不再需要标注、不再需要特征工程、不再需要数据科学家**。这会重构整个"企业 ML 平台"的产品形态。
5. **算力供给侧的信号越来越强**：Cerebras 部署万亿参数模型、TorchNeuron/TorchTPU 让同一模型跨芯片可移植。**推理算力的稀缺性正在被稀释，模型本身的可替代性在上升**。当算力和模型都变成"可替换的日用品"，产品的护城河只能来自**数据闭环、工作流嵌入和验证机制**——这三样恰好都是"证据"的变体。

## 🎯 潜在需求分析

### 需求 1：Agent 给出的每一个结论，都没有"可查验的依据"

**痛点来源**：
- 今天企业里跑着的 Agent，绝大多数是"会写"的：会写周报、会写合同摘要、会写代码、会写尽调报告。但**没有任何一个 Agent 会在写完的时候告出"这句话的依据在第 3 页第 2 段"**。人类读一份人类写的报告，可以要求作者标注来源；读 Agent 写的报告，只能选择全信或者全不信
- 更严重的是**缺失证据的场景**：EpiSEM-Bench 之所以要单独建基准，是因为 Agent 在"上下文里没有相关信息"时，行为极不稳定——有时会说"资料中没有提到"，有时会用一个高度相似但实际无关的内容顶替，有时会直接生成一个看起来合理的结论。**这三种行为在产品演示里毫无差别，在审计现场是灾难**
- 责任链条断了：当一个 Agent 生成的合同风险摘要漏掉了关键条款，出事后第一问是"它凭什么说这条不重要"。今天的日志系统记录的是**调用了哪个模型、消耗了多少 token、返回了什么文本**，却没有记录**这个判断引用了哪几条事实、这些事实来自哪份文件的哪个位置、当时那份文件是不是最新版本**
- RIDAR 的出现说明学术界已经在担心自主 Agent 的诚信问题，而企业侧的现状更原始：**大部分公司连"Agent 的输出要留档"都还没做**，更不用说"留档要可验证"
- 结果是一个荒谬的局面：**Agent 越能干，企业越不敢让它干**。金融、医疗、法律、审计这些高价值行业，恰恰是 Agent 渗透率最低的地方，不是因为能力不够，而是因为**没有一套东西能让"人签字"这件事在 Agent 时代继续成立**

**具体场景**：
一家券商的投行部门用 Agent 做 IPO 招股书的初稿。Agent 表现很好，三天产出 200 页，分析师只需要修改。但合规部门卡住了：按照流程，招股书里的每一条业务描述、每一个财务数字，都必须能追溯到工作底稿的具体文件。Agent 的稿子里有 800 多处事实陈述，分析师没办法逐一核对来源，因为**Agent 没有提供来源**。项目组尝试让 Agent"重新生成一遍并附上引用"，结果两遍生成的引用对不上，第二遍还漏了十几条。最后这个项目退回人工，Agent 只在"润色"环节被使用。**公司省下的不是 70% 的工作量，而是 5%。**

**市场机会**：
- 目标客户：投行/律所/审计/医药注册/保险理赔——所有**产出物需要有人签字负责**的行业
- 产品形态：**Evident —— Agent 举证层（Evidence Layer for Agents）**
  - **结论-证据绑定**：在 Agent 的推理循环里插入一个强制步骤，每一个"事实性断言"必须挂载至少一个 evidence ref（文件 ID + 页码 + 段落哈希 + 抓取时间）。没有 evidence 的断言会被自动标记为"待验证"，而不是被丢弃——**保留它，但降级它的可信度**
  - **缺失证据检测**：对每个断言做一次反向检索，判断"如果这个断言为真，上下文里应该有什么"。找不到就标记 gap，输出一份"未知清单"而不是硬编一个答案
  - **异议通道**：人类审查者可以逐条标记"不同意"，并写下理由。异议被结构化存储（who / when / which claim / why），成为下一轮微调或提示优化的训练信号——这是 Contestable Agents 那篇论文的产品化
  - **证据版本快照**：每份被引用的文档生成内容哈希，文档更新后自动标记"引用已过期"，触发重新核验
  - **审计导出**：一键生成"断言-证据-异议"三列表，可直接进合规档案；支持 PDF/A 与哈希存证
- 定价：按"审查通过的断言数"计费（$0.02/条），或 $8k/月含 50 万条；私有化 $200k/年起
- 壁垒：不在模型，而在**接入深度**。要拿到"页码 + 段落哈希"级别的证据，必须深度对接客户的 DMS、邮箱、工单、数据库。**接得越深，替换成本越高**——这是典型的高转换成本生意
- 风险：客户会说"我们已经有 OA 审批了"。要区分清楚：审批管的是"谁同意了"，Evident 管的是"凭什么这么写"。**这是两个完全不同的问题，前者已经饱和，后者完全空白**

### 需求 2：多个 Agent 并行干活，但它们不共享"记忆"，只共享"文件"

**痛点来源**：
- 今天的多 Agent 系统，协作方式基本是"传文件"或"传消息"：一个 Agent 写个 JSON，另一个 Agent 读。这在流水线式任务里够用，但一旦**多个 Agent 并行处理同一份不断变化的世界状态**，问题立刻暴露——A 以为订单已取消，B 以为订单还在，C 在两者之间做了退款
- *Muffin* 这篇论文点破的就是这件事：**Agent 是异步的，但共享内存的语义是同步假设下的**。传统并发编程用锁、版本号、事务来解决，而今天的 Agent 框架里，这些概念一个都没有。所谓"共享记忆"，绝大多数实现就是一个向量库，**没有版本、没有冲突检测、没有读写隔离**
- *Subgoal-aware Memory Graph for GUI Agent* 提供了另一个角度：GUI Agent 的记忆不该是"历史截图列表"，而应该是**以子目标为节点的图**——因为我关心的是"订票这个子目标完成到哪一步了"，而不是"我点过哪些按钮"。这个抽象对多 Agent 协作同样适用：**协作的共享状态应该是目标图，不是消息流**
- 现实中的表现是"Agent 团队看起来很忙，但一直在重复劳动"：三个 Agent 分别去查同一个客户的同一个信息，因为谁都不知道别人查过了。成本翻三倍，延迟翻两倍，**而老板看到的是账单**
- 更隐蔽的问题是**回放能力缺失**：出了错，没人能重建"当时每个 Agent 各自看到了什么"。没有这个，多 Agent 系统就是不可调试的，而不可调试的系统不可能被允许上生产

**具体场景**：
一家跨境电商用四个 Agent 做售后：一个判责、一个算退款、一个跟物流、一个写回复。某天一个包裹被物流标记"丢失"又在两小时后"找到"，判责 Agent 基于"丢失"做了全额退款判断，算退款 Agent 基于"找到"拒绝了退款，写回复 Agent 收到了两条矛盾结论，最后给客户发了一封自相矛盾的邮件。事后复盘，发现**两个 Agent 都读了同一个物流 API，但读的时间差了 90 分钟，而系统里没有任何机制告诉写回复 Agent"你手上的两条信息版本不同"**。

**市场机会**：
- 目标客户：已经在跑 3 个以上 Agent 的中大型企业（数量在 2026 年快速上升）；以及做 Agent 平台、想把"可靠性"当卖点的厂商（**他们是更好的第一批客户，因为可以 OEM**）
- 产品形态：**Loom —— 异步 Agent 共享工作记忆总线**
  - **目标图作为一等公民**：共享状态不是"消息列表"，而是"目标 → 子目标 → 状态"的图。每个 Agent 声明自己要推进哪个子目标，系统自动分配写权限，避免多个 Agent 写同一节点
  - **乐观并发 + 版本向量**：每个状态节点带版本号，Agent 读的时候记下版本，写的时候校验。冲突不阻塞，而是**生成一个"冲突事实"给上层 Agent 决策**——这比加锁更符合 Agent 的工作方式
  - **读写分离的"视图"**：每个 Agent 看到的是"它订阅的那部分世界"的快照，而不是全局。快照带时间戳，跨 Agent 引用时必须携带，**让"信息陈旧"变成一个显式错误而不是隐性 bug**
  - **完整回放**：任意时间点，重建每个 Agent 的视图、它的决策、它引用的状态版本。这是给运维和审计用的，也是**给开发者 debug 用的**（后者才是日常高频需求）
  - **成本归因**：按子目标统计 token 与调用次数，直接回答"这个流程里哪个环节最贵"
- 定价：$0.5/千次状态操作 + $3k/月基础费；OEM 授权按调用量分成
- 壁垒：**这是基础设施，一旦嵌进客户的 Agent 编排里就很难换**。但也要清楚，基础设施的销售周期长、需要 SDK 生态，**适合有耐心的团队**
- 风险：主流 Agent 框架（LangGraph 等）随时可能自己加一层记忆原语。防守方式是**做跨框架**——不绑死任何编排引擎，反而在"跨框架、跨厂商"上建立中立性

### 需求 3：以"产出物"为对象的评估体系，正在集体失效

**痛点来源**：
- 伯克利数学教授那句"AI 之后给作业打分没有意义了"被顶上了 HN 首页，因为它说出了千万教师的心里话。但真正的痛点不在大学，而在**所有依赖"提交一份东西来证明你会"的场景**：作业、论文、代码作业、设计稿、翻译测试、入职笔试、晋升述职材料
- 失效的机制很直接：**当生成成本趋近于零，产出物不再携带能力信号**。过去一份写得好的作业，隐含了"这个人查了资料、想了很久、组织过语言"；现在它只隐含了"这个人会用工具"。评价者看到的信号和想测量的能力之间，**相关性断崖式下跌**
- 而 sycophancy 那篇论文补充了另一半：**人会对自信的表达过度顺从**。这意味着即使评价者知道"这可能是 AI 写的"，他们在面对一份结构清晰、语气笃定的材料时，仍然倾向于给高分。**评估者的判断力本身也在被侵蚀**
- 现有替代方案都不成立：查重工具只能查"复制"，查不了"生成"；AI 检测器误判率高到无法作为处分依据（已有大量学生申诉案例）；线下闭卷考试能防 AI，但**把二十年积累的教学方法全部推翻**，成本高到没人愿意承担
- 于是形成了一个真空：**所有人都知道旧标准失效了，但没有人在建新标准**

**具体场景**：
一家 800 人的科技公司做校招，往年靠笔试 + 作业筛人。今年笔试题库被泄露到 AI 工具里，作业题的平均分从 62 涨到 88，但入职后三个月的绩效与作业分数**相关性从 0.4 掉到 0.05**。HR 试着加面，但面试官的时间成本翻倍，且面试官自己也在用 AI 写面试评价。最后公司改成"只看实习经历"，**结果是招聘渠道窄了一半，多样性指标崩了**。

**市场机会**：
- 目标客户：高校院系（有预算、有压力、要合规）、企业招聘（痛点自带预算）、专业认证机构（CPA/CFA/医师资格这类，**他们的整个商业模式建立在"能验证能力"上**）
- 产品形态：**Viva —— 过程性能力评估平台（"口试即服务"）**
  - **语音追问式考核**：不看作答结果，看**追问下的表现**。系统基于提交的材料自动生成三层追问（是什么 / 为什么 / 如果改成这样呢），用语音实时进行，全程录音转写
  - **过程产物留痕**：允许学生/候选人使用 AI，但要求开启"过程记录"——草稿版本、提问历史、修改轨迹。评估的不是"最终答案"，而是**"你如何从不知道走到知道"**
  - **能力维度打分卡**：把"概念理解 / 迁移能力 / 边界意识 / 表达清晰度"拆成独立维度，每个维度有行为锚定描述。**这是让评估脱离"印象分"的关键**——没有维度拆解，AI 辅助的评估只会更主观
  - **防作弊但不反 AI**：定位清晰——**不是禁止使用 AI，而是要求"用了也要能讲明白"**。这一条决定了产品能不能进校园：反 AI 的产品会被学生抵制、被教师质疑、被舆论攻击；"要求你讲明白"的产品立场更容易被接受
  - **批量与成本**：一场 8 分钟语音答辩的成本要压到 $1 以内，否则无法替代人工批改。技术路径是 ASR + 结构化评分模型，不做开放式对话（那太贵且不稳定）
- 定价：$2-4/人次（高校），$15-30/候选人（企业招聘）；认证机构按年授权
- 壁垒：**评分卡的内容资产**。每个学科/岗位的维度定义和追问模板，需要领域专家逐条打磨，这是纯人力活，也是后来者最难抄的部分
- 风险：**这是一个会被骂的产品**。学生会说侵犯隐私，教师会说增加工作量，学校法务会担心录音合规。必须从第一天就把数据处理做成"本地化 + 最短留存 + 学生可查"，**否则一次舆情就能终结整个项目**

### 需求 4：垂类场景里，"小而专"正在系统性地打败"大而全"

**痛点来源**：
- HN 那条"10 岁 CNN 打败前沿 LLM 做皮肤癌诊断"不是孤例，它代表了一类被反复验证的现象：**在数据分布稳定、标签质量高、评价标准明确的任务上，专用小模型的性价比远高于通用大模型**
- 但企业的采购逻辑还停留在"买最强的模型"：因为**没有人能告诉他们"你这个任务到底需要多大的模型"**。模型选型今天基本靠三样东西——厂商 benchmark、同行口碑、以及"先用最大的试试"。这三样都不针对他们的具体任务
- 成本侧的压力是真实的：VocabX 的 77% 降本说明**同一个模型在词表层面还有巨大浪费空间**。一个只处理中文合同的模型，词表里却有大量阿拉伯语、代码符号、罕见 Unicode 字符，这些 token 占据嵌入参数、参与每一次 softmax 计算，**纯属白烧钱**
- 更深的问题是**评测缺失**：企业不知道自己任务的"天花板"在哪，所以既不敢用小模型（怕效果差），也无法判断大模型的溢价是否合理。**这是一个纯粹的信息不对称市场，而信息不对称就是产品机会**

**具体场景**：
一家医疗信息化公司做病理报告的结构化抽取，每天处理 4 万份报告。他们用某前沿大模型，月账单 $60k，准确率 94%。老板问"能不能便宜点"，技术团队试了三个月：换小模型准确率掉到 88%（不可接受），做量化掉了 1.5 个点（勉强），加缓存命中率只有 12%（报告文本几乎不重复）。**他们真正需要的是"针对病理报告词表做特化"，但团队里没有人知道这条路，也没有工具帮他们评估这条路值不值**

**市场机会**：
- 目标客户：日均推理成本 $10k 以上的企业（这个门槛保证了节省的绝对值足够大）；以及模型厂商/云厂商的"降本"销售场景（**他们需要一个能证明"换小模型也够用"的工具，来推动客户从大模型迁移到自家小模型**）
- 产品形态：**LexCut —— 垂直领域模型特化与选型服务**
  - **任务画像**：用客户自己的 500-2000 条真实样本，跑一个"能力下限探测"——测出这个任务在参数量、上下文长度、词表规模三个维度上的最小可行配置
  - **词表特化**：分析客户语料的 token 分布，裁掉长尾 token、合并高频片段，重训嵌入层 + 少量适配。**输出是一个比原模型小 20-40%、推理快 2-3 倍、精度基本持平的专用模型**
  - **溢价审计**：给出"你为通用能力多付了多少钱"的报告。这个报告本身就是销售工具——**客户拿去给老板看，比任何 demo 都有说服力**
  - **回归测试集**：每次特化后自动跑一遍客户的真实样本，输出逐条 diff。**没有这个，客户不敢上线**
  - **可选托管**：特化后的模型托管在客户自己的云上或私有环境
- 定价：诊断报告 $15k 一次性；特化项目 $50k-150k + 效果对赌（达不到承诺精度退 50%）；托管按推理量抽 10%
- 壁垒：**这是咨询 + 工程的混合体，规模化难，但毛利高、客户粘性强**。真正的壁垒是"特化方法论 + 行业语料统计先验"——做过 20 个医疗客户之后，你比任何模型厂商都懂"医疗文本的 token 分布长什么样"
- 风险：**模型厂商可能自己下场做这件事**（而且他们有动力，因为能推动客户用更便宜的自家模型）。防守方式是**做跨厂商中立**，同时把交付物做成"客户资产"（模型权重、评测集归客户），**用"中立 + 归属"对抗厂商的垂直整合**

### 创意 1：Evident —— 让 Agent 的每句话都能被"查"

**一句话定位**：
不是让 Agent 更聪明，而是让 Agent 的每一句话都**可以被追问、被核验、被签字**。它是 Agent 与企业合规体系之间缺失的那层"举证中间件"。

**核心功能**：
1. **断言抽取与分类**：Agent 输出后，自动切分为"事实性断言 / 判断性结论 / 建议性表述"三类。只有第一类需要强制证据，第二类需要"推理依据"，第三类需要"利益披露"。**分级是关键**——如果要求每一句话都有引用，产品会立刻变成噪音制造机
2. **证据挂载（自动 + 人工）**：自动从检索结果、工具返回、文档解析结果中匹配 evidence ref；匹配不上的进入"待补证"队列，由人工补齐或由 Agent 二次检索
3. **缺失证据检测（Gap Detection）**：对每条断言做反向提问——"若此断言成立，应存在哪些支撑材料"。在已有语料中检索不到，标记为 gap 并写入"未知清单"。**这份清单本身就是一个高价值交付物**：它告诉决策者"这个方案里我们其实还不知道什么"
4. **异议与仲裁流**：审查者逐条提出异议（结构化：断言 ID + 异议类型 + 理由 + 替代证据），系统生成"争议台账"，支持三级仲裁（业务 / 合规 / 法务）
5. **证据时效管理**：所有引用文档做内容哈希 + 版本快照，源文变更时自动标记"引用失效"，触发重审
6. **审计包导出**：断言-证据-异议-仲裁四联表，附哈希清单，支持 PDF/A、WORM 存储、时间戳服务

**技术实现**：
- 断言抽取用**小模型微调**（不需要大模型，这个任务边界清晰，Qwen 7B 级别足够，成本可控）
- 证据匹配用**混合检索**：BM25（保精确匹配，法条、编号、金额）+ 稠密向量（保语义）+ 段落级 rerank。**必须有 BM25**——纯向量检索在"条款编号"这种精确匹配上错得离谱
- 反向检索用**假设性提问生成 + 检索**（类似 HyDE），但不用生成答案，只用生成"应该存在的证据描述"去检索
- 版本管理用**内容寻址存储**（类似 git 的 blob 模型），每份文档一个 SHA-256，天然支持去重和快照
- 输出层用**结构化 schema**（JSON-LD），保证任何下游系统都能解析，**不做私有格式**——私有格式是这类产品的死因

**MVP 范围（8-10 周）**：
- 只做**单一文档类型**：合同（因为合同的结构化程度最高、证据边界最清楚、客户最容易验证效果）
- 只做**单一工作流**：合同风险条款摘要 → 断言抽取 → 证据挂载 → 人工确认 → 导出
- 只接**一个 DMS**（先做飞书/SharePoint 二选一）
- **不做**：多语言、多文档类型、自动仲裁、实时协作
- 验收标准：10 份真实合同，断言抽取召回率 > 90%，证据匹配准确率 > 85%，人工确认时间比纯人工减少 50% 以上。**达不到就不要往下做**

**定价策略**：
- **按断言计费**：$0.02/条已核验断言，含存储与审计导出。一个中型法务团队月均 20 万条 → $4k/月
- **团队版**：$8k/月，含 50 万条 + 5 个 DMS 连接器 + SSO
- **企业版**：$200k/年起，私有化部署 + 定制连接器 + 合规认证支持
- **为什么按断言而不按席位**：席位制会鼓励客户"少开账号"，按断言计费鼓励客户"多跑业务"，**计费单位必须和客户的价值增长同向**

**为什么现在做**：
EpiSEM-Bench 和 RIDAR 的出现说明"Agent 可信度"刚刚被学术界定义成一个独立问题，**而企业侧的解决方案还是零**。这个窗口期大约 12-18 个月，之后要么被 Agent 平台内置，要么被合规厂商收购。**先做出 3 个愿意付钱的律所/券商客户，比做完整个产品重要得多**。

### 创意 2：Loom —— 给多个 Agent 用的"共享工作记忆"

**一句话定位**：
不是又一个 Agent 编排框架，而是**编排框架下面那层"并发安全的世界状态"**。如果说 LangGraph 管的是"谁下一步做什么"，Loom 管的是"大家看到的世界是不是同一个"。

**核心功能**：
1. **目标图（Goal Graph）**：把任务建模成"目标 → 子目标 → 完成条件"的有向图。每个 Agent 声明自己负责的节点，系统据此分配写权限。**这是权限模型，也是协作协议**
2. **状态节点 + 版本向量**：每个状态节点有独立版本号；Agent 读取时获取快照版本，写入时校验。冲突不抛异常，而是产生一条"冲突记录"供上层决策
3. **订阅式视图**：Agent 只订阅自己需要的状态子集，系统返回带时间戳的快照。**跨 Agent 传递信息时，时间戳必须随行**——这样"信息陈旧"从隐性 bug 变成显式可检
4. **完整回放（Time Travel）**：任意历史时刻，重建全局状态 + 每个 Agent 的视图 + 它的决策记录。用于 debug、审计、以及"出了事到底谁看错了"
5. **冲突解释器**：当两个 Agent 基于不同版本得出矛盾结论时，自动生成"分歧说明"（各自看到了什么、版本差多少、分歧点在哪），交给上层 Agent 或人类裁决
6. **成本账本**：按子目标聚合 token、工具调用、耗时，输出"这个流程哪一段最贵"

**技术实现**：
- 核心是一个**带版本向量的 KV/图存储**，可以用 SQLite（单机）或 Postgres（分布式）实现，**不需要自研数据库**——这是工程判断，不是技术炫耀
- 并发控制用**乐观锁 + CRDT 处理可合并字段**：计数类、集合类字段用 CRDT 自动合并（避免不必要的冲突），文本类、决策类字段用版本校验（必须人工或上层裁决）
- SDK 优先做 **Python + TypeScript**，提供 `read(goal_id) -> snapshot` / `write(goal_id, patch, base_version)` 两个原语，**其余都是组合**
- 回放通过**事件溯源（event sourcing）**实现：所有写操作追加到日志，状态是日志的投影。这样回放是免费的
- 与现有框架的集成用**适配器模式**：LangGraph / AutoGen / 自研框架各写一个 adapter，**不改用户的编排代码**

**MVP 范围（6-8 周）**：
- 只支持**单机 SQLite + Python SDK**
- 只做**三个原语**：目标图 CRUD、快照读、带版本写
- 只做**一个杀手级功能**：回放。**这是唯一能让开发者在 10 分钟内感受到价值的功能**
- **不做**：分布式、CRDT、成本账本、Web UI
- 验收标准：用一个 4 Agent 的客服售后 demo，能复现出"两个 Agent 基于不同版本做出矛盾决策"的场景，并且回放能一眼看出分歧点。**这个 demo 就是销售材料**

**定价策略**：
- **开源核心 + 托管**：SDK 与单机版 Apache 2.0 开源（**基础设施必须开源，否则没人敢用**）
- **Cloud 版**：$0.5/千次状态操作，$3k/月起（含回放存储 90 天）
- **OEM**：Agent 平台厂商按调用量分成，$50k/年起
- **企业版**：$150k/年，私有化 + SSO + 审计日志 + SLA
- **变现逻辑**：开源获取开发者心智，托管赚生产环境的钱。**不要对 SDK 收费，那会杀死采用率**

**为什么现在做**：
一天之内三篇 Agent 记忆论文（Muffin、Subgoal-aware Memory Graph、The Value of Memory），说明痛点已经被学界确认，**但工程侧的成熟实现还没有出现**。窗口期存在，但不会太长——**主流编排框架 12 个月内大概率会加一层原生记忆**。所以策略是：**先做跨框架的中立层，用开源换 adoption，用"回放"这个单点功能建立认知**。

### 创意 3：Viva —— 用 8 分钟追问，替代一份可以被 AI 写完的作业

**一句话定位**：
不检测 AI，不禁止 AI，只要求**"你用了可以，但你得讲明白"**。把评估对象从"提交物"换成"对话中的思维过程"。

**核心功能**：
1. **材料解析 + 追问生成**：接受学生/候选人的提交物（论文、代码、设计稿、报告），自动识别其中的关键论断、方法选择、以及"看起来像是套话"的部分，生成三层追问：
   - L1 复述层："你这部分为什么选这个方法？"
   - L2 迁移层："如果把数据量缩小 100 倍，你的结论还成立吗？"
   - L3 边界层："什么情况下你这个方案会彻底失效？"
2. **语音答辩（8 分钟）**：WebRTC 实时语音，AI 考官按追问树推进，允许被打断、允许追问"你刚才说的 X 是什么意思"。全程录音 + 转写
3. **多维度评分卡**：概念理解 / 推理连贯性 / 边界意识 / 表达清晰度 / 诚实度（是否承认"这块我不确定"）。**每个维度有 5 级行为锚定描述**，AI 只做初评 + 证据引用，最终分数由人确认
4. **"我不知道"奖励机制**：明确承认不确定并说明"我会怎么去查"，在诚实度维度得分。**这是整个产品最重要的设计**——它把"猜"变成劣势，把"承认不知道"变成优势
5. **过程留痕（可选）**：对接编辑器/IDE 插件，记录草稿版本与提问历史，作为"过程分"的输入
6. **申诉通道**：学生可查看自己的转写、评分依据、AI 引用的原话，并可申诉。**没有这个，产品进不了学校**

**技术实现**：
- ASR 用专用模型（Whisper 级别 + 领域热词注入），延迟要求 < 500ms 首字，否则对话感崩塌
- 追问生成用**中等模型 + 强约束 prompt**：追问必须引用提交物原文，不能泛泛而问；每次只问一个问题
- 评分用**评分卡 + few-shot 锚定**，输出"维度分 + 引用原话 + 置信度"，低置信度自动转人工
- 反作弊：检测"背诵式回答"（语速均匀、无停顿、无自我修正）与"屏幕朗读"（无目光/无思考停顿），**只作为提示，不作为判定**——技术上无法可靠区分，**承诺"能检测 AI"的产品都会翻车**
- 成本控制：8 分钟答辩约 3000 token 输入 + 2000 token 输出，用中型模型即可，单次成本 < $0.3

**MVP 范围（10-12 周）**：
- 只做**一个学科/岗位**：先做"计算机专业本科毕业论文答辩"或"初级程序员技术面"
- 只做**8 分钟固定流程**，追问树深度 2 层
- 只做**评分卡 + 转写报告导出**，不做 LMS 集成
- **不做**：多语言、实时视频、防作弊检测、自动打分（必须人工确认）
- 验收标准：与 3 位有经验的教师/面试官做一致性对比，AI 初评与人工评分的 Spearman 相关 > 0.7。**达不到就说明评分卡没设计好，回去改评分卡**

**定价策略**：
- **高校**：$3/人次（含转写 + 评分卡 + 报告），院系年包 $20k 起（约 7000 人次）
- **企业招聘**：$25/候选人，或 $30k/年（含 1500 人次 + ATS 集成）
- **认证机构**：$150k/年起，按考点授权，含定制评分卡
- **试点策略**：前 5 个院系免费做一学期，换取"评分卡校准数据 + 案例背书"。**这个品类的销售靠同行推荐，不靠广告**

**为什么现在做**：
"作业失去意义"这件事已经从教师的私下抱怨变成了 HN 头条，而现有方案（检测器、闭卷考）都在往"对抗"的方向走，**注定失败且得罪所有人**。Viva 走的是唯一可持续的路：**承认 AI 存在，然后测量人本身**。这个判断如果对了，市场极大（全球高等教育 + 招聘 + 认证）；如果错了，至少能退化成"AI 模拟面试"这个确定存在的生意——**下行有保底，上行很大，这是好创意的特征**。

### 创意 4（备选，轻量）：LexCut —— "你的模型为通用能力多付了多少钱"
